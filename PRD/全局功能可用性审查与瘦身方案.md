# 漫剧 Agent 2.0：全局功能可用性审查与瘦身方案

> 版本：v1.0  
> 日期：2026-07-24  
> 状态：审查完成；Phase 0 已开工  
> 目标：**用最少代码实现最完整功能**——可运行性 > 核心正确性 > 稳定性 > 性能 > 可维护性

---

## 0. 执行结论（一句话）

核心制作链路（上传→圣经→分集→剧本→分镜→确认→参考图视频→评审→成片）**可用且主路径清晰**；真正的问题不是功能缺失，而是 **1.0 式范围回潮**：双控制面、双状态账本、死代码与未接线开关把「小而深」撑成「中而厚」。

瘦身原则：**只删死轨、假开关、双份实现；不砍真实能力；不引入新框架。**

---

## 1. 现状盘点

### 1.1 代码体量（审查时点）

| 区域 | 规模 | 备注 |
|------|------|------|
| `app/` | ~102 个 py / ~1.6MB | 后端主战场 |
| `frontend/src/` | ~50 个 ts(x) / ~608KB | 10 个 View，远超 PRD「6 页」 |
| `tests/` | 57 个用例文件 | 工程回归较全，质量金样仍弱 |
| 最大文件 | `api.py` 3440、`worker.py` 2217、`stages.py` 1590 | 职责堆叠，不是第二套业务 |

### 1.2 现行主路径（保留）

```text
UI / MCP / Agent
    ↓
Command Bus（capabilities：风险 / 批准 / 幂等 / preflight）
    ↓
api / auto / planning / orchestration 领域函数
    ↓
文本：stages + loops.AgentLoop
媒体：worker + media_scheduler（lease / 预算）
证据旁路：WorkflowRecorder / media_runs / media_pipeline（限流辅助）
```

**不要删**：Command Bus、批准门禁、worker 媒体队列、stages 校验修复回路、hiagent 网关。  
这些是「少代码换可靠」的正确抽象，不是膨胀源。

### 1.3 产品面 vs PRD

| PRD 承诺 | 实际 | 判定 |
|----------|------|------|
| ≤6 个页面 | 10 个 View（+ Agent 抽屉） | **超范围** |
| ≤10 张核心表 | 另有 workflow_runs / media_tasks / reference_* 等 | 证据面必要；`media_tasks` **未接线** |
| P3 贵环节前人工确认 | 页面路径有效；一键全自动 **自动 confirm** | **功能隐患** |
| 禁止静默兜底 | 多处「增强失败不影响主流程」 | **部分违背 P2** |

## 2. 功能可用性审查

### 2.1 主链路可用性

| 能力 | 状态 | 说明 |
|------|------|------|
| 小说摄入 / 分章 | ✅ | 确定性映射一章一集 |
| 人物谱 / 定妆照 | ✅ | 按集反应式生成 |
| 场景库 | ✅ | 增强项；失败不挡主流程（见隐患） |
| 分集规划 | ✅ | 无 LLM |
| 可拍剧本 | ✅ | Schema + 修复 |
| 分镜脚本 | ✅ | 逐镜 + 大纲可降级 |
| 人工确认门 | ⚠️ | 常规路径 OK；auto / Agent 可绕过语义 |
| 参考图视频生成 | ✅ | 现行唯一视频入口 |
| 评审墙采用 / 重抽 | ✅ | |
| 成片 / 交付包 | ✅ | 相对 P0 偏厚，但已接线 |
| 重启恢复 | ✅ | 复杂但有统一 `recover_all` |
| 案头 Agent | ⚠️ | 原生 tool calling + 流式已落地；并行只读 / 上下文压缩 / 计划相未做 |
| MCP | ✅ | 与 Bus 同源，非第二业务实现 |

### 2.2 控制面重复（可用性摩擦）

同一写能力经 **REST + Capability + MCP/Agent** 三入口暴露——**设计如此，实现单一**。摩擦在前端：

1. 页面按钮 vs Agent 工具（功能重叠）
2. `CapabilityApprovalHost` vs Agent `ApprovalCard`（两套批准 UI）
3. `RunDock` + Monitor `RunCenter` + Agent `RunProgressCard`（三套进度）
4. Agent UI Bridge 半残：证据点击只 toast；`select_shot` 不定位具体镜

## 3. 功能隐患清单（按严重度）

### P0 — 正确性 / 原则冲突

| ID | 隐患 | 位置 | 影响 |
|----|------|------|------|
| H1 | **一键全自动自动 `confirm_episode_core`**，跳过人工看分镜 | `app/auto.py` ~451 | 违背 P3；可能直接烧 Seedance 钱 |
| H2 | 领域状态 + workflow_runs + jobs lease **三套账本** | `api`/`worker`/`engine`/`system_api.jobs_overview` | 恢复与监制房展示可能短暂不一致；认知成本高 |
| H3 | 场景圣经 / 场景库失败「不影响主流程」 | `app/api.py` | 下游在残缺场景锚点上继续，质量静默下降（近 P2 违规） |
| H4 | 分镜大纲失败退回纯逐镜 | `app/api.py` / `stages` | 同上：成功外观下的质量降级 |

### P1 — 可用性 / 运维

| ID | 隐患 | 位置 | 影响 |
|----|------|------|------|
| H5 | `media_pipeline_v2_enabled` **假开关**（无读取分支） | `config.py` + Monitor 文案 | 运维误判路径 |
| H6 | `agent_enabled` 仅写入 DEFAULT_SETTINGS，API **不检查** | `config.py` | 开关无效 |
| H7 | `media_tasks` 表已建 **无 DML** | `db.py` | 死表误导后续「再造第三调度器」 |

| H9 | 前端多路轮询叠加 | Studio/Episode/RunDock/Monitor | 闲时仍打 API；忙时重复拉同一项目 |
| H10 | Agent 证据 / 选镜 Bridge 假闭环 | `AgentDrawer` / `uiBridge` | 用户以为点开了证据，实际只有 toast |

### P2 — 膨胀 / 可维护性

| ID | 隐患 | 位置 | 影响 |

| H12 | `handlers/domain.py` ~504 行与模块化 handlers **双份** | `capabilities/handlers/` | 改一处漏一处；生产不走 domain |

## 4. 瘦身候选（按风险）

### 4.1 安全删除（Phase 0，本轮执行）

| 动作 | 预期收益 | 验证 |
|------|----------|------|
| 删除 worker 关键帧死块，保留 `enqueue_scene` 一行 raise + 启动清扫 | ~300 行 | `test_keyframe_chain` |
| 掏空 `domain.py` → 空 `HANDLER_MAP`；catalog 只绑 preflight | ~500 行 | `test_command_dispatch` |
| 删除 `MEDIA_PIPELINE_V2_*` 假开关与 Monitor 文案 | 去伪配置 | 设置页仍可用 |
| 工具脚本去掉关键帧阶段，收敛到视频入口 | 防误用 | 脚本 `--help` / 文档注释 |

### 4.2 需迁移后删除（Phase 1）

| 动作 | 说明 |
|------|------|
| `media_tasks` schema 标注废弃或迁移删除 | 确认无外部依赖 |
| `ShotVideoModeSelector` 合并进 `default_reference_decision` | 更新测试与 `regression_diff` |
| Agent Bridge：补全或删除假意图 | 证据打开 EvidenceDrawer；选镜传 shotId |
| 接线或删除 `agent_enabled` | 二选一，禁止假开关 |

### 4.3 需验证后合并（Phase 2–3）

| 动作 | 说明 |
|------|------|
| 拆 `api.py` / `worker.py`（纯搬迁，不改行为） | 按 bible/screenplay/storyboard/video 切模块 |
| 轮询统一为单一 store / AdaptivePoller | 忙时页面优先，闲时降频 |
| 产品面收敛：Bible+Scenes+Episodes 可合并导航；Reader 变抽屉 | UI 不砍能力，减入口 |
| 双状态账本：领域 `*_status` 降为 projection，Run 为权威；或反过来明确「Run 仅旁路」并写死 | 二选一，禁止长期双写语义 |

### 4.4 明确不删

- `capabilities` Bus / Registry / Policy / MCP
- `loops.AgentLoop` 与 `agent.orchestrator`（制作循环 ≠ 对话 Agent）
- `media_scheduler` 与 `worker` 的租约/执行分离
- `validators` / `stages` / `hiagent`（大体量单职责）

## 5. 整改计划（分阶段）

### Phase 0 — 去死代码 / 假开关（本 PR）★最少代码最大收益

1. worker 关键帧死实现删除  
2. domain 双份掏空  
3. V2 假开关删除  
4. 资产脚本收敛到视频路径  
5. 本文档入库  

**准入**：相关单测通过；`compileall`；前端 build 若触及 Monitor。

### Phase 1 — 功能隐患止血（下一轮，优先）

| 项 | 方案（三选一后立即做，不做大而全） | 推荐 |
|----|--------------------------------|------|
| H1 确认门 | A) auto 停在 `scripted` 等人点确认；B) auto 仍确认但 UI 强警示+二次确认预算；C) 拆「全自动到分镜」与「全自动含视频」两按钮 | **C**：能力完整且守 P3 |
| H3/H4 静默降级 | 失败写 `run_events` + UI 黄条；禁止当成功静默 | 必做 |
| H10 Bridge | 补全或删意图定义 | 补全证据；删未接线意图 |
| H6/H7 | 接线或删除 | 删除死表标注 + 接线 agent 开关 |

### Phase 2 — 结构瘦身（搬迁为主）

1. `api.py` → `app/domain/{project,bible,screenplay,storyboard,video}.py` + 薄路由  
2. `worker.py` → queue / prepare / poll / qa / concatenate  
3. `video_modes` 去掉空 Selector；参考图配置键收敛为 1 个策略对象  
4. Monitor / Wall 拆文件（不改交互）

### Phase 3 — 产品面收敛

1. 侧栏合并「前期准备」（圣经/场景/分集 Tab）  
2. Agent 默认「只读诊断 + 引导回页面按钮」；写入仍走批准但减少双入口曝光  
3. 轮询合并；Studio 固定 6s 改为 Adaptive  
4. Cinema 保留，但交付审批文案降噪到「成片检查」

### Phase 4 — 算法 / 提示词（不增模块）

1. 案头 Agent：只读工具并行（Harness 方案 Phase 2 残余）  
2. 上下文摘要压缩（避免再加子代理框架）  
3. 参考图一致性检查：失败可观测，不静默放行脏图进 Seedance（阈值可配）
