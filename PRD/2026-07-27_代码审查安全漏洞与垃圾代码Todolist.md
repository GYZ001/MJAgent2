# 2026-07-27 代码审查：安全漏洞与垃圾代码 Todolist

> 版本：v1.1  
> 日期：2026-07-27  
> 状态：审查完成；**P0 Todolist T1–T7 已落地**  
> 范围：`app/`、`frontend/`、鉴权面、密钥面、文件系统、媒体静态挂载  
> 原则：可运行性 > 核心正确性 > 稳定性；**安全闸门优先于瘦身**，不引入新框架

---

## 0. 审查结论（一句话）

主制作链路可用，但**鉴权是结构性空洞**：Agent/MCP 有防护，主体 REST（含密钥写入、MCP Token 签发、目录浏览、settings 回传）几乎裸奔；前端开发服 `allowedHosts: true` 进一步放大暴露面。另有 `exec` facade、上帝文件、空 `except`、假白名单等垃圾/质量债。

---

## 1. 发现清单（已核实）

### 1.1 P0 — 安全漏洞（必须修）

| ID | 问题 | 证据位置 | 影响 |
|----|------|----------|------|
| S1 | 主体 REST 无鉴权；仅 Agent 与少数 call-detail 用 `require_local_session` | `app/domain/*.py`、`app/system_api.py`、`app/agent/api.py`；全仓 `require_local_session` 仅约 6 处 | 网络可达即可删项目、改设置、触发视频生成 |
| S2 | `GET /api/session` 无鉴权直接下发会话秘密；无 Origin 时不校验来源 | `app/main.py` ~79–82；`app/local_session.py` ~66–84 | 领到 token 后即可调用受保护的 `/api/agent/*`，Agent「鉴权」可被绕过 |
| S3 | `PUT /api/keys`、`PUT /api/models/{id}/credentials` 无鉴权且绕过 Command Bus | `app/system_api.py` ~454–472、~1256–1287 | 覆盖 `.env` 全部 API Key，劫持模型调用与计费 |
| S4 | `GET /api/settings?include_schema=false` 明文回传含密钥的 settings | `app/system_api.py` ~1074–1079 | 未鉴权 + 未脱敏 = 密钥一键导出 |
| S5 | MCP Token 签发/列表/撤销无鉴权，可自选高权限 scopes | `app/system_api.py` ~1296–1333 | 匿名颁发「外挂超级客户端」凭证 |
| S6 | 未鉴权 REST 的 202 响应回传 `approval_token`，可自批自执行破坏性操作 | `app/capabilities/dispatch.py`；如 `DELETE /api/projects/{id}` | 拿 token 重放即可删库/清产物（MCP 已剥离 token，REST UI 路径未剥离） |
| S7 | `/system/browse`、`/system/mkdir` 仅 blocklist，无 directory_grant 真校验 | `app/system_api.py` ~85–152；catalog 声称需 grant | 可枚举家目录；可在非黑名单路径建目录 |
| S8 | `/system/calls` 返回未脱敏 body；`/system/errors/{id}` 无会话 | `app/system_api.py` ~558–564、~778–784 | 提示词、业务正文、堆栈外泄 |
| S9 | 前端开发服 `allowedHosts: true` + 代理本机 `/api`/`/media` | `frontend/vite.config.ts` ~9–13 | 隧道/公网域名场景放大上述无鉴权 API 风险 |

### 1.3 P2 — 垃圾代码 / 质量债

| ID | 问题 | 证据位置 |
|----|------|----------|
| G1 | `exec(compile(...))` 聚合 facade，破坏静态分析与鉴权审查 | `app/api.py`、`app/worker.py`、`app/domain/__init__.py` |

## 2. 今日 Todolist（2026-07-27）

> 只做 P0 与必要 P1；P2 仅立项，不在今日扩 scope。  
> 每项完成后跑该条对应的最小回归；提交前跑 `py scripts/verify.py`（改动影响面）。

### P0 — 今日必须落地

- [x] **T1 全局会话闸门**  
  为除 `GET /api/system/health`、MCP 信息页外的所有 `/api/*` 加 `Depends(require_local_session)`。  
  验收：无头访问 `DELETE /projects/{id}`、`PUT /keys`、`GET /settings`、`POST /system/mcp-tokens`、`GET /system/browse` 均返回 401。

- [x] **T2 锁死密钥面**  
  `PUT /keys`、`PUT /models/{id}/credentials` 强制会话 + 二次确认（或走 dispatch）；`GET /settings` 永远脱敏，禁止返回 `model_credentials` / `api_key`。  
  验收：响应 JSON 不得含明文 `api_key` / `sk-` 族密钥。

- [x] **T3 MCP 运维端点鉴权**  
  `/api/system/mcp-tokens*` 全部要求本机会话；`create_token` 默认 scopes=`manju:read`，禁止匿名指定 `generation-*` / `delivery`。  
  验收：匿名签发 401；默认 scopes 不含媒体/交付写权限。

- [x] **T4 批准令牌绑定会话**  
  `issue_approval` / waiting_approval 载荷绑定 `session_id`；无有效会话的 REST **不得**返回 `approval_token`。  
  验收：匿名 `DELETE project` 的 202 body 中不得出现 token。

- [x] **T5 文件系统收敛**  
  `browse` / `mkdir` 仅允许 grant 白名单根；实现 `parent_grant` 真实校验（与 catalog 对齐）。  
  验收：越权路径 403；家目录默认不可枚举。

- [x] **T6 日志与错误详情脱敏**  
  `/system/calls` 去掉 `request_json` / `response_json`；`/system/errors/{id}` 加会话。  
  验收：list 端点无 body 字段；detail 无会话 401。

- [x] **T7 收紧前端开发暴露面**  
  `vite.config.ts` 去掉默认 `allowedHosts: true`，改为显式 host 列表；文档标明隧道场景安全前提。  
  验收：默认配置下任意临时域名不可直连开发服。

### P1 — 今日有余力则做，否则本周

- [ ] **T8 SSRF 收口**：`hiagent.download` URL allowlist + 重定向后 IP 复核；单测覆盖 `169.254.169.254` / `127.0.0.1` 拒绝。
- [ ] **T9 `/media` 鉴权或签名 URL**；文档禁止 `--host 0.0.0.0` 公网暴露。
- [ ] **T10 SSE 会话**：一次性 ticket 替代长期 `?session=`；前后端统一单一 session 模块。
- [x] **T11 交付下载**：报告/ZIP 改走 `api.download` + blob，去掉匿名直链。
- [ ] **T12 UI Bridge runtime 白名单** + `safeMediaUrl` 媒体入口闸门。
- [ ] **T13 WallPage critique**：用 React state 替代 `querySelectorAll`。

### P2 — 质量债（立项，不扩今日 scope）

- [ ] **T14** 消灭 `exec` facade（`api.py` / `worker.py` / `domain/__init__.py`），改为正常 import。
- [ ] **T15** 「空 except」清理标准：优先 `media_exec/run_job.py`、`video_supervisor.py`。
- [ ] **T16** 静态门禁：新 `@router` 必须带鉴权 Depends，接入 `scripts/verify.py`。
- [ ] **T17** 复核 catalog 中 `ConfirmationPolicy.NEVER` 的 R2 列表。
- [ ] **T18** 拆分 Monitor/Wall 上帝文件与超长单行；抽取共享 Dialog/`track`。
- [ ] **T19** Agent 批准提交 `approval_token` + 强制 reason；收敛双份 session。
