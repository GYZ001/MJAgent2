### 1.1 术语

- **发布版**：当前可供下游消费、已通过相应门禁的分镜 Artifact。
- **工作草稿**：尚未通过业务门禁、不得覆盖发布版或被下游消费的人工/Agent 修改。
- **基线版本**：用户进入编辑时看到的 Artifact 身份与版本，而非轮询后的最新版本。
- **完整终态**：Supervisor 已结束、计划镜头全部落地、最终镜标记及整集门禁均通过、允许确认的状态。
- **影响预览**：高影响动作提交前，由服务端基于当前版本计算的失效对象、重跑范围、成本区间与门禁结果。本文仅定义能力和语义，不预设未确认的 URL、方法名或代码接口名。

## 2. 整改背景与现状结论

分镜台的审片信息架构已基本成立：横向镜头轨道、进入→动作→离开状态链、首尾帧、台词容量、声音和原文证据让“看分镜”较顺手；分集搜索实测可在 1646 集项目中准确定位第 1600 集，键盘切镜、上下集和放弃编辑也符合预期。

当前风险集中在动作与状态没有收敛：扫描中曾同时出现“待确认”、确认按钮和仍在修复的 Supervisor；生成中可以编辑，旧编辑副本却可能借用轮询后的新版本号保存；原文审计证据可自由改写；确认前看不到完整门禁与成本；错误提示建议“人工补写最后一镜”，页面却没有增镜入口。失败草稿、口播冲突和下游失效虽然在后端存在处理逻辑，前端没有形成可恢复、可验证的闭环。

本次整改将分镜台从“内部专业用户可审阅”提升为“普通制作用户可安全编辑、恢复并确认”的生产工作台，先守住并发、审计和付费边界，再提升修镜效率。

## 3. 目标与量化成功指标

### 3.1 产品目标

1. 任一时刻只有一个与真实状态一致的推荐主操作，生成、编辑、修复、确认不会互相竞争。
2. 任何陈旧人工草稿都不能覆盖 Supervisor 或另一会话发布的新版本。
3. 原文证据具备可验证来源；确认动作在提交前完成完整性、门禁、版本和成本预览。
4. 台词、角色、镜头结构、连续性和失败草稿均可在页面内完成真实修复。
5. 保留现有高质量浏览能力，并在 390px 窄屏及键盘/读屏环境中可用。

### 3.2 成功指标

| 指标 | 目标 | 口径 |
|---|---:|---|
| 陈旧草稿覆盖新版本事件 | 0 | 保存审计中基线版本落后但仍发布成功的次数 |
| 运行中直接编辑/保存成功次数 | 0 | Supervisor 运行态未先暂停并取得编辑租约的写入 |
| 不可验证原文证据进入发布版 | 0 | 发布版证据缺少有效章节、偏移或内容校验 |
| 非完整终态确认成功次数 | 0 | 计划镜未完成、最终镜缺失、全量门禁未过或预览过期仍确认成功 |
| 高影响动作预览覆盖率 | 100% | 会导致媒体/成片失效、重新确认或预计费用变化的保存/冲突修复/确认 |
| no-op 新版本率 | 0 | 结构化内容哈希未变化却创建新 Artifact 的保存 |
| 可操作错误闭环率 | 100% | 面向用户的建议动作在当前状态有可用入口，或明确说明不可人工处理 |
| 修改单条台词无误报冲突成功率 | 100% | 自动化与灰度样本中仅改台词、未改时间轴的保存 |
| 失败草稿可恢复率 | 100% | 业务校验失败后可重新打开草稿、定位字段并继续编辑 |
| 编辑控件可访问名称覆盖率 | 100% | 自动化无障碍扫描与人工读屏抽检 |
| 390px 首屏镜头可达性 | ≤1 次操作 | 首屏直接看到镜头轨道，或通过固定“查看镜头”入口一次到达 |
| 状态冲突率 | 0 | 同一快照出现互斥状态/操作组合；以状态机契约校验计 |

上线前以自动化和预发环境建立埋点基线；线上指标按版本、项目、分集和运行 ID 聚合，不记录剧本文本或台词正文。

## 4. 范围与非范围

### 4.1 本期范围

- 分集导航、搜索、剧本前置门禁和空状态。
- 分镜首次生成、Agent 迭代、自动确认、取消、暂停、转人工、继续及 Supervisor 进度。
- 镜头轨道、键盘导航、筛选、单镜概览、首尾帧、声音、原文证据。
- 单镜基础参数、连续性、角色、信息点、台词及镜头结构编辑。
- 编辑并发控制、影响预览、no-op 幂等、失败草稿和口播冲突恢复。
- 分镜确认、评审墙入口、窄屏和无障碍。
- 与上述流程直接相关的状态契约、数据校验、后台任务约束、埋点与告警。

### 4.2 非范围

- 改变视频模型、TTS 或 Seedance 的生成质量与计费规则。
- 重做剧本台、监制房或评审墙自身功能；仅约束分镜台的跳转与交接。
- 取消既有台词容量、连续性或整集门禁标准。
- 在前端直接暴露内部 Artifact、合同字段或错误码作为主要业务语言。
- 本 PRD 不指定现有代码中尚未确认的接口路径、类名或数据库表名。

## 6. 目标用户流程

### 6.1 浏览与定位

1. 用户从分集规划或侧栏进入分镜台；系统读取同一份状态快照。
2. 顶部用一句话显示“当前阶段 + 完成度 + 下一步”，只呈现一个主操作。
3. 用户可按分集状态搜索/筛选，进入目标集；当前镜头和相邻镜头可用按钮或键盘定位。
4. 镜头卡展示问题、最终镜、口播超限和连续性风险徽标；用户可仅看问题镜。

### 6.2 生成、暂停与恢复

1. 无剧本时仅提供“先去剧本台”；有剧本且无分镜时主操作为首次生成。
2. 提交生成前展示动作含义；请求受幂等保护，进入提交/运行状态后不能重复触发。
3. 运行中主操作统一为“查看分镜进度”；停止、暂停并编辑、转人工等控制动作进入“更多操作”，避免多个同级主操作。
4. 服务端确认任务已暂停并签发编辑基线后，编辑入口开放；取消、暂停、转人工分别说明是否可恢复、从何处恢复及已有产物是否保留。

### 6.3 编辑、预览与恢复

1. 用户进入编辑，页面锁定基线版本并保留原始值；轮询只提示有新版本，不替换基线。
2. 默认编辑画面、首尾帧、参数、角色、台词；连续性/信息合同在高级区，以结构化控件呈现。
3. 实时校验容量、必填、角色与相邻状态；删除可撤销，未改动时保存不可用。
4. 保存前由服务端计算精确影响。版本未变时用户批准并保存；版本变化时冻结提交，显示“我的草稿 vs 最新版”字段级差异。
5. 校验不通过时保持编辑态并关联失败草稿，用户定位问题、继续修改或回到发布版。

### 6.4 确认与下游

1. 仅完整终态显示“确认分镜”。
2. 点击后先展示镜头数、计划数、总时长、最终镜、门禁结果、警告、预计视频成本区间、将解锁能力与当前版本。
3. 用户批准后提交；快照变化则预览失效，必须重新预览。
4. 成功后页面进入已确认态，才展示“进入评审墙”；失败保留当前上下文并给出可操作错误。

## 7. 详细功能需求

### SB-FR-01｜统一状态快照与唯一推荐动作（P0）

- **现状问题**：状态、空态、工具栏和 Supervisor 各自判断，出现“待确认 + 修复中 + 可确认/继续修复”并存；空态还引用不存在的按钮。
- **整改规则**：
  1. 后端状态快照必须同时表达剧本可用性、任务阶段、计划/已产出/已验证镜数、最终镜状态、门禁、确认状态及唯一推荐动作。
  2. 工具栏、空状态、提示、下游入口均消费该快照，不自行推导互斥业务状态。
  3. 主操作只能有一个；次要动作进入“更多操作”，不可用动作说明原因。
  4. 分集下拉增加制作状态；进入/切集/搜索保持原有正确定位和边界禁用。
- **异常/边界**：快照缺字段或组合非法时进入“状态同步中/需刷新”安全态，隐藏确认及写操作；轮询过期不得回退已观察到的新状态。
- **验收标准**：覆盖无剧本、无分镜、运行、暂停、失败、待确认、已确认七类组件状态；任一快照只有一个主操作；非法组合契约测试 100% 拒绝。

### SB-FR-02｜生成与任务控制语义（P1）

- **现状问题**：首次、迭代、续跑、自动确认同级出现；取消单击即执行；暂停/转人工/取消后果不清。
- **整改规则**：
  1. 主文案使用制作语言，技术术语放入详情；明确首次、从 checkpoint 继续或全量重做。
  2. 首次生成或从 checkpoint 继续前必须先展示任务启动预检：剧本/分镜基线、已保留合格镜头、计划与剩余镜头、恢复起点、预计影响，以及可取得的等待时间和费用估算；用户确认的预检版本必须与实际创建任务时一致。
  3. 取消属于破坏长任务的动作，展示二次确认、保留产物、恢复点和不可恢复影响。
  4. 暂停、取消、转人工、继续均展示请求中状态并禁止重复提交；完成后显示服务端终态证据。
  5. “通过后自动确认”只作为生成设置，不与普通生成并列；启用前解释会自动确认分镜但不会自动提交付费视频，并仍受 SB-FR-05 门禁和预览约束。
- **异常/边界**：任务已自然结束时控制命令返回当前终态，不报通用错误；重复命令幂等；网络超时后以任务查询结果为准。
- **验收标准**：各控制动作有独立说明及完成态；预检与实际任务的基线、checkpoint 和范围一致，状态变化会使旧预检失效；双击不产生重复任务；取消必须二次确认；自动确认无法绕过确认预览和完整终态。

### SB-FR-03｜运行态编辑隔离与乐观并发（P0）

- **现状问题**：运行中可编辑，陈旧编辑副本可能借用刷新后的版本号覆盖 Supervisor 新产物。
- **整改规则**：
  1. 生成/修复运行时默认只读；“暂停并编辑”必须等待任务进入可编辑终态。
  2. 进入编辑时固定基线 Artifact 身份、版本及内容哈希；保存必须提交该基线，不得使用轮询更新后的版本替换。
  3. 编辑期间发现新版本，冻结发布保存并保留本地草稿，显示字段级差异；允许重新载入、复制改动到新草稿或退出，不允许静默覆盖。
  4. 后端以基线校验、编辑租约/任务状态和内容校验共同决定是否发布。
- **异常/边界**：多标签页、任务恢复、编辑租约过期、暂停失败均按冲突处理；草稿可下载/复制但不能进入下游。
- **验收标准**：旧草稿 + 新版本号组合被服务端拒绝；运行态无直接保存；保存后 30 秒内旧运行不得回写；双标签页后提交者看到冲突 diff。

### SB-FR-04｜原文证据不可伪造（P0）

- **现状问题**：审计原文可自由改写，长度校验无法证明来源真实。
- **整改规则**：
  1. 默认只读展示证据文字、章节和定位。
  2. 需要修正时仅允许从本集授权原文中框选连续片段，保存章节身份、起止偏移与内容哈希；不提供自由文本框。
  3. 服务端验证范围属于本集、偏移有效、文本与对应版本内容一致；原文版本变更时证据需重新绑定。
  4. UI 明确该证据不送视频模型，业务画面描述和审计证据分开编辑。
- **异常/边界**：原文不可用、片段跨章节、版本漂移或权限不足时禁止修改证据但不影响只读审片；给出处理路径。
- **验收标准**：非连续子串、错章、错偏移、哈希不匹配均不能发布；已有合法证据可无损展示；审计记录可追溯到原文版本。

### SB-FR-05｜确认前全量门禁、成本与版本预览（P0）

- **现状问题**：修复未完成时曾出现确认；点击直接提交，镜头时长与预计成本仅成功后可见。
- **整改规则**：
  1. 仅当 Supervisor 处于允许确认的完整终态、计划镜全部落地、最终镜有效、全量硬门禁通过且授权有效时展示确认按钮。
  2. 确认前预览必须含版本、镜头数/计划数、总时长、最终镜、硬门禁、警告、预计视频成本区间、下游解锁项。
  3. 提交绑定预览令牌/版本快照；任何相关数据或费率变化使预览失效。
  4. 自动确认也只能消费有效预览；若存在警告需要人工判断，则自动确认停止并转人工。
- **异常/边界**：成本暂不可算时不显示虚假数字，明确“暂无法估算”并按产品计费策略决定是否允许确认；重复确认幂等。
- **验收标准**：14 镜计划仅完成 6 镜时按钮不可见；版本变化后旧预览被拒绝；确认请求不能绕过服务端门禁；成功后才开放评审墙。

### SB-FR-06｜分层单镜编辑与即时校验（P1）

- **现状问题**：表单像内部数据后台；编辑态无容量即时反馈；时长审核过程不清。
- **整改规则**：默认区只含画面/动作、首尾帧、时长、景别、运镜、转场、角色和台词；高级区承载连续性与合同信息。所有必填、格式、容量和需 AI 审核条件即时显示，标题与只读概览同步预览。放弃编辑继续完全恢复基线。
- **异常/边界**：即时校验不可代替服务端校验；校验服务不可用时可存工作草稿但不可发布。
- **验收标准**：用户不接触内部 ID 即可完成常见修镜；口播超限在输入时可见；需审核字段显示阶段与结果；放弃后结构化等价于基线。

### SB-FR-07｜邻镜连续性对照（P2）

- **现状问题**：编辑本镜状态链时看不到邻镜，容易修好本镜却破坏前后镜。
- **整改规则**：编辑连续性时并排或抽屉展示前镜离开、本镜进入/动作/离开、后镜进入；冲突实时标记并可跳转邻镜。窄屏采用横滑卡或逐段模式，不堆成长列。
- **异常/边界**：首镜/末镜显示明确边界；邻镜被其他会话更新时刷新对照并触发版本冲突。
- **验收标准**：相邻状态冲突可定位到两镜字段；首末镜不出现不存在的依赖；390px 可在两次以内操作查看邻镜。

### SB-FR-08｜台词与口播时间轴单一编辑语义（P1）

- **现状问题**：普通台词修改同时携带旧时间轴，后端误判双侧修改；删除无撤销；冲突修复未预览下游影响。
- **整改规则**：
  1. 普通编辑仅提交实际变化的台词领域数据，由服务端按既有规则重建/校验时间轴；高级时间轴编辑才提交时间轴变更。
  2. 前端基于结构化 diff 表达变更来源，后端不得靠“字段同时出现”推断双方都被修改。
  3. 新增/删除/改文案实时计算字数和容量；删除提供会话级撤销。
  4. 真正双侧冲突时展示两个版本、选择后果，并走 SB-FR-11 统一影响预览。
- **异常/边界**：自动重建失败时保留草稿并标出具体台词；多人同时编辑依照 SB-FR-03。
- **验收标准**：修改一条已有台词直接保存且合同 coherent；普通请求不携带未改时间轴；冲突选择前可见视频/成片失效数量；删除可撤销。

### SB-FR-09｜结构化角色与信息点（P1）

- **现状问题**：头部角色与可见角色语义不统一；信息点暴露裸 ID，用户可能无法修复“缺角色”。
- **整改规则**：以“画面角色”作为产品单一入口，使用人物谱选择器；后端按现有领域合同统一派生/校验主角色和可见角色。声音角色独立选择。新信息从本集剧本信息清单多选，展示可读标题与来源，内部 ID 仅作为存储键。
- **异常/边界**：角色或信息点被上游删除时显示失效引用并要求重选；临时群演按既有权限策略处理，不允许手填未知 ID。
- **验收标准**：“缺角色”可从同一控件修复且保存后头部同步；请求中无用户手写裸 ID；无效引用不能发布。

### SB-FR-10｜人工镜头结构操作闭环（P1）

- **现状问题**：错误建议人工补镜，但页面没有新增、复制、删除或移动能力。
- **整改规则**：提供“在当前镜后新增”“复制为下一镜”“删除”“移动”四类结构操作；提交前预览镜号变化、相邻校验、媒体失效和最终镜影响；保存后重跑受影响镜及相邻窗口校验。若该能力在阶段开关下不可用，所有错误文案只能提供真实可执行的继续修复、转人工 Agent 或修改现有问题镜。
- **异常/边界**：运行中、已确认或存在下游媒体时必须按权限、暂停和影响预览规则处理；删除唯一镜/最终镜需阻止或要求指定新最终镜。
- **验收标准**：每条建议动作均能从提示直达；增删移动后镜号连续、最终镜唯一、邻镜重验；功能关闭时页面不存在“人工补镜”承诺。

### SB-FR-11｜保存前精确影响预览与 no-op 幂等（P1）

- **现状问题**：精确失效数量保存后才算；未改动也可创建新版本和下游失效。
- **整改规则**：
  1. 前端结构化 diff 为空时禁用保存；服务端对规范化内容哈希再做幂等保护，返回未变化结果且不创建 Artifact。
  2. 有变化时先由服务端计算受影响参考图、视频版本、成片、重新确认、重验范围及预计重生成成本。
  3. 保存绑定预览版本；预览到提交间状态漂移必须重新预览。
  4. 普通保存、口播冲突、镜头结构调整复用同一影响卡及批准语义。
- **异常/边界**：预览计算超时不得退化成“先保存后告知”；允许保存工作草稿，但发布与失效传播必须等待有效预览。
- **验收标准**：no-op 不创建版本、不失效下游；影响数字与提交结果一致；过期预览被拒绝；高影响动作预览覆盖率 100%。

### SB-FR-12｜失败草稿、字段定位与恢复（P1）

- **现状问题**：业务校验失败虽保留草稿，但用户只看到 Toast，无法找回输入或对比发布版。
- **整改规则**：失败后保持编辑态，字段内联错误并在顶部汇总；提供“失败草稿/当前发布版”双栏或逐字段 diff；草稿列表显示时间、作者、基线和失败原因，可继续编辑或丢弃。发布版不因失败而改变。
- **异常/边界**：草稿基线过旧时允许迁移到新基线并逐字段解决冲突；草稿删除需确认但不影响发布版。
- **验收标准**：422/业务门禁失败输入不丢失；刷新后可恢复；错误能定位镜头与字段；失败草稿不会被下游读取。

### SB-FR-13｜人话错误、真实动作和状态说明（P1）

- **现状问题**：错误码、Artifact、合同版本成为主文案；时长审核和任务控制后果不清；空态动作漂移。
- **整改规则**：主文案使用“第 N 镜 + 问题 + 如何处理”；技术错误码、错误 ID、Artifact 和合同版本折叠在“技术详情”且支持复制。所有提示动作由统一动作定义生成，可定位到问题镜/字段；原始错误编号继续保留用于排障。
- **异常/边界**：未知错误给出重试、保存草稿和错误 ID，不承诺不存在的修复能力。
- **验收标准**：已知错误 100% 有定位和真实动作；技术详情默认折叠；无剧本/暂停/失败等状态文案与主操作一致。

### SB-FR-14｜问题镜筛选与高效导航（P2）

- **现状问题**：大量镜头审阅缺少筛选，键盘切镜只有聚焦轨道才生效且无提示。
- **整改规则**：支持仅看问题镜、按角色/场景/口播超限/连续性风险筛选；轨道卡展示问题、最终镜和容量徽章。方向键在不占用文本输入时切镜，首次使用展示快捷键提示；焦点和选中镜同步。
- **异常/边界**：编辑输入框、组合框内方向键保持原生行为；筛选后上一/下一镜按可见集合移动。
- **验收标准**：筛选结果与服务端问题清单一致；键盘不会劫持表单输入；读屏能听到当前镜和问题数量。

### SB-FR-15｜390px 窄屏布局与运行提醒避让（P2）

- **现状问题**：顶部状态区约 612px，底部提醒约 119px 并遮挡内容。
- **整改规则**：窄屏首屏仅保留单行状态、进度和主操作；Supervisor 详情、错误和活动进入抽屉。运行提醒可最小化为徽标，并为固定底部操作预留安全区；状态链使用横滑/折叠方案。
- **异常/边界**：系统字体放大 200%、软键盘弹出及横竖屏切换不得遮住当前输入或保存/放弃操作。
- **验收标准**：390×844 无页面横溢；镜头轨道/入口首屏可达；提醒不遮挡内容和主操作；截图回归覆盖运行、错误、编辑、弹窗四态。

### SB-FR-16｜无障碍与弹窗键盘规范（P2）

- **现状问题**：多数编辑 `label` 未绑定；影响弹窗缺焦点锁定和 Escape 行为。
- **整改规则**：每个控件有唯一可访问名称、描述和错误关联；页签/轨道/组合框遵循键盘模式。所有模态框打开聚焦标题或首个安全控件、焦点锁定、Escape 关闭（不可安全关闭时解释原因）、关闭后归还触发点；状态变化用非打断式读屏播报。
- **异常/边界**：危险操作的 Escape 仅关闭弹窗，不执行；后台状态更新不得抢焦点。
- **验收标准**：自动扫描无严重无障碍问题；纯键盘完成选集、选镜、编辑、预览、放弃；读屏抽检所有表单控件名称唯一。

### SB-FR-17｜保留已验证浏览能力与下游交接（P1）

- **现状问题**：整改可能破坏已达 8～9 分的导航、轨道、页签及放弃编辑；评审墙入口依赖状态正确。
- **整改规则**：保持上下集边界、搜索 60 条说明、镜头轨道选中、上一/下一镜、首尾帧/声音/原文页签及放弃编辑行为；只有确认成功的当前版本可进入评审墙，跳转携带当前项目/分集上下文但不隐式执行其他任务。
- **异常/边界**：下游不可用时入口保留并解释原因，不能回退确认状态。
- **验收标准**：既有正向用例全部回归；进入评审墙只导航且版本一致；无确认态不展示下游主入口。

## 8. 状态与交互规则

| 实际状态 | 页面主文案 | 唯一主操作 | 编辑 | 确认 | 其他规则 |
|---|---|---|---|---|---|
| 无可用剧本 | 尚无可用于分镜的剧本 | 先去剧本台 | 禁止 | 隐藏 | 不出现生成承诺 |
| 有剧本、无分镜 | 剧本已就绪，尚未生成分镜 | 生成分镜 | 禁止 | 隐藏 | 提交后立即防重 |
| 生成/修复运行中 | 正在生成：阶段、通过/计划镜数 | 查看分镜进度 | 只读；可从更多操作“暂停并编辑” | 隐藏 | 停止、转人工在更多操作；不展示人工确认 |
| 暂停可恢复 | 已暂停在第 N 镜，已有 M 镜通过 | 继续生成 | 取得编辑租约后允许 | 隐藏 | 转人工/取消在更多操作 |
| 失败可恢复 | 生成停在第 N 镜：可读问题摘要 | 继续生成分镜（从第 N 镜） | 按规则允许 | 隐藏 | 建议动作必须存在 |
| 草稿校验失败 | 修改尚未通过，共 N 个问题 | 继续修改 | 允许 | 隐藏 | 发布版保持可见 |
| 完整待确认 | N/N 镜已通过，等待确认 | 确认分镜 | 允许但会使预览失效 | 先预览 | 只此状态显示确认 |
| 已确认 | 当前分镜已确认 | 进入评审墙 | 变更前需影响预览 | 已完成 | 编辑将产生新未确认版 |
| 状态未知/冲突 | 状态同步中，暂不可执行高影响操作 | 刷新状态 | 禁止发布 | 隐藏 | 技术详情保留错误 ID |

通用交互规则：主按钮不得因轮询在用户指针按下到提交之间改变含义；请求中按钮展示明确进度且不可重复触发；Toast 仅作补充，任何需要决策、恢复或长期保留的信息必须进入页面状态或抽屉。

## 9. 数据、API 与后台任务要求

以下均为能力契约，复用现有接口时扩展响应即可；具体路径和代码名由技术方案确认。

剧本台与分镜台必须消费同一份分镜状态、推荐动作和任务启动预检契约。语义字段可参考 `storyboard_status`、`recommended_action`，最终代码命名由技术设计确认；同一状态的动作码必须一致，页面只负责把动作码翻译为所在页面的展示文案。失败可恢复统一表达为“继续生成分镜（从第 N 镜）”，运行中统一以“查看分镜进度”为主操作。

| 能力 | 必需输入/输出语义 | 服务端约束 |
|---|---|---|
| 分镜状态快照 | 剧本可用性、运行阶段、镜头计划/产出/通过数、最终镜、门禁、确认态、唯一推荐动作、快照版本 | 原子读取；禁止返回互斥状态；客户端不能自行拼主状态 |
| 分镜任务启动预检 | 动作类型、剧本/分镜基线、checkpoint、已保留镜头、计划/剩余镜头、影响、等待/费用估算及预检版本 | 预检零写入；创建任务时复核同一版本；状态变化使旧预检失效；两页面口径一致 |
| 编辑会话 | 分集/镜头、基线 Artifact/版本/哈希、编辑租约状态 | 运行态无租约不允许发布；租约过期安全失败 |
| 编辑影响预览 | 结构化 diff、基线、受影响媒体/成片/确认、重验范围、成本区间、预览有效期/令牌 | 与保存使用同一计算规则；状态漂移使令牌失效 |
| 保存命令 | 真实变更、基线、预览凭据、变更来源（普通台词/高级时间轴等） | 乐观锁、内容哈希幂等、全量业务校验；no-op 不建 Artifact |
| 原文证据绑定 | 原文版本、章节、起止偏移、内容哈希 | 连续子串与范围校验；不可接受自由文本伪造证据 |
| 确认预览/提交 | 当前版本、完整性、门禁、成本、预览凭据 | 提交再次校验完整终态；幂等；预览过期拒绝 |
| 任务控制 | 当前运行身份、期望动作、请求幂等键 | 暂停/取消完成后返回可验证终态；旧运行在停止后不得写入 |
| 草稿与 diff | 草稿身份、基线、失败问题、字段级差异 | 草稿与发布版隔离；失败不得传播下游 |
| 镜头结构变更 | 增/复制/删/移动意图及目标镜 | 原子重排；最终镜唯一；触发相邻窗口与整集门禁 |

后台任务必须在每次落库前核对运行身份、当前基线和取消/暂停栅栏；被替代或取消的旧运行写入应拒绝并记录。轮询响应使用单调快照版本，避免旧响应覆盖新 UI。所有费用仅以服务端预览为准，客户端不得自行估算为确定金额。

## 10. 埋点与可观测性

| 事件/指标 | 必要维度（禁止正文） | 用途/告警 |
|---|---|---|
| 状态快照渲染 | 匿名项目/分集、快照版本、展示状态、推荐动作 | 发现互斥状态；非法组合立即告警 |
| 任务动作请求/结果 | 动作类型、运行 ID、前后状态、耗时、结果码 | 取消/暂停失败率、重复提交率 |
| 编辑开始/冲突/结束 | 基线版本、是否运行态、冲突类型、处理选择 | 陈旧草稿覆盖指标必须为 0 |
| 影响预览/批准/过期 | 变更类型、影响对象计数、成本区间、是否批准、过期原因 | 预览覆盖率与放弃率 |
| 保存结果 | 是否 no-op、校验问题类别、是否草稿、版本变化 | no-op 建版告警、失败草稿恢复漏斗 |
| 原文证据校验 | 结果类别、章节/偏移是否有效（不含文本） | 不可验证证据发布告警 |
| 确认预览/提交 | 完整性、门禁、警告数、版本、预览是否有效 | 非终态确认立即阻断并告警 |
| 错误操作闭环 | 错误类别、问题镜、展示动作、动作点击/结果 | 无动作错误和死链告警 |
| 移动端/无障碍 | 视口档位、首个镜头入口可达、键盘/读屏路径结果 | 布局退化趋势，不采集用户输入 |

日志需用运行 ID、分集 ID、镜头稳定 ID、Artifact 版本和预览 ID 串联；技术错误详情可复制，但前端主文案不暴露敏感载荷。高危告警至少覆盖：旧运行停止后继续写入、陈旧基线发布成功、非终态确认、原文证据校验绕过、no-op 创建 Artifact。

## 12. 实施阶段、风险与回滚

### 12.1 分阶段实施

1. **阶段 A（P0 安全底座）**：统一状态快照、运行态编辑隔离、基线并发校验、原文证据绑定、确认预览和服务端终态门禁。先以只读/隐藏危险动作方式灰度。
2. **阶段 B（P1 恢复闭环）**：任务控制语义、分层编辑、台词同步、角色/信息选择、影响预览、no-op、失败草稿、错误定位、镜头结构操作。
3. **阶段 C（P2 效率与普适性）**：问题筛选、邻镜对照、窄屏折叠、提醒避让、全量无障碍与轮询体验优化。

### 12.2 主要风险与缓解

| 风险 | 缓解 |
|---|---|
| 状态契约切换导致旧前端不识别 | 响应保留兼容字段一个发布周期；新快照有版本；客户端未知值进入安全只读态 |
| 暂停并编辑使操作等待变长 | 展示停止进度和最长等待策略；超时不开放编辑发布，只允许存本地/服务端草稿 |
| 原文历史数据无偏移 | 离线/懒迁移生成候选绑定；未验证前只读并标记，不伪造“已验证” |
| 影响预览与保存结果不一致 | 共享同一服务端计算器；预览绑定版本；差异即拒绝提交 |
| 镜头结构操作扩大下游失效 | 独立功能开关、按分集灰度、强制影响预览和相邻/整集校验 |
| 新 UI 影响现有审片效率 | 保留原轨道/页签布局，做视觉回归和专业用户灰度 |

### 12.3 回滚策略

- 每个高风险能力使用独立功能开关；回滚 UI 时服务端 P0 防线（基线锁、终态确认、证据校验、旧任务写入栅栏）不得回滚。
- 状态快照异常时切换到安全只读版：保留浏览、下载错误 ID和跳转剧本台，隐藏保存、结构调整与确认。
- 镜头结构操作出现异常时关闭入口，已有草稿保留，发布版与下游不回退。
- 新证据绑定写入采用向后兼容读取；不得通过删除新字段或覆盖发布版完成回滚。
