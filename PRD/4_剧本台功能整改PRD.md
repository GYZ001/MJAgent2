### 1.1 术语与约束

- **纯导航**：只改变页面位置/上下文，不创建、续跑、取消或修改任何业务任务。
- **可交付剧本**：通过现有业务门禁、可供分镜消费的发布版 Artifact。
- **工作草稿**：未发布的人工编辑内容，不得清空或驱动下游。
- **基线版本**：开始编辑时的剧本 Artifact 身份与版本；保存必须基于此版本校验。
- **影响预览**：服务端在高影响操作前计算的下游数量、重跑范围、版本差异及风险，供一次批准使用。
- 本 PRD 描述能力契约，不虚构尚未确认的 URL、接口名、数据库表或后台类名；字段的最终代码命名由技术设计复用现有领域模型。

## 2. 整改背景与现状结论

剧本台已具备“选集 → 选必保留台词 → 生成/修复 → 阅读与编辑 → 查看证据 → 进入分镜”的完整链路。高分能力包括：入口和上下集 8.5、1646 集搜索 8.0、删除影响预检 8.0、主线骨架和场次卡 8.0、979 字正文展开/收起 9.0。这些能力必须在整改中保留并回归。

真正阻断生产信任的是动作语义与数据边界。扫描实测“进入分镜台”并非纯导航：点击后从 5 镜 checkpoint 自动续跑，约 5 分 43 秒后保留 6 镜并再次失败。与此同时，分镜运行中仍可手工编辑并保存剧本，保存会清空下游，但服务端没有先取消并等待旧分镜任务退出，存在新旧剧本产物混用、状态回跳和孤儿镜头风险。编辑器还存在陈旧草稿未带版本、`|` 分隔结构字段、未保存静默丢失、修复态台词选择看似可改但实际不生效等问题。

本次整改的核心不是增加更多字段，而是让按钮只做文案承诺的事，让状态、保存、任务和版本由同一安全契约约束，并把现有“数据库式表单”改造成编剧可理解、可恢复、可预览的结构化工具。

## 3. 目标与量化成功指标

### 3.1 产品目标

1. 导航与任务执行彻底分离；任何长任务或潜在费用动作都由独立、明确、可预检的按钮触发。
2. 编辑发布与下游任务互斥：运行中的旧分镜必须先安全停止，陈旧草稿不能覆盖新剧本。
3. 必保留台词在选择阶段就能看到位置、上下文和口播时长预算；继续修复时用户修改的约束要么生效，要么明确锁定。
4. 主线、正文、场次、依据与状态使用结构化编辑，支持脏标记、草稿、撤销和离开保护。
5. 保持既有高分阅读、搜索、删除预检和证据能力，同时补足移动端、键盘、错误态与轮询成本。

## 4. 范围与非范围

### 4.1 本期范围

- 项目/分集入口、上下集、分集下拉与搜索、状态徽标、计时及空/失败/暂停态。
- 必保留台词单选、全选、重复出现位置、预算、上下文与跨集草稿。
- 首次生成、继续局部修复、停止任务及任务防重。
- 剧本全文、主线、场次、辅助结构、原文来源范围的阅读和结构化编辑。
- 保存前 diff/影响预览、版本并发、先停下游任务再原子保存、失败草稿与 dirty guard。
- drop 恢复、删除、证据抽屉和“查看/生成分镜”的交接。
- 390×844 移动端、键盘、焦点管理、轮询/推送与可观测性。

### 4.2 非范围

- 改变剧本生成模型、分镜生成模型或计费单价。
- 重做分镜台内部生成/编辑体验；本 PRD 只规范剧本台到分镜台的动作拆分和任务交接。
- 修改现有业务门禁的创作标准，或用降低质量阈值代替修复。
- 一次性迁移/删除所有历史 Artifact；历史数据只做兼容读取与必要的增量迁移。
- 本期不承诺云端通用多人协作编辑；但必须以乐观锁防止多标签/后台流程覆盖。

## 6. 目标用户流程

### 6.1 选集与选择必保留台词

1. 用户进入剧本台，系统定位当前分集并展示单一状态与主操作。
2. 切集/搜索只导航；若当前编辑或台词选择有未保存变化，先提示保存草稿、放弃或留在当前页。
3. 每条候选台词按稳定出现位置展示，可展开上下文；重复文字可分别选择。
4. 页面实时显示已选数量、估算口播时长、目标时长差值和硬/软约束；全选仍可用，但超出硬约束时不允许直接启动任务。

### 6.2 生成、继续修复与停止

1. 首次生成前展示本次输入、台词预算、预计等待/费用（可用时）和约束；提交受幂等保护。
2. 修复暂停时，页面明确 checkpoint、已保留结果和约束是否可修改。若允许改，用户先保存为“新修复约束”并看到需要重规划的影响；若不允许则控件只读。
3. 停止任务展示“取消中”，直到服务端证明 worker 已停止并返回可恢复点；超时按查询结果恢复，而不是假定取消成功。

### 6.3 阅读与编辑

1. 阅读态保留主线骨架、完整正文、场次卡、辅助结构和证据入口；可折叠、定位、搜索、复制/导出。
2. 编辑态分为“主线、正文、场次、依据与状态”，场次和节拍使用结构化行，不再手写分隔符。
3. 修改产生 dirty 标记并自动保存工作草稿；撤销/重做可用；切集、路由和关闭页面有离开保护。
4. 保存发布前先做即时/服务端校验，再展示字段差异、需要停止的下游运行、将清空的镜头/媒体及重跑范围。
5. 用户批准后，服务端原子执行“阻止新下游写入 → 取消并等待相关任务退出 → 复核基线 → 保存新版本 → 清理/失效下游 → 更新状态”。

### 6.4 查看或生成分镜

1. “查看分镜台”始终纯导航，即使有 checkpoint 或失败任务也不执行写操作。
2. 需要执行时使用独立动作，如“首次生成分镜”或“继续生成分镜（从第 N 镜）”。
3. 执行动作先展示 checkpoint、预计影响、等待/费用信息，再创建任务；随后用户可选择查看分镜进度。

## 7. 详细功能需求

### SC-FR-01｜纯导航与任务执行强制拆分（P0）

- **现状问题**：“进入分镜台”表面是导航，实际可能创建或续跑任务，用户无法预判等待、失败和费用。
- **整改规则**：
  1. 所有名为“进入/查看/返回/上一集/下一集”的动作只能执行读取与导航。
  2. 分镜任务使用独立按钮，文案明确首次生成或从第 N 镜继续；执行前走服务端预检并显示 checkpoint、保留镜数、预计影响、等待与可用的费用信息。
  3. 导航和执行使用不同权限、埋点与交互组件，不允许根据页面状态在导航处理器中偷偷切换为执行。
  4. 面包屑与侧栏保留清晰入口，重复层级可在不损害定位的前提下精简。
- **异常/边界**：无分镜、存在失败 checkpoint、正在生成、已确认均不改变“查看分镜台”的纯导航语义；分镜页不可用时显示可重试错误。
- **验收标准**：点击“查看分镜台”的网络记录不存在 POST/写命令/任务创建；失败 checkpoint 仅在独立“继续生成”批准后续跑；跳转上下文仍为当前分集。

### SC-FR-02｜剧本发布与下游任务原子互斥（P0）

- **现状问题**：分镜运行中可发布剧本，旧任务未先退出就清空下游，存在竞态写回。
- **整改规则**：
  1. 分镜运行中剧本发布默认禁止；用户可继续编辑工作草稿，但发布必须走“停止下游并保存”。
  2. 服务端建立写入栅栏，阻止相关分镜运行获得新写权限；请求取消并等待 worker 到终态后，才能清空/失效下游和发布新剧本。
  3. 任一步失败时不发布新剧本、不清空已交付下游；返回可恢复状态和关联运行证据。
  4. 被取消/替代的旧运行之后每次写入都必须核对运行身份和栅栏，并被拒绝、记录和告警。
- **异常/边界**：取消超时、worker 失联、多个分镜运行、另一个会话新启任务都视为未满足发布前置条件；可保存草稿但不能发布。
- **验收标准**：保存后 30 秒及后台重试窗口内无旧 run 写入；取消失败不改变发布版和下游；并发启动任务与保存仅一个按状态机成功。

### SC-FR-03｜编辑基线、乐观锁与冲突 diff（P1）

- **现状问题**：服务端具备冲突能力，但前端未提交基线，Agent/另一标签更新后旧草稿可覆盖。
- **整改规则**：进入编辑固定剧本 Artifact 身份、版本和内容哈希；每次发布保存都提交该基线。基线变化返回冲突并保留工作草稿，展示“当前发布版/我的草稿”的字段级 diff，用户可重新加载、迁移改动或退出；不得自动采用轮询后的新版本为旧草稿背书。
- **异常/边界**：多标签、Agent 发布、删除重建、原文版本变化均触发冲突；自动草稿可以继续保存，但发布必须重新建立基线。
- **验收标准**：两个标签后保存者无法覆盖；冲突信息定位主线/正文/场次具体字段；拒绝冲突不丢用户草稿。

### SC-FR-04｜单一展示状态与唯一下一步（P1）

- **现状问题**：“修复中/已暂停”“已交付/待确认”等文案冲突，确认对象不明；空态引用错误动作。
- **整改规则**：由统一状态快照给出剧本状态、分镜状态、任务阶段、计时、错误、唯一推荐动作及操作原因。顶部只显示一句主状态，例如“剧本已交付｜分镜修复暂停在第 6 镜”；空态、徽标、按钮和错误说明必须消费同一动作定义。“待确认”必须说明确认对象。
- **异常/边界**：非法或缺失组合进入安全只读“状态同步中”；技术错误码保留在详情，不作为主状态。
- **验收标准**：pending、baseline running、repair paused、ready+无分镜、ready+分镜失败、ready+分镜运行六类至少组件覆盖；任一状态一个主操作且空态不引用不存在按钮。

### SC-FR-05｜脏数据保护、自动草稿与键盘选集（P1/P2）

- **现状问题**：编辑态切集、点侧栏、后退会丢修改；台词选择切集也丢；分集下拉缺方向键导航。
- **整改规则**：正文、结构、状态和台词选择任一变化即标 dirty，并将工作草稿按项目/分集/用户本地或服务端保存。切集、路由、后退和关闭前提供“保存草稿/放弃/留在当前页”；恢复页面提示可恢复草稿。分集组合框支持 ArrowUp/Down、Enter、Escape、活动项滚动；统一集号显示格式。
- **异常/边界**：草稿存储失败时显著提示且阻止无确认离开；浏览器无法拦截的崩溃由自动草稿恢复。
- **验收标准**：所有离开路径无静默丢失；刷新后恢复最近草稿；纯键盘可搜索并选择第 1646 集；首尾禁用和最多 60 条说明保持。

### SC-FR-06｜按出现位置选择台词与实时预算（P1/P2）

- **现状问题**：相同文本按字符串去重；27 条可全选但只有软提醒，50 秒目标无口播预算。
- **整改规则**：
  1. 每次台词出现使用稳定 occurrence 标识，展示章节/段落或序号和上下文；相同文字可独立选择。
  2. 实时展示已选条数、估算口播秒数、目标秒数、超出量、硬/软限制及估算口径。
  3. 可识别问答、反驳等上下文组并建议成组选择，但用户可展开审阅并在业务允许时调整。
  4. 固定“最多 6 条”改为由当前时长、语速、必保留项和业务规则共同计算的动态上限；页面解释必保留台词可能抬高上限及其时长代价，不把动态上限伪装为模型成功保证。
  5. 全选/取消全选保留；超过硬约束时主操作禁用并给出拆分/减少/调整目标的真实路径，软风险说明收敛概率而非保证结果。
  6. 选择随分集保存为草稿，不因导航丢失。
- **异常/边界**：估算服务不可用时显示不可用而非 0 秒；原文变更使 occurrence 失效时列出需重选项。
- **验收标准**：重复文本可分别勾选；上下文成组建议正确、可解除且不会强制误分组；27 条全选仍工作并显示预算；50 秒目标的动态上限、必保留台词影响和超额可量化；提交使用稳定出现标识而非文本去重键。

### SC-FR-07｜首次生成与分镜执行预检、防重（P1）

- **现状问题**：首次生成缺输入/时长/费用说明，提交后刷新未等完成，短窗口可能重复；分镜续跑曾被导航隐式触发。
- **整改规则**：剧本首次生成和独立分镜生成动作均先展示输入摘要、约束、可用的等待/费用估算与影响。提交带业务幂等键，按钮保持提交中直至收到任务身份或确定失败；相同分集、基线和输入的活动任务返回现有任务，不新建。
- **异常/边界**：请求超时后先查询现有任务再允许重试；估算不可用时明确未知，不展示伪精确值。
- **验收标准**：快速双击、刷新、网络重试仅创建一个任务；必保留台词完整进入剧本首次生成；分镜执行只有独立按钮可触发。

### SC-FR-08｜继续修复的约束语义（P1）

- **现状问题**：暂停态台词可编辑，但继续修复不携带本地变化，用户修改无效。
- **整改规则**：系统必须二选一并由状态契约明确：若 checkpoint 不允许改约束，则台词控件只读并解释；若允许，则提供“保存新约束并重新规划修复”，服务端返回 checkpoint 可复用范围和将重跑阶段，用户批准后创建新修复计划。继续按钮摘要展示本次实际使用的约束版本。
- **异常/边界**：新约束与已保留产物冲突时必须重规划，不能静默忽略；保存约束失败保留本地草稿。
- **验收标准**：可编辑约束 100% 进入修复任务并可从任务详情核对版本；锁定态无法勾选；旧 checkpoint 不错误消费新约束。

### SC-FR-09｜停止任务的可观察终态（P1）

- **现状问题**：有取消能力，但缺取消中过渡、完成证据，实测未覆盖运行中取消。
- **整改规则**：停止后显示取消中、请求时间和运行身份，持续获取服务端状态直至已取消/已完成/取消失败；完成显示保留产物和恢复点。重复停止幂等，按钮在处理中不可重复触发。
- **异常/边界**：任务恰好完成返回已完成，不用红色错误；超时允许后台继续观察并提醒用户，不宣称已停止。
- **验收标准**：运行中真实/受控 E2E 覆盖取消；每个结果有证据和下一步；取消中不得发布剧本。

### SC-FR-10｜统一高影响批准与取消语义（P1）

- **现状问题**：保存先 `window.confirm` 再服务端批准；drop 恢复也用原生确认；用户拒绝删除被通用异常显示为红色错误。
- **整改规则**：所有高影响动作只使用服务端计算的统一影响卡，移除原生确认。影响卡展示不可恢复性、下游数量、保留信息、差异和批准有效期；拒绝/关闭属于中性“未执行”，不进入错误通道。删除当前/失败剧本现有 R3 预检信息完整性必须保留。
- **异常/边界**：批准过期或状态变化要求重新预览；服务端拒绝与用户取消分别呈现。
- **验收标准**：一次动作只出现一次批准；拒绝后数据不变且无红色错误；下游影响与实际执行一致。

### SC-FR-11｜面向编剧的结构化编辑器（P1）

- **现状问题**：20 多字段堆在一页，场次/节拍用 `|` 分隔，缺目录、撤销、草稿、即时校验；来源范围错误显示为空。
- **整改规则**：
  1. 分为“主线、正文、场次、依据与状态”页签或锚点，并提供目录和每区错误数。
  2. 主线节拍、场次、人物状态使用结构化行/卡，可增删排序；正文里的 `|` 是普通字符，不参与结构解析。
  3. 即时校验必填、字符数、台词是否可追溯到正文、目标时长等；服务端仍执行最终门禁。
  4. 支持撤销/重做、自动草稿和保存前差异；分区“保存”仅保存工作草稿，发布仍为一次完整原子动作。
  5. 原文来源范围优先展示已有结构化范围，缺失时回退本集章节范围并标记“推断显示”，不要求用户重复手填。
- **异常/边界**：导入历史分隔文本需一次解析预览，列数异常交给用户确认，不静默补空后发布。
- **验收标准**：任何字段含 `|` 都不串列；结构项可独立增删排序；错误可定位；979 字正文编辑与放弃/恢复无丢失；来源范围不再无故为空。

### SC-FR-12｜保存前差异/影响预览与原子发布（P0/P1）

- **现状问题**：保存清空下游的后果分两次确认，缺少统一差异，且与运行任务未原子协调。
- **整改规则**：保存前服务端基于 SC-FR-03 基线返回字段 diff、硬门禁、受影响镜头/参考图/视频/成片数量、需停止的运行、重跑范围和批准凭据。用户批准后执行 SC-FR-02 原子流程；内容无变化时返回 unchanged，不创建新 Artifact 或清空下游。保存成功生成可追溯证据版本。
- **异常/边界**：预览后基线、下游或运行状态变化，批准失效并重新预览；预览失败可继续存草稿但不可发布。
- **验收标准**：影响数字与实际一致；no-op 无版本/下游变化；任一步失败保持原发布版；无需第二次确认。

### SC-FR-13｜drop 恢复“可拍化”向导（P1）

- **现状问题**：恢复项直接写入关键剧情点，缺少如何改成可见/可听内容的引导和差异预览。
- **整改规则**：保留先授权再逐条恢复的谨慎入口；恢复流程依次要求恢复原因、可见/可听改写、落入节拍/场次、影响检查和差异预览。结果先进入工作草稿，不直接发布；批准复用 SC-FR-10/12。
- **异常/边界**：与当前主线重复、超过时长或不可拍时给出校验，不强行恢复；取消为中性结果。
- **验收标准**：恢复后可定位到具体节拍/场次，保存前有 diff；未经发布不影响下游；现有授权门槛不降低。

### SC-FR-14｜阅读效率与信息去重（P2）

- **现状问题**：主线节拍和长页缺定位；完整剧本缺复制/导出/搜索/跳场；辅助结构与主线/场次重复。
- **整改规则**：主线、场次、辅助结构支持折叠和章节导航；正文提供页面内搜索、复制、按现有合规格式导出和跳转场次。辅助结构与主线相同内容只保留摘要或关联链接，默认折叠。保持字数、行数、主线前提/节拍/收束与场次卡信息层级。
- **异常/边界**：复制/导出受项目权限控制；搜索仅客户端处理当前已加载正文时不得上报关键词。
- **验收标准**：979 字样本展开/收起、字数/行数不退化；能定位匹配和场次；主线/场次高分视觉回归通过。

### SC-FR-15｜证据抽屉三态与无障碍（P2）

- **现状问题**：血缘失败静默变空，用户可能把失败当作 0 下游；抽屉无加载/失败态、焦点锁定和 Escape。
- **整改规则**：证据和血缘分别呈现 loading/success/error，error 保留已成功数据并提供重试；“0 个下游”仅在服务端成功返回空集合时显示。抽屉打开后锁定焦点、Escape 关闭、关闭归还触发点；技术 Hash/版本可复制，主结论使用业务语言。
- **异常/边界**：部分加载成功需显示部分结果和失败区，不整体清空；请求过期不覆盖新分集抽屉。
- **验收标准**：模拟血缘 5xx/超时显示错误而非 0；真实 0 与失败可区分；纯键盘完整操作；T2、硬门禁、100 分评估、版本/Hash及 29 下游样本无回归。

### SC-FR-16｜390×844 移动端信息分层（P2）

- **现状问题**：无横向溢出，但约 670px 状态卡占满首屏，正文不可见。
- **整改规则**：移动端首屏只显示主状态、主操作和剧本摘要/“查看剧本”；计时、证据、能力边界、技术错误收进“详情”底部抽屉。固定操作避让安全区和软键盘，保留搜索弹层尺寸与 Escape 行为。
- **异常/边界**：200% 字体、横竖屏和软键盘下不遮挡编辑/保存；长错误不撑高首屏。
- **验收标准**：390×844 无横溢，正文摘要一次操作可达；视觉回归覆盖运行、失败、编辑、证据抽屉；搜索弹层现有正确行为保持。

### SC-FR-17｜高分能力保留与回归（P1）

- **现状问题**：安全/编辑重构可能破坏现有 8～9 分能力。
- **整改规则**：保持项目入口自动定位、上下集边界、1646 集搜索与 60 条限制、27 条全选/取消、删除 R3 影响信息、主线层级、979 字正文排版/计数/展开、场次卡审阅和辅助结构。任何视觉调整不得减少只读信息；原有错误 ID 保留于技术详情。
- **异常/边界**：历史剧本字段缺失时以兼容展示替代白屏；回归失败阻断发布。
- **验收标准**：扫描记录中的所有高分正向路径进入自动化或人工回归清单并通过；详情见 SC-AT-18～22。

### SC-FR-18｜轻量状态同步与轮询降载（P2）

- **现状问题**：1646 集项目中 picker 约 125,158B/3s、当前集约 35,710B/2s，约 3.6MB/分钟，多标签页放大。
- **整改规则**：分集选择数据与当前集详情分离；列表仅同步定位和展示状态所需最小字段，支持 ETag/增量版本或等价缓存。运行状态使用轻量查询、SSE/现有推送能力中的可行方案；页面隐藏、无运行任务和非当前标签降低或停止轮询。响应带单调版本，旧响应不得覆盖新状态。
- **异常/边界**：推送断开退化为带抖动/退避的轻量轮询；重新激活页面立即校验一次，不依赖陈旧缓存执行写操作。
- **验收标准**：同等样本一分钟传输较基线下降 ≥80%；三标签不会线性请求完整 picker；状态变化时延满足现有生产要求并由技术方案量化。

## 8. 状态与交互规则

| 实际状态 | 主文案 | 唯一主操作 | 可编辑/发布 | 分镜交接 |
|---|---|---|---|---|
| pending | 尚未生成剧本 | 首次生成剧本 | 仅台词选择；无发布 | 查看分镜可导航，但不生成 |
| baseline running | 正在生成首版剧本 | 停止生成 | 只读 | 仅查看状态 |
| repair paused | 局部修复已暂停在阶段 X | 继续局部修复 | 约束按 SC-FR-08 锁定或新建计划 | 可纯导航查看已有分镜 |
| ready + storyboard empty | 剧本已交付，尚无分镜 | 生成分镜 | 可编辑草稿；发布走影响预览 | “查看”与“生成”分开 |
| ready + storyboard failed | 剧本已交付，分镜停在第 N 镜 | 继续生成分镜 | 可编辑草稿；发布需先停任务（如有） | 继续动作先预检 |
| ready + storyboard running | 剧本已交付，分镜生成中 | 查看分镜进度 | 可编辑草稿，不可直接发布 | 查看纯导航；停止后才可发布 |
| editing dirty | 有未保存修改 | 预览并保存 | 草稿自动保存；离开受保护 | 执行任务前处理草稿 |
| save stopping downstream | 正在安全停止下游任务 | 查看进度 | 禁止重复保存/发布 | 不允许新启分镜 |
| conflict | 当前剧本已被更新 | 查看差异 | 草稿保留，解决后发布 | 不基于旧版启动任务 |
| unknown/invalid | 状态同步中 | 刷新状态 | 仅只读/存草稿 | 禁止执行任务 |

通用规则：导航按钮不弹高影响批准卡，因为它无副作用；执行按钮必须用动词和对象明确说明动作。Toast 不承载草稿恢复、版本冲突、任务取消、下游影响等持久决策。用户取消批准是中性状态，不展示红色异常。

## 9. 数据、API 与后台任务要求

以下定义语义能力，优先复用和扩展现有接口；不得因 PRD 名称直接新增未经设计评审的具体路径。

剧本台与分镜台必须消费同一份分镜状态、推荐动作和任务启动预检契约。语义字段可参考 `storyboard_status`、`recommended_action`，最终代码命名由技术设计确认；同一状态必须返回相同动作码。失败可恢复统一表达为“继续生成分镜（从第 N 镜）”，运行中统一以“查看分镜进度”为主操作，页面不得自行创造另一套动作语义。

| 能力 | 输入/输出语义 | 强制约束 |
|---|---|---|
| 统一剧本台状态快照 | 剧本/分镜状态、运行身份/阶段、计时、发布版、checkpoint、推荐动作、快照版本 | 原子一致；非法组合安全失败；所有 UI 共用 |
| 台词 occurrence 数据 | 稳定出现标识、文本展示、原文位置、上下文组、估算时长 | 相同文本不同位置不可合并；原文版本变化可判失效 |
| 生成/修复预检 | 动作类型、剧本/分镜基线、输入摘要、约束版本、checkpoint、已保留镜头、计划/剩余镜头、影响、等待/费用可用信息、预检版本与幂等语义 | 预检零写入；执行与导航分权；创建任务时复核同一版本；状态变化使旧预检失效；相同活动任务不重复创建；两页面口径一致 |
| 编辑草稿 | 用户/分集、基线、结构化变更、dirty 时间、校验结果 | 与发布版隔离；可恢复；不驱动下游 |
| 保存影响预览 | 字段 diff、门禁、下游计数、活动运行、重跑范围、批准凭据 | 与执行共享计算；状态变化即过期 |
| 原子发布命令 | 基线、预览凭据、工作草稿身份 | 写入栅栏→cancel-and-wait→复核→发布→失效下游在单一一致性流程内 |
| 任务控制/状态 | 运行身份、动作、幂等键；返回过渡/终态和恢复点 | 取消未终态前不得宣称成功；旧运行写入被拒绝 |
| 证据与血缘 | 独立 loading/error/success 所需数据、版本和下游计数 | 错误不可伪装为空；部分成功保留 |
| 轻量列表/状态同步 | 分集最小字段、增量版本/缓存标识、活动状态 | 隐藏页降频；旧响应不覆盖新快照 |

结构化编辑数据不得再依赖显示字符串分隔解析。历史 `|` 格式在读取时进入显式迁移/预览层，发布存储使用领域结构。服务端在每个后台写点校验运行身份、剧本基线和栅栏；所有取消、冲突、批准和发布动作形成审计链。

## 12. 实施阶段、风险与回滚

### 12.1 分阶段实施

1. **阶段 A（上线阻断/P0）**：拆分查看与执行；发布写入栅栏和 cancel-and-wait；运行态只存草稿；接入编辑基线；先用功能开关隐藏危险入口。
2. **阶段 B（核心 P1）**：统一状态、dirty guard/自动草稿、结构化编辑、台词预算、修复约束版本、统一影响卡、原子发布、停止任务终态、drop 向导。
3. **阶段 C（P2 与保持项）**：移动端分层、证据三态与无障碍、阅读导航/搜索/复制/导出、轻量同步和键盘选集；全量高分能力回归。

### 12.2 风险与缓解

| 风险 | 缓解 |
|---|---|
| cancel-and-wait 增加保存耗时 | 先存草稿；明确进度；超时不发布；后台提供运行终止诊断 |
| worker 不支持及时停止 | 先上线写入栅栏，使旧运行即使继续计算也无法污染数据；再优化取消延迟 |
| 历史分隔文本迁移错列 | 只读兼容 + 解析预览 + 人工确认；不批量静默覆盖 |
| 状态契约升级影响旧前端 | 版本化响应、兼容期和未知状态安全只读降级 |
| 估算时长/费用不稳定 | 显示区间与口径/更新时间；不可用时明确未知，不以客户端估算作扣费依据 |
| 自动草稿涉及敏感正文 | 采用现有授权存储、最小保留和显式清理；常规埋点不含正文 |
| 同步降载造成状态延迟 | 活动任务用轻量推送/高频状态，静态列表缓存；写操作前强制刷新状态 |

### 12.3 回滚策略

- 导航/执行拆分、基线并发、写入栅栏和服务端发布门禁属于安全底线，不随 UI 回滚撤销。
- 新编辑器以功能开关按项目灰度；回滚到旧只读视图时保留新结构数据读取，发布入口可临时关闭，草稿不得删除。
- 推送/增量同步异常时退化为带缓存和退避的轻量轮询，不退回全量 2～3 秒无条件轮询。
- drop 向导、阅读增强和移动布局可独立关闭；关闭不改变发布版或已批准影响。
- 发生状态契约异常时启用安全只读页面：允许查看/导出/复制错误 ID，禁止发布、删除和创建/续跑任务。
