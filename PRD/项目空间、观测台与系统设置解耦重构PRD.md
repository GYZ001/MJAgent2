## 2. 执行摘要与已确定产品决策

本次重构将现有“项目中心 + 项目制作菜单 + 全局监制房”改为三个明确隔离的产品空间：

1. **项目空间选择态**：每一部已上传小说就是一个项目空间；上传小说等价于创建项目空间。
2. **项目工作空间**：围绕当前小说展示现有五个制作菜单，并新增当前项目专属的“观测台”。
3. **系统设置空间**：从左侧底部进入独立全页，只保留“总览、模型中心、系统设置”三个系统级能力。

目标信息架构：

```text
漫剧案头（产品）
├── 项目空间选择 / 创建
├── 项目工作空间：《当前小说》
│   ├── 前期准备
│   ├── 剧本台
│   ├── 分镜台
│   ├── 生成台
│   ├── 成片台
│   └── 观测台
│       ├── 运行中心
│       ├── 任务队列
│       └── 调用日志
└── 系统设置空间
    ├── 总览
    ├── 模型中心
    └── 系统设置
```

关键决策如下：

- “项目中心”不再占用左侧一级制作菜单；项目列表、搜索、切换和创建收敛到产品名下方的项目空间切换器，并保留独立的“管理全部项目空间”页面。
- 现有五个制作菜单的业务能力、名称、顺序、项目/分集选择逻辑不变；“前期准备”内部的人物谱、场景库、分集规划三级导航继续保留。
- 观测台是**项目级第六个入口**，其中只有运行中心、任务队列、调用日志三个子页；固定绑定 URL 中的项目，不提供可切换到其他项目的高级筛选。
- 系统设置按钮固定在左侧底部。点击后打开独立 SPA 全页路由，而不是弹窗、浏览器新窗口或叠加在项目页面上的抽屉。
- 系统设置空间不挂载项目制作菜单，也不继承当前项目 ID；返回项目时恢复离开前的项目路由。
- 系统总览允许展示跨项目的**聚合健康数据**，但不展示跨项目的逐条 Run、任务或调用记录；明细只能进入对应项目的观测台。
- 项目隔离必须由服务端校验，不能只依赖前端把 `project_id` 放进查询参数。

## 3. 背景、现状证据与主要风险

### 3.1 当前实现基线

| 区域 | 当前实现 | 本次必须解决的问题 |
|---|---|---|
| 应用路由与导航 | `frontend/src/App.tsx` 用单个 `View` 联合类型维护页面；`/monitor` 被视为全局页面并清空 `projectId` | 无法表达“项目观测”与“系统设置”两种不同作用域；切换时易携带或丢失错误上下文 |
| 项目入口 | `frontend/src/pages/Studio.tsx` 同时承担项目列表、上传、创建、删除和进入项目 | “小说就是空间”的心智不突出；切换项目需要先退回项目中心 |
| 监制房 | `frontend/src/pages/MonitorPage.tsx` 在一个 4200+ 行组件中混合总览、Run、任务、模型、调用和设置 | 数据获取、URL、抽屉、写操作与系统配置强耦合，拆页面时容易产生联动回归 |
| Run | `/runs/query` 支持可选 `project_id`；`RunCenter` 仍允许手工输入任意项目，门禁请求当前为全局 `/gates?limit=100` | 项目观测台如果只预填筛选，仍可能被清除或通过详情接口访问其他项目 |
| 任务 | `/system/jobs/query` 支持可选 `project_id`，但响应中的 `counts` 继承全局汇总 | 项目列表与顶部计数可能口径不一致，造成“列表只有本项目、计数却包含全部项目” |
| 调用日志 | `/system/calls/query` 从调用 `meta` 中读取项目上下文并可选过滤；详情按调用 ID 直接读取 | 历史记录可能只通过 Run/Step 间接归属项目；详情端点没有验证当前项目 |
| 系统能力 | 模型、设置、健康状态与业务观测共用 MonitorPage 生命周期 | 进入项目日志会额外加载系统设置/模型；修改设置时也会轮询项目任务，边界和故障域过大 |

### 3.2 本次最高风险

1. **跨项目串数据**：列表按项目过滤，但总数、聚合、详情、人工门禁或写动作没有按同一项目复核。
2. **项目切换串状态**：旧项目的 `episodeId`、选中 Run/Job/Call、请求响应或未保存草稿进入新项目。
3. **拆分导致能力丢失**：当前监制房已有的搜索、分页、异常聚合、详情抽屉、连接测试、设置原子保存等能力在组件搬迁时回退。
4. **旧深链失效**：现有 `/monitor?section=...&run_id=...`、页面内“查看进度”和助手引用不能定位到新页面。
5. **重复实现形成双重事实源**：为项目观测台新写一套 Run/Job/Call 查询，旧系统查询继续演进，最终口径分叉。
6. **系统与项目生命周期互相干扰**：项目页卸载触发系统设置草稿丢失，或系统页错误携带项目 Agent 上下文。

## 4. 目标、成功指标与非目标

### 4.1 产品目标

- 用户在任意项目页面都能看清当前产品、当前小说项目以及所在制作环节。
- 用户可以像 HiAgent 切换空间一样直接切换小说项目，无需回到项目中心。
- 运行、任务和调用信息天然属于当前项目，页面上不再把“指定项目”作为可编辑筛选项。
- 系统配置与项目制作完全分离，避免把模型、并发、预算等全局变更误认为只影响当前小说。
- 在不改动核心生产链路的前提下分阶段迁移，任一阶段都能独立回滚。

### 4.2 量化成功指标

| 指标 | 放行标准 |
|---|---|
| 项目观测数据隔离 | A 项目观测台的列表、计数、聚合、详情、下载、门禁与动作请求中出现 B 项目数据的次数为 0 |
| 路由恢复 | 刷新、前进、后退、复制链接后，项目、菜单、观测子页和合法选中对象恢复率 100% |
| 项目切换安全 | 切换项目后旧 `episodeId`、Run/Job/Call ID、筛选、旧请求响应残留率为 0 |
| 能力保留 | 原监制房运行中心、任务队列、调用日志、模型中心、系统设置的既有 P0/P1 验收能力回归通过率 100% |
| 生产链路零改动 | 小说导入、人物/场景、分集、剧本、分镜、生成、成片的领域接口和持久状态机无语义变更 |
| 可理解性 | 所有项目业务页都显示当前项目名称；所有系统设置页明确显示“全局生效”，覆盖率 100% |
| 请求解耦 | 项目观测页不请求模型目录或设置 schema；系统设置页不轮询项目 Run/Job/Call 明细 |
| 响应式可用 | 桌面和 390px 窄屏均可完成空间选择、五个制作菜单、观测切页、系统进入与返回 |

### 4.3 非目标

- 不重写工作流引擎、任务调度器、Provider 调用协议和媒体流水线。
- 不改变现有五个制作菜单内部的业务规则、人工确认门、费用确认或资产版本语义。
- 不引入多租户、成员、权限角色或云端团队空间；“空间”仍是本地单人产品中的小说项目容器。
- 不在本期重做品牌视觉、配色系统或全部业务页面内容区。
- 不把系统设置改成项目级覆盖；现有设置仍是全局设置，除非未来另立 PRD。
- 不删除历史观测数据，也不要求为上线强制重算全部历史记录。

## 5. 术语与作用域定义

| 术语 | 定义 | 是否携带 `projectId` |
|---|---|---|
| 产品 | 整个“漫剧案头”应用 | 否 |
| 项目空间 | 一部小说及其章节、人物、场景、分集、剧本、分镜、视频、成片和观测数据的容器 | 是 |
| 工作空间 | 用户进入某一项目后的制作界面，与“项目空间”同义，界面文案统一使用“项目空间” |
| 观测台 | 当前项目的运行中心、任务队列、调用日志集合 | 必须 |
| 系统设置空间 | 全局总览、模型中心、系统设置的独立界面 | 禁止 |
| 系统总览 | 全局健康和跨项目聚合，不包含跨项目逐条日志列表 | 否 |
| 未归属记录 | 无法可靠解析到任何项目的历史或系统级 Run/Job/Call | 否，不得塞入任一项目 |

作用域是不变量：

```text
project route  => projectId 必须存在且项目有效
system route   => projectId 必须为 null
workspace list => projectId 可为空
```

不得以“最后一次项目”“列表第一项”或前端缓存猜测记录归属。

## 6. 目标页面结构与布局

### 6.1 项目工作空间

桌面端左侧栏从上到下固定为：

```text
┌────────────────────────┐
│ [折叠]  漫剧案头        │  产品名称
│ [封面]《当前小说》 ⌄  ＋ │  项目空间切换 / 创建
├────────────────────────┤
│ 前期准备                │
│   备  前期准备          │
│ 内容制作                │
│   剧  剧本台            │
│   镜  分镜台            │
│ 质量交付                │
│   生  生成台            │
│   片  成片台            │
│ 项目管理                │
│   观  观测台            │
│                        │
├────────────────────────┤
│   ⚙  系统设置           │  固定底部
└────────────────────────┘
```

布局规则：

- 左上只展示产品名称“漫剧案头”和折叠按钮；不把当前项目名混进品牌区。
- 项目切换器固定在品牌下方。项目名称单行省略，悬停/聚焦可看到完整名称；封面可继续使用现有默认“漫”字封面。
- 五个现有制作菜单保持现有名称、分组、顺序、图标语义和激活样式。
- “观测台”独立于五个制作菜单，放在“项目管理”分组，避免用户误认为它是生产阶段。
- 系统设置固定在侧栏底部，不随中部菜单滚动；需要状态提示时只显示非干扰性健康点，不显示项目任务数量。
- 折叠态仍保留产品图标、项目封面、六个项目入口图标和系统设置图标；每个图标必须有 `title` 与可访问名称。

### 6.2 项目空间切换器

展开后结构参考 HiAgent，但使用本产品字段：

```text
搜索项目空间
最近使用
  《项目 A》  制作中
  《项目 B》  需要处理
全部项目空间
  ...
────────────────
＋ 创建项目空间
  管理全部项目空间
```

- 搜索仅过滤已成功加载的项目列表；加载、错误、空列表分开表达。
- 当前项目使用勾选和背景同时标记，不能只靠颜色。
- 键盘支持：打开后聚焦搜索；上下键移动；Enter 切换；Esc 关闭并返回触发器。
- 项目超过 20 个时使用分组/虚拟列表或受控滚动，不让弹层超过视口。
- “创建项目空间”打开小说导入流程；“管理全部项目空间”进入保留现有卡片信息和删除能力的管理页。

### 6.3 观测台页面

观测台顶部必须始终显示固定上下文：

```text
《当前小说》 / 观测台
[运行中心] [任务队列] [调用日志]       作用域：仅当前项目
```

- 子导航继续使用当前监制房成熟的 URL 化、激活态与状态徽标方式。
- 删除“指定项目（高级筛选）”输入框；用不可编辑的项目作用域标签替代。
- 其他搜索、状态、工作流、功能、模型、时间、排序、分页和历史筛选能力继续保留。
- 所有加载、空、错误、过期文案必须带当前项目名称，避免用户误判查询范围。

### 6.4 系统设置空间

系统设置为独立全页，不与项目工作空间共用项目菜单：

```text
┌────────────────────────┐
│ [返回]  漫剧案头        │
│ 系统设置                │
├────────────────────────┤
│ 总览                    │
│ 模型中心                │
│ 系统设置                │
│                        │
└────────────────────────┘
```

- 页面标题区显式标注“全局设置，可能影响所有项目和后续新任务”。
- “返回项目空间”返回进入系统页之前的完整项目 URL，包括具体集和页面；原项目已删除时回到项目空间选择页。
- 系统页不显示项目切换器、五个制作菜单、观测台菜单或项目任务徽标。
- 系统设置存在未保存草稿时，返回、浏览器后退、切换系统子页均继续使用现有离开保护。

### 6.5 窄屏

- 沿用当前 `720px` 移动导航断点；390px 为强制验收视口。
- 移动端顶部按钮打开完整侧栏抽屉；项目切换弹层在侧栏内占可用宽度，不叠出屏幕。
- 系统页与项目页使用不同抽屉菜单；关闭抽屉后焦点返回触发器。
- 表格按现有方案使用横向滚动或卡片化，不因新侧栏压缩列宽。

## 7. 路由、导航与兼容合同

### 7.1 新路由表

| 页面 | 新路由 | 作用域 |
|---|---|---|
| 项目空间选择/管理 | `/workspaces` | 无项目 |
| 创建项目空间 | `/workspaces/new`，也可由受控对话框承载并同步 URL | 无项目 |
| 前期准备 | `/projects/:projectId/bible`、`/scenes`、`/episodes` | 项目 |
| 剧本/分镜/生成/成片 | 保留现有项目级与 `/episodes/:episodeId/:view` 路由 | 项目 + 可选分集 |
| 观测台运行中心 | `/projects/:projectId/observability/runs` | 项目 |
| 观测台任务队列 | `/projects/:projectId/observability/jobs` | 项目 |
| 观测台调用日志 | `/projects/:projectId/observability/calls` | 项目 |
| 系统总览 | `/system/overview` | 系统 |
| 模型中心 | `/system/models` | 系统 |
| 系统设置 | `/system/settings` | 系统 |

根路由 `/` 的行为：

1. 若本地保存的最后项目仍存在，恢复该项目最后一个合法路由。
2. 若没有最后项目、项目已删除或从未创建项目，进入 `/workspaces`。
3. 不允许静默打开列表第一项，避免用户在错误项目中继续操作。

“最后路由”只用于体验恢复，不是权限或记录归属依据；读取后必须向项目列表验证。

### 7.2 类型化路由状态

前端路由模型必须从“一个 `View` + 多个可空 ID”改成可判别联合，防止非法组合：

```ts
type AppRoute =
  | { scope: 'workspace-index'; page: 'list' | 'new' }
  | {
      scope: 'project'
      projectId: string
      page: 'bible' | 'scenes' | 'episodes' | 'script' | 'board' | 'wall' | 'cinema' | 'observability'
      episodeId?: string
      observabilityTab?: 'runs' | 'jobs' | 'calls'
    }
  | { scope: 'system'; page: 'overview' | 'models' | 'settings' }
```

系统路由不可构造 `projectId`；项目路由不可缺少 `projectId`。Agent 上下文、轮询生命周期和导航高亮都从该路由对象派生，不再分别维护可能漂移的状态。

### 7.3 切换项目规则

| 当前页面 | 切换项目后的目标 | 必须清理 |
|---|---|---|
| 前期准备三页 | 新项目同名页面 | 旧项目数据快照、抽屉、选择项 |
| 剧本/分镜/生成/成片 | 新项目同名项目级入口；再解析新项目自己的最近/首个合法分集 | 旧 `episodeId`，不得用相同字符串猜测 |
| 观测台 | 新项目同一观测子页 | Run/Job/Call ID、项目相关筛选、详情、请求序列 |
| 项目空间管理 | 进入新项目默认前期准备页 | 管理页临时选择 |

- 任一页面存在未保存草稿时，先触发现有导航保护；用户取消后切换器必须恢复原项目。
- 切换成功后页面以 `key={projectId}` 或等价边界重挂载，并取消旧请求或忽略请求序列不匹配的响应。
- 只可保留与项目无关的展示偏好，如每页数量、排序方向、侧栏折叠状态；不得保留对象 ID 和项目过滤值。

### 7.4 旧路由兼容

| 旧路由 | 兼容行为 |
|---|---|
| `/` | 按 7.1 节解析到最后项目或 `/workspaces` |
| `/monitor`、`?section=overview` | `replace` 到 `/system/overview` |
| `/monitor?section=models` | `replace` 到 `/system/models` |
| `/monitor?section=settings` | `replace` 到 `/system/settings` |
| `/monitor?section=runs&run_id=...` | 先解析 Run 的项目归属，再 `replace` 到项目观测台并保留 Run ID |
| `/monitor?section=jobs&job_id=...` | 先解析任务归属，再进入对应项目任务队列 |
| `/monitor?section=calls&call_id=...` | 先解析调用归属，再进入对应项目调用日志 |
| `/monitor?section=runs/jobs/calls` 且无可解析项目 | 进入 `/workspaces?intent=observability&tab=...`，明确提示先选项目，不默认选第一项 |

“可解析项目”可以来自目标对象的权威归属，也可以来自旧链接中合法的 `run_project/job_project/call_project`；两者同时存在却不一致时按范围冲突处理，不能任选其一。

旧深链解析失败时显示持久错误和“返回项目空间”入口，不把用户送到其他对象。兼容期至少跨两个稳定版本，并记录旧链接使用量后再决定移除。

## 8. 项目空间创建与管理流程

### 8.1 创建项目空间

现有小说导入领域能力保持不变，仅重命名和搬迁入口：

```text
点击“创建项目空间”
→ 输入项目名（可选）并选择一个 TXT
→ 本地校验文件
→ 明确展示会创建项目并启动后台准备、可能产生费用
→ 上传附件并换取 attachment_token
→ 调用现有项目导入命令
→ 成功后切到新项目“前期准备”
```

保留要求：

- 一次只允许一份 TXT；编码、空文件、扩展名、体积校验保持现有规则。
- 选择文件不立即创建；确认后才上传和创建。
- 使用当前 attachment token 幂等逻辑，响应丢失重试不得重复创建项目。
- 自动分集、人物谱和素材准备的启动方式、费用确认及失败语义不变。
- 创建失败保留已选文件和仍有效的 attachment token；现有项目不受影响。
- 创建成功后刷新共享项目目录，再导航；不得依赖下一次 6 秒轮询才出现。

### 8.2 管理全部项目空间

- 复用现有项目卡片的章节数、集数、字数、制作阶段和错误状态。
- 删除项目继续使用现有高风险确认与后端清理能力。
- 删除当前项目成功后：取消其后台任务，清理共享目录缓存和最后路由，进入 `/workspaces`；其他项目状态不重置。
- 删除非当前项目不打断当前页面，只刷新切换器和管理列表。
- 删除进行中时禁用同一项目的切换与重复删除；失败后保留目标和错误详情。

## 9. 项目观测台详细需求

### 9.1 通用作用域要求

| 需求 ID | 优先级 | 需求 |
|---|---|---|
| OBS-SCOPE-001 | P0 | 所有列表请求、汇总、聚合、详情、下载、人工门禁、重试、恢复、取消和源页面跳转都必须验证对象的有效项目归属等于路径 `projectId` |
| OBS-SCOPE-002 | P0 | 响应必须回显权威 `scope.project_id/project_name`；前端发现与路由不一致时拒绝渲染并上报，不尝试自行修正 |
| OBS-SCOPE-003 | P0 | 未归属记录不进入任何项目观测台；项目空查询不能混入“上下文未关联”记录 |
| OBS-SCOPE-004 | P0 | 列表 `items`、`total`、`counts`、`aggregates`、`page_count` 必须在同一项目过滤后计算 |
| OBS-SCOPE-005 | P1 | 项目切换、删除或快速切页时，旧响应不得覆盖新项目；详情对象不在新列表时必须清空而非保留 |

服务端对于“对象存在但不属于路径项目”的读取统一返回不可枚举的 404；写动作同时记录被拒绝的作用域冲突审计，但不向前端泄露另一个项目名称。

### 9.2 运行中心

保留现有能力：默认待处理/异常集、搜索、状态、工作流、集数、时间、历史开关、排序、分页、Run/Step/Event 时间线、人工门禁、证据、取消/恢复/重试、错误详情和深链高亮。

调整规则：

- `RunCenter` 接收必填 `projectId`，组件内不再允许把项目筛选清空或改成其他项目。
- 门禁查询必须携带相同项目；证据详情和决策动作再次校验证据所属项目。
- Run 详情、Steps、Events 和关联 Artifact 使用同一个作用域守卫。
- 从项目任意业务页面打开运行详情时生成 `/projects/:projectId/observability/runs?run_id=...&focus=...`。
- Run 若属于已删除项目或无法归属，项目观测台不展示；旧深链显示“目标运行无法归属到该项目”。

### 9.3 任务队列

保留现有能力：搜索、状态、工作流、时间、排序、分页、真实总数、详情抽屉、错误码、重试/恢复/取消和源页面跳转。

调整规则：

- 顶部状态计数必须从项目过滤后的任务集合计算，不复用全局 `jobs_overview().counts`。
- Run 投影任务、无 Run 的旧媒体任务和旧剧本任务继续合并，但三类记录必须使用同一个项目归属解析器和去重规则。
- 详情接口按 `(projectId, jobId, source)` 查找；仅按 `jobId` 查询后由前端判断不合格。
- “去源页面”只允许生成同一项目下的 URL；发现记录中的项目与路由不一致时禁用并显示范围错误。
- 动作响应若创建新 Run，必须返回其 `project_id`；不一致时不自动跳转。

### 9.4 调用日志

保留现有能力：业务/工作流/内部类别、搜索、状态、模型、功能、时间、排序、分页、异常聚合、脱敏详情、按需大字段、复制/下载和关联 Run。

调整规则：

- 项目观测台默认显示当前项目的业务调用；工作流和内部事件只有在能够可靠归属当前项目时才可通过类别筛选显示。
- 异常聚合键至少包含 `effective_project_id`，禁止跨项目合并同类错误。
- 调用详情、下载和关联 Run 跳转都要复核调用与 Run 属于当前项目。
- 历史调用没有直接项目字段时，可通过 `run_id → workflow_run`、`step_run_id → run`、`episode_id`、`shot_id` 或可信 meta 解析；解析冲突时进入“归属异常”，不进入任一项目。
- URL 只保存调用 ID 和非敏感筛选；请求、响应、错误全文和 prompt 不进入 URL。

## 10. 系统设置空间详细需求

### 10.1 系统总览

系统总览保留“总览”能力，但从“跨项目日志首页”改为“系统健康与跨项目聚合首页”。建议区块：

1. **系统健康**：后端、数据库、调度器、恢复任务、配置健康和最后成功同步时间。
2. **模型能力**：四类职责当前模型、连接就绪数和需要配置数量，进入模型中心。
3. **配置概况**：配置版本、运行时有效值、需重启项、历史非法配置告警，进入系统设置。
4. **制作运行聚合**：全部项目的运行中、待处理、异常、近期完成总数；只展示聚合。
5. **按项目摘要**：项目名及其运行中/待处理/异常数量；点击进入该项目观测台的对应筛选。
6. **归属健康**：无法可靠归属项目的 Run/Job/Call 数量和最近检测时间；只显示数据质量告警，不把原始记录放进任一项目。

原“最近任务”和“需要关注”逐条列表不再作为跨项目明细留在系统总览。它们改为按项目摘要并深链到项目观测台，既保留全局发现能力，又满足项目日志隔离。

### 10.2 模型中心

- 原模型分配、模型库 CRUD、搜索/分组、连接测试、凭证不回显和生效时机说明全部保留。
- 页面持续强调配置为全局能力：新任务使用新分配，运行中任务使用启动时快照。
- 不接受项目参数，也不显示“当前项目模型”；未来若要项目级模型覆盖必须另立配置模型和 PRD。

### 10.3 系统设置

- 原设置 schema、类型化控件、即时校验、规范化 diff、差异预览、版本冲突、一次批准、事务保存、requested/effective 和需重启语义全部保留。
- 设置页不轮询任何项目观测明细。
- 设置影响文案统一使用“所有项目”“后续新任务”或明确的系统范围，不再写“当前项目”。
- 离开保护覆盖系统子导航、返回项目、浏览器后退、刷新和关闭页面。

## 11. 数据归属与 API 合同

### 11.1 单一项目归属解析器

新增共享的逻辑服务 `resolve_effective_project_scope(object_type, object_id)`；名称可在技术设计中调整，但语义必须唯一。解析优先级：

1. 记录的权威直接 `project_id`。
2. `episode_id → episodes.project_id` 或 `shot_id → shots → episodes.project_id`。
3. `run_id → workflow_runs.scope_type/scope_id → project`。
4. `step_run_id → step_runs.run_id → workflow_run → project`。
5. 历史调用中经过白名单解析的 `meta.project_id`，且项目存在。
6. 无法解析则为 `unattributed`。

若多个来源给出不同项目，结果为 `conflict`，不得按优先级静默选一个。冲突应进入系统总览的归属健康指标并记录可排障关联 ID。

### 11.2 推荐的项目作用域接口

为降低旧消费者回归风险，首期新增薄的项目作用域 façade，内部复用现有查询/动作服务，不直接删除全局接口：

```text
GET  /projects/{project_id}/observability/runs
GET  /projects/{project_id}/observability/runs/{run_id}
GET  /projects/{project_id}/observability/runs/{run_id}/steps
GET  /projects/{project_id}/observability/runs/{run_id}/events
POST /projects/{project_id}/observability/runs/{run_id}/{cancel|resume|retry}
GET  /projects/{project_id}/observability/gates
GET  /projects/{project_id}/observability/artifacts/{artifact_id}
GET  /projects/{project_id}/observability/artifacts/{artifact_id}/evals
GET  /projects/{project_id}/observability/artifacts/{artifact_id}/lineage
POST /projects/{project_id}/observability/gates/{artifact_id}/decision

GET  /projects/{project_id}/observability/jobs
GET  /projects/{project_id}/observability/jobs/{job_id}
POST /projects/{project_id}/observability/jobs/{job_id}/{action}

GET  /projects/{project_id}/observability/calls
GET  /projects/{project_id}/observability/calls/{call_id}
GET  /projects/{project_id}/observability/calls/{call_id}/download
```

动作也可继续复用 Run 级动作，但项目 façade 必须先做范围校验、状态校验、幂等和审计，再调用同一领域函数。禁止复制取消/恢复/重试实现。

### 11.3 列表响应合同

```json
{
  "scope": {
    "kind": "project",
    "project_id": "proj_x",
    "project_name": "小说名",
    "scope_version": "obs-scope-v1"
  },
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 20,
  "page_count": 1,
  "counts": {},
  "aggregates": [],
  "server_time": 0
}
```

- `counts`/`aggregates` 只在适用接口返回，但一旦返回就必须与 `scope` 和筛选条件一致。
- 分页发生在归属解析与全部筛选之后。
- 搜索、排序、时间和状态口径继续沿用现有监制房合同。
- `scope_version` 用于灰度期比较新旧口径和定位历史数据归属变化。

### 11.4 历史数据与存储策略

- 阶段 1 不要求破坏性迁移；可先通过 SQL 投影/共享查询服务解析有效项目。
- 新写入的 Run、Job、Call 必须尽早携带可验证项目上下文；Call 至少在结构化 meta 中持久化项目 ID，并保留 Run/Step 关联。
- 若后续为性能增加可空的归属列或索引，只允许非破坏性迁移；回填必须可重复、可审计，冲突不覆盖原始值。
- 删除项目时继续沿用现有证据/Run/Call 清理链路；新增归属索引不得留下可被其他项目查询的孤儿记录。

### 11.5 读取与写入保护

- 详情、下载和动作不能因为用户知道 ID 就绕过项目路径作用域。
- 前端隐藏或禁用按钮不是保护；服务端必须再次验证项目、对象版本、状态和权限。
- 写操作使用现有幂等键/版本保护；作用域校验发生在任何写入和外部调用之前。
- 作用域错误不得触发自动重试、恢复、取消或费用相关操作。

目录名称为推荐方案，不是发布门槛；职责边界是门槛。

### 12.2 拆分顺序

1. 先从 `MonitorPage.tsx` 提取纯类型、标签、DataBoundary、分页、Run/Job/Call 面板、ModelCenter、SettingsPanel，保持旧 `/monitor` UI 和测试行为不变。
2. 为提取后的 Run/Job/Call 面板增加必填 `scope` 合同及项目作用域 API 适配器。
3. 新建 ProjectShell/SystemShell 和新路由，复用已经提取的面板。
4. 最后启用旧路由重定向并移除旧 MonitorPage 的页面编排；不在同一个提交中同时大改 CSS、API 和业务动作。

### 12.3 状态所有权

| 状态 | 唯一所有者 | 生命周期 |
|---|---|---|
| 项目目录、当前项目元信息 | `ProjectCatalogProvider` | 应用级；创建/删除后主动失效 |
| 当前路由/作用域 | 路由层 | URL 级；前进后退为权威输入 |
| 当前分集 | 项目路由/分集选择器 | 每项目独立；切项目必须重解析 |
| 观测筛选和选中对象 | 各观测子页 URL | 每个项目、每个子页独立 |
| 系统设置草稿 | `SystemSettingsPage` | 系统设置页内；受离开保护 |
| 模型编辑草稿 | `ModelCenterPage` | 模型中心内；不进入项目 Context |
| 侧栏折叠 | AppShell 展示偏好 | 可跨页面保留 |

### 12.4 请求隔离

- 所有项目请求的缓存键必须包含 `projectId` 和完整查询串。
- 页面切换使用 `AbortController` 或递增请求序列；旧响应只能更新发起它的作用域。
- `ProjectObservabilityPage` 不初始化 settings/health/catalog poller。
- `SystemShell` 不初始化 jobs/calls/runs poller；总览使用独立聚合接口，而非拉全量明细到前端聚合。
- API 层继续保持 GET 单飞，但不能让不同 scope 复用相同 key。

### 12.5 Agent 与全局组件

- 项目制作和项目观测路由向案头助手传递当前 `project_id`；系统设置和项目选择页传 `null`。
- 项目切换时新建/更新对话上下文，不允许助手沿用旧项目执行危险命令。
- 全局审批宿主、Toast、导航保护和助手抽屉仍由 AppShell 承载，避免在两个 Shell 中重复。
- 业务页面现有 `go('monitor')` 入口统一改为带当前项目的观测深链；有 `run_id` 时必须携带。

## 13. 关键交互与异常状态

### 13.1 项目目录加载失败

- 已有当前项目快照时保留页面并标记项目切换器“列表可能过期”；不清空当前工作。
- 无快照时显示可重试错误，不显示“尚无项目”。
- 当前项目详情仍可工作时，不因目录接口失败强制退出。

### 13.2 项目不存在或被删除

- 直接打开无效 `/projects/:id/...` 显示持久 404 状态，提供“返回项目空间”。
- 轮询期间项目被删除时停止项目请求、关闭项目抽屉、清除最后路由并进入 `/workspaces`。
- 不自动打开另一个项目。

### 13.3 观测对象失效

- Run/Job/Call 不存在、已清理或不属于当前项目时，不选中列表第一项。
- 保留筛选和列表，顶部展示持久错误；用户可关闭错误回到当前列表。
- 同页重复打开同一深链时滚入视野、聚焦并短暂高亮。

### 13.4 数据状态

继续沿用现有 `initial/loading → ready-data/ready-empty → refreshing → stale/error` 语义：

- 未知或失败不得显示 0、“无异常”或“暂无记录”。
- 有旧快照时刷新失败进入 stale，并显示最后成功时间。
- 项目切换后旧项目快照不能作为新项目 stale 快照展示。
- 会改变任务状态或产生费用的动作在 stale 下提交前强制重校验。

### 13.5 未保存内容

- 切项目、进入系统设置、返回项目、浏览器后退都走统一导航守卫。
- 守卫必须说明将放弃哪一个项目/系统区域的哪类草稿。
- 用户确认离开后才清理草稿；取消则 URL、选择器和页面状态保持原样。

## 14. 发布、迁移与回滚策略

### 14.1 功能开关

建议使用相互独立的开关：

| 开关 | 控制范围 | 关闭时行为 |
|---|---|---|
| `workspace_shell_v2` | 新产品名、空间切换器和项目侧栏 | 回到现有 App 侧栏和项目中心 |
| `project_observability_v1` | 项目观测台及作用域接口 | 回到现有全局 Monitor 兼容页和既有动作能力；页面不声称已实现项目隔离 |
| `system_shell_v1` | 独立系统设置空间 | 继续使用旧 Monitor 的 overview/models/settings |
| `legacy_monitor_redirect_v1` | 旧 `/monitor` 映射 | 关闭时旧链接保持原页 |

开关只控制界面和路由编排，不改变正在运行任务、设置有效值或数据库状态。

### 14.2 分阶段实施

| 阶段 | 内容 | 放行门槛 |
|---|---|---|
| 0：基线冻结 | 记录现有路由、监制房功能、接口口径和回归快照；补 A/B 项目隔离固定数据 | 现有测试全绿；所有旧入口清单有负责人 |
| 1：无行为拆组件 | 拆 MonitorPage 与共享组件，仍由旧页面编排 | UI、请求路径、写动作和快照等价；无新路由 |
| 2：后端项目作用域 | 建归属解析器和 scoped façade；列表/计数/聚合/详情/动作隔离 | 双项目 + 未归属 + 冲突数据测试全部通过 |
| 3：项目 Shell 与空间切换 | 上线产品名、项目切换器、创建/管理页和五菜单 | 创建、切换、删除、未保存保护、项目级路由通过 |
| 4：项目观测台 | 上线 Run/Job/Call 三子页；改业务深链 | 现有监制房 P0/P1 能力无回归；跨项目泄漏为 0 |
| 5：系统 Shell | 上线总览、模型中心、系统设置；不再加载项目明细 | 设置原子性、模型连接门槛、返回恢复通过 |
| 6：旧路由迁移 | 启用 `/monitor` 重定向和埋点；观察后删除旧编排 | 旧深链成功率达标；完成开关回滚演练 |

### 14.3 回滚

- 任何阶段回滚只切路由/界面开关，不回滚或删除 Run、Job、Call、设置版本和审计记录。
- scoped façade 是只读/动作前置保护层，可独立保留，即使 UI 回到旧页也不会影响生产任务。
- 新增可空字段或索引不得成为旧代码必填依赖。
- 系统设置链路异常时回到只读模式，不能回滚到允许非法值或部分写入的旧实现。
- 已受理异步任务继续执行并按权威状态恢复展示。

### 15.3 关键验收脚本

1. 在项目 A 的分镜台发起任务，从状态入口打开 Run，确认落到 A 的观测台并选中同一 Run。
2. 手工把 URL 中项目 A 改成项目 B，同时保留 A 的 Run ID；页面必须返回范围错误，不能展示 A 的详情。
3. 在 A 的任务队列记录列表数、状态计数和真实总数；数据库同时加入 B 任务后，A 的三个数均不变化。
4. 打开 A 的调用日志，再快速切 B；让 A 的慢请求最后返回，页面仍只能展示 B 数据。
5. 从 B 的调用详情跳关联 Run，目标必须仍在 B；伪造跨项目关联时跳转被阻断。
6. 修改系统设置但不保存，点击“返回项目”；取消后草稿和系统 URL 不变，确认后恢复离开前项目页面。
7. 从旧 `/monitor?section=runs&run_id=...` 打开，正确解析项目并迁移；未知 Run 不自动打开其他项目。

## 19. 实现记录与验证结论

本次实现采用“兼容外壳 + 强作用域门面”方案：为降低五个既有制作页面的回归风险，`App.tsx` 保留原 `Nav` 调用接口作为兼容门面，但路由解析已把项目观测与系统设置约束为互斥状态；页面装载、轮询生命周期和侧栏结构按 Project/System 两种 Shell 分支隔离。Monitor 内部既有成熟面板继续复用，通过 `mode` 和项目作用域适配器停止无关请求，避免为了物理拆文件重写已验证的详情、设置和动作逻辑。

新增后端 `app/observability/api.py` 作为唯一项目观测入口。Run、Job、Call、Artifact、Gate 的列表、汇总、详情、下载和动作在执行前统一反查项目；直接项目字段、Episode、Shot、Run、Step 归属冲突时一律视为不可归属，项目端点返回不泄露对象存在性的 404。批量查询预加载作用域映射，避免按调用记录产生 N+1 查询。

已完成的验证：

- `scripts/verify.py`：101 个后端高风险/回归用例、前端类型检查与 122 个前端用例全部通过。
- 新增 `tests/test_project_observability.py`：覆盖双项目列表、统计、Run-only 调用归属、冲突元数据、跨项目详情、门禁、动作分发前阻断、HTTP 合同和系统聚合无原始记录。
- 生产构建通过；`git diff --check` 无空白错误。
- 真实浏览器完成桌面和 390px 验收：项目选择/搜索、五个制作菜单、观测三页、系统三页、设置折叠表单、调用详情抽屉、旧 Run/Call/Settings 深链、移动侧栏均通过；页面横向溢出为 0，控制台新增 error/warning 为 0。
