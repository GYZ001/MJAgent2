## 2. 整改背景与现状结论

评审墙已具备分集/镜头切换、文字/参考图/视频审阅、QA/费用/状态查看、生成/停止/采用/导出/清空、陈旧资产修复和 Supervisor 补齐等完整能力，但综合体验仅为 **2.8/5**。当前形态更接近后台能力控制台，尚不足以承担高频、低误差的连续评审。

关键扫描证据如下：

- 第 1 集处于 `scripting` 时，镜头数在扫描过程中由 5 变 4；页面用数组下标保存选择，用户从第 5 镜被静默切到第 4 镜，后续采用、重生、废弃或清空可能作用于错误对象。
- 远端第 1646 集搜索可用，但该集为 `planned` 且 0 镜，页面主体完全空白；无视频时曾提示“请使用下方按钮”，实际没有按钮。
- 切换镜头强制回到“文字内容”；问题镜头无筛选、上一/下一问题镜、批注、负责人或评审完成标记。
- 视频“对比”只有单播放器切换，无法同步 A/B；改词重生、恢复参考图和 Supervisor 授权依赖浏览器 `prompt/confirm`。
- 授权值通过 `Number(value) || default` 解析，`0` 会被默认值替代，负数会保留；服务端未完整校验正数、合理上限和有限数。
- `scripting` 期间仍能清空本镜/本集；清空只停止视频 Supervisor，不会停止正在写分镜的上游任务，存在写入竞争。
- 单镜详情失败只显示约 3.2 秒 Toast，随后摘要被当作详情，可能把接口错误伪装成“无参考图/无版本”。
- Supervisor 轮询失败静默保留旧快照；运行提醒在桌面视口遮挡内容；手机下固定约 480px 播放器与至少 520px 评审区造成大量滚动。
- 已有能力必须保留：侧栏入口清晰；上一/下一集与上一/下一镜首尾禁用正确；1646 集搜索可命中；参考图三类分组清楚；采用理由留审计；停止任务能说明供应商可能继续执行和计费；导出入口直接；遗留任务“预演→确认”模式较稳健。

整改后的定位是“对象稳定、状态可信、风险可控、适合连续评审的工作台”。先保证用户不会看错镜头、不会进入死路、不会错误授权或误清空，再增强 A/B、批注与问题队列。

## 3. 目标与量化成功指标

| 目标 | 发布成功指标 |
|---|---|
| 保证评审对象稳定 | 后台刷新后当前 `shotId` 保持率 100%；原镜删除时操作区冻结并明确提示，静默切换率为 0 |
| 消除流程死路 | 零镜头、未确认、无参考图、无视频、详情失败等所有空/错态均包含原因、当前状态和至少一个合法下一步；虚假 CTA 数为 0 |
| 降低连续评审成本 | 评审 20 镜时，每镜平均额外点击次数相对整改前基线降低至少 40%；切镜保持标签成功率 100% |
| 控制费用与长任务风险 | 所有预算/时间授权通过前后端 `min/max/finite` 及依赖校验；非法授权接受率为 0；不可恢复动作只出现一次权威影响确认 |
| 保证数据可信 | 详情请求失败时显示为“无素材”的比例为 0；Supervisor 连续两次轮询失败后过期标识覆盖率 100%，控制动作进入保护态 |
| 提升版本判断质量 | A/B 模式可完成同步播放、同帧暂停、循环区间、QA 差异和明确对象的一键采用；采用/删除/导出错版本率为 0 |
| 提升可访问性 | 仅键盘可完成镜头/标签切换、图片/版本预览、采用和关闭弹窗；阻断级可访问性问题为 0 |
| 保持现有高分能力 | 侧栏入口、首尾禁用、远端集搜索、参考图三分组、采用审计、停止风险说明、导出和遗留任务预演能力回归通过率 100% |
| 建立自动化保护 | 报告全部 P1 风险具备端到端用例；本 PRD 全部 P0/P1 发布前通过率 100%，既有相关前端 12 项和后端 45 项测试持续通过 |

“点击降低 40%”需在灰度前以同一任务脚本采集整改前基线；不得用估计值替代实测。

## 4. 范围与非范围

### 4.1 本期范围

- 分集入口、上/下一集、远端搜索、制作/评审状态筛选与上次位置恢复。
- 镜头状态轨、稳定选中、上/下一镜、问题镜筛选、跨镜标签保持和评审任务记录。
- 文字/连续性信息、参考图、Lightbox、废弃/恢复、原因与血缘。
- 视频播放器、真正 A/B、版本列表/采用/导出/删除、统一新建版本向导和停止任务。
- 全集快速生成、补齐到全片、预算/时间授权、Supervisor 面板与控制。
- 陈旧资产影响预览、选择性修复、清空本镜/本集及上游任务竞态保护。
- 加载/空态/错误/自动刷新/Toast、运行提醒布局、键盘/读屏和窄屏适配。
- 对应数据/API/任务契约、埋点、监控、组件测试、端到端测试和回滚。

### 4.2 非范围

- 更换视频/图像供应商或重写生成、QA、连续性算法。
- 重新定义剧本台、分镜台的内容生产流程；仅建立合法前置跳转和并发保护。
- 自动替用户完成主观评审、采用或删除决策。
- 迁移/删除全部历史媒体版本；本期提供逐版本管理和可选归档能力。
- 在 PRD 中确定未评审的具体接口路径、数据库表、锁实现或预算上下限数值；这些需由业务、财务和技术共同配置并版本化。

## 6. 目标用户流程

### 6.1 进入并连续评审

1. 用户从侧栏进入评审墙：从未保存过镜头身份时进入明确默认位置；若已保存的 `shotId` 仍存在且有权限则恢复；若该身份已删除或失权，则进入墓碑/冻结态并要求用户显式选镜，不自动回退到其他镜头。
2. 用户通过远端搜索或制作/评审状态筛选找到目标集；集级状态显示中文含义和下一步。
3. 镜头轨显示状态、问题和未评审标记；用户选择“只看问题/待采纳/失败”等集合。
4. 用户选择一个镜头和评审标签后，用按钮或快捷键连续切镜；标签保持，选中对象始终由 `shotId` 确定。
5. 用户添加锚定批注、问题类型、负责人和处理状态，并在满足规则时标记本镜评审完成。
6. 后台刷新若只更新同一镜内容，页面提示差异；若原镜删除，冻结写操作并让用户主动选下一镜，绝不静默替换。

### 6.2 A/B 对比与采用

1. 用户从版本列表选定 A、B 两个明确 versionId；两播放器显示镜号、版本、状态和 QA。
2. 用户同步播放、同帧暂停、逐帧、设置循环区间并查看 QA 差异。
3. 点击采用时，结构化确认展示将采用版本、当前采用版、理由、依赖影响和费用（如有），只确认一次。
4. 服务端重新校验 shotId、versionId、对象版本和权限；成功后更新采用状态、版本列表、审计和评审项。
5. 若版本在确认期间变化/删除，提交被冲突拒绝，A/B 选择保留并提示刷新，不可采用另一版本。

### 6.3 新建视频版本

1. 用户从统一向导选择“按原词新建候选 / 修改提示词 / 带评语修复”。
2. 向导展示输入差异、带入评语、模型约束、估算费用、预计影响和旧采用版保留策略。
3. 前端校验后进入一次权威影响确认；服务端再次校验并创建异步任务。
4. 页面展示任务标识、排队/运行阶段、可取消窗口和终态；“请求已接受”不等于“视频已生成”。

### 6.4 Supervisor 补齐与控制

1. 用户打开单个结构化授权弹窗，填写预算、时间墙及是否允许改分镜；字段单位、范围、默认值和估算清楚可见。
2. 预演返回影响镜头数、预计费用/时长和前置条件；用户一次确认后签发授权并启动。
3. 面板展示最后同步时间；连续两次轮询失败后标“数据已过期”，所有控制动作进入保护态，先刷新/重校验。
4. 暂停、转人工显示接受与实际生效阶段；取消、追加预算展示旧值、新值和最终影响并一次确认。

### 6.5 清空与陈旧资产修复

1. 用户先查看只读预演：目标镜头/版本、上游活动任务、引用、人物/场景差异、估算费用与可回滚资产。
2. 陈旧修复可逐镜勾选；清空若存在活动编剧/分镜任务，则禁用直接清空或提供“停止上游并清空”的统一原子方案。
3. 用户确认引用同一预演版本；服务端发现状态变化时要求重新预演。
4. 修复期间保留旧采用版直到新版本成功；清空/停止失败不得留下半清空状态。

## 8. 状态与交互规则

### 8.1 分集、镜头与详情状态

| 状态 | 页面规则 | 写操作规则 |
|---|---|---|
| 分集加载中 | 保留导航骨架，不显示 0 镜业务空态 | 禁止依赖分集详情的生产动作 |
| 已加载且 0 镜 | 显示原因/前置/去剧本台或分镜台 CTA，隐藏清空 | 只开放合法跳转/刷新 |
| 上游资格未知/未确认/运行中/已失效 | 展示发布剧本、确认分镜版本、活动 Run 和阻断原因；不伪装成无素材 | 禁止生成/重生、恢复参考输入、采用、Supervisor 启动/补齐和陈旧修复等正向生产动作；允许查看/刷新、停止或取消既有任务、废弃/隔离输入、去上游处理，以及通过专用预演执行原子“停止上游并清空” |
| 人物/场景资产硬失败或未验证 | 在参考输入和受影响镜头上展示门禁原因、资产/规则版本和修复入口；历史视频标风险 | 禁止新选择、恢复为输入、生成/重生与采用；软警告可继续但必须透传；硬失败/未验证不可绕过 |
| 镜头详情加载中 | 显示目标镜号和详情骨架，不复用上一镜内容 | 依赖详情的动作禁用并说明 |
| 镜头详情错误 | 持久错误卡、关联 ID、重试；摘要标“非完整” | 采用、生成、废弃、恢复、清空等禁用 |
| 已就绪 | 显示详情版本和最后更新时间 | 提交携带 shotId 与对象版本 |
| 已更新 | 保留用户位置，展示变更摘要；有草稿时提供比较 | 未确认新版本前，可能冲突的动作需重校验 |
| 原镜已删除/无权限 | 冻结内容和操作，明确原因，要求用户主动选新镜 | 任何写请求不得重新指向其他镜 |

### 8.2 对象一致性规则

- 镜头、参考图、视频版本、任务、Supervisor 均以稳定 ID 作为选择和写操作主键；数组下标、当前播放器位置和 DOM 顺序不得作为业务对象身份。
- 每个确认弹窗必须重复展示项目/集/镜/版本（适用时），提交携带打开弹窗时的对象版本或等价并发令牌。
- 列表刷新只能按 ID 合并；对象消失时不自动选择相邻对象执行原动作。
- A/B 两侧、当前采用版和拟采用版是三个独立概念，视觉标签和请求参数必须一致。

### 8.3 风险交互等级

| 等级 | 示例 | 规则 |
|---|---|---|
| L1 可逆低风险 | 切换筛选、预览、可立即恢复的废弃 | 直接执行并提供 Undo/恢复，不弹多余确认 |
| L2 有业务影响但可恢复 | 评审完成、归档候选、暂停 | 结构化摘要；必要时一次确认；明确恢复方式 |
| L3 不可恢复/费用/终止长任务 | 全集生成、采用替换、删除、清空、Supervisor 取消/追加授权 | 只读预演 + 一次权威确认；服务端重校验版本、权限和影响；完整审计 |

禁止用浏览器原生 `prompt/confirm` 承担 L2/L3 生产决策。

### 8.4 反馈规则

- 低风险成功可用短 Toast；关键失败、并发冲突、数据过期和详情错误必须留在相关区域，直到用户处理或明确关闭。
- “已提交/已接受”与“已完成”必须使用不同文案和状态；异步任务展示可追踪标识与阶段。
- 禁用按钮提供可读取原因和下一步；文案不得引用当前不可见/不可执行的按钮。
- 自动刷新只更新数据，不夺取焦点、不改变 tab、不滚动页面、不静默覆盖草稿。

## 9. 数据、API 与任务要求

以下仅定义语义要求，具体接口名称由技术设计确认。

### 9.1 查询与对象版本

- 分集查询支持远端关键词、制作状态、评审状态、有无镜头/视频等过滤，返回稳定 episodeId、显示信息和状态口径。
- 上游资格快照至少包含发布剧本 Artifact/版本、当前确认分镜 Artifact/版本、确认与整集门禁、活动编剧/分镜 Run、资格版本和服务端时间；空态、工具栏与所有写操作使用同一快照。
- 镜头列表摘要与单镜详情分离；二者均携带 shotId、数据版本/更新时间和详情完整性标记，禁止客户端把摘要当完整详情。
- 参考图包含稳定 refId、用途分组、来源人物/场景资产 ID 与版本、QA、硬门禁结论、规则/评估版本、下游资格、软警告、一级原因/技术码、风险级别和视频版本引用关系。
- 视频版本包含稳定 versionId、shotId、状态、QA、费用/延迟（若可得）、输入版本、采用关系和可执行动作条件。
- Supervisor 快照包含稳定 supervisorId、状态版本、服务端时间、最后更新时间、预算/覆盖/等级/策略/问题镜及控制能力。

### 9.2 写操作并发与幂等

- 采用、废弃/恢复、评审项、生成、停止、授权、Supervisor 控制、修复、删除/归档和清空均携带稳定目标 ID、预期对象版本、操作者权限上下文及幂等键或等价去重机制。
- 服务端先对全部写操作校验稳定目标 ID、预期对象/任务版本、操作者权限、命令状态合法性和幂等键；冲突返回最新可显示状态，不自动重试写操作。
- 正向生产动作——生成/重生、恢复为可用参考、采用、Supervisor 启动/补齐、陈旧修复——还必须校验发布剧本与确认分镜仍是预演版本、无阻断上游 Run、人物/场景输入仍具下游资格、预算/时间有效；任一资格未知、失败或过期均 fail-closed 拒绝。
- 安全止损/隔离动作——停止或取消既有任务、废弃/隔离不合格输入、归档/删除，以及经专用预演的“停止上游并清空”——只校验目标身份、权限、最新任务/对象版本、影响范围和该动作所需的预演/锁，不要求上游仍已确认或资产仍合格；它们不得创建/恢复新生产输入、候选或采用关系。清空另须满足 REV-CLEAR-001 的原子性约束。
- 异步任务响应至少表达已接受/拒绝、任务标识、当前阶段、是否可取消和关联对象；终态通过现有轮询/推送能力更新。
- 视频任务创建时固定发布剧本、确认分镜、人物/场景资产及规则版本的完整依赖快照；后台每次写候选、QA、版本关系或采用关系前均复核快照与失效栅栏。过期 Run 仅可写陈旧/失败证据，不能成为当前候选或采用版。
- 采用/删除/清空等操作需写不可抵赖审计：目标 ID、旧/新状态、理由、影响摘要、预演版本、操作者、时间和关联请求 ID。

### 9.3 授权与影响预演

- 预算/时间约束由服务端权威配置提供：类型、单位、默认、min/max、步长、finite 要求和依赖；前端不得硬编码作为唯一来源。
- 授权请求使用类型化模型而非任意字典语义；服务端拒绝 NaN、Infinity、非法 0、负数、越界值和未知字段。
- L3 操作先生成只读影响预演，包含目标集合、发布剧本/确认分镜、人物/场景资格、上游任务、费用/时间估算、可恢复性和预演版本；确认必须引用该版本。
- 预演后任一关键对象版本改变，执行被拒绝并要求重新预演。

### 9.4 清空与修复任务

- 清空前服务端检查活动编剧、分镜、视频生成/Supervisor 任务及媒体引用；需要组合“停止上游+清空”时必须以状态机/锁实现整体成功或整体不执行。
- 陈旧资产修复按用户选择的 shotId 集合执行；每镜保留旧采用版直至新版本成功，返回逐镜结果并支持失败镜重试。
- 失败、取消或回滚不得留下悬空引用、半删除版本或 UI 不可解释的中间状态。

### 9.5 安全与费用

- 费用只展示后端可提供的估算和置信/更新时间，不承诺供应商无法保证的最终值。
- 评审批注、提示词和媒体 URL 按项目权限返回；下载/导出沿用访问控制和审计。
- URL、埋点和普通日志不记录完整提示词、批注正文、签名媒体地址或授权敏感值。

### 12.3 发布与回滚

- 稳定选中、详情状态、授权弹窗、风险预演、A/B、评审工作流、布局分别使用独立功能开关，按内部角色→小项目→全量灰度。
- 数据契约先向后兼容发布；前端稳定后再删除 idx 依赖或旧字段。回滚前端时，服务端仍需拒绝非法授权和并发清空，安全修复不可回滚。
- REV-UPSTREAM-001、REV-ASSET-001 及视频 Run 逐写入依赖栅栏是服务端不可回滚的安全底线；资格服务、快照或栅栏异常时，全部新生产写入保持 fail-closed 只读，只保留查看及按最新目标版本执行的安全停止/取消/隔离，不得回退旧写路径。
- 若 selectedShotId 新逻辑异常，回滚到只读镜头详情并要求用户重新选择；禁止回退到可写的 idx 选择。
- 若授权/预演链路异常，Supervisor 新启动、追加预算和 L3 动作切只读；已有任务继续展示/安全停止，不恢复浏览器 prompt/confirm。
- 若 A/B 性能异常，可关闭双播放器并回到带明确 A/B 快照的交替比较；版本 ID 和采用确认保持新逻辑。
- 回滚不得删除评审批注、审计、授权记录或已创建任务；陈旧修复/生成中的任务继续按权威状态收口。
