## 2. 整改背景与现状结论

监制房已集中运行、任务、模型、调用日志、并发和预算设置，基础搜索、状态筛选及分页可用，但综合体验仅为 **5.2/10**。核心矛盾是：页面能展示大量技术信息，却不能稳定回答“真正卡在哪里、下一步做什么、如何直接到达处理对象”。

本次整改必须正视以下扫描证据：

- 首次加载曾短暂显示全 0；接口失败也可能被渲染成“无任务/无异常”，未知状态被伪装为正常状态。
- 账本约有 361 条运行/历史任务，而任务页和调用日志页均只可访问最近 200 条；运行中心只展示最近 50 次运行。
- 人工门禁有 9 项，但证据需要两次同义点击才能打开，且没有批准、打回或跳转编辑等闭环动作。
- 任务错误文案出现“可点击重试”，页面却没有重试入口；运行提醒的“查看详情”不携带 Run 上下文。
- 将“视频提交并发”从 `20` 改成 `abc` 时无即时校验且仍可保存；改回 `20` 后仍显示有改动。非法值可能落库，而运行时静默回退默认值。
- 设置目前逐项写入后再热更新；热更新 warning 未被前端展示，存在页面宣称成功但运行时未生效、甚至部分写入的风险。
- 调用详情可把数万字符请求直接铺在表格中，并暴露本机绝对路径；缺少摘要、遮罩、复制、下载和键盘操作。
- 已有保护应保留：六个子区域命名和位置清晰；任务搜索、状态筛选、分页可用；模型连接保存前要求连接测试通过；API Key 使用密码输入且不回显。

整改后的产品定位是“异常与待办优先的监制工作台”：默认层服务监制决策，技术详情作为二级排障信息；任何未知、失败或过期数据都不得被伪装成空数据或正常状态。

以下指标均为发布门槛；若当前基线无法通过现有埋点获得，必须在灰度前先补齐基线采集，不得虚构基线。

| 目标 | 成功指标 |
|---|---|
| 消除状态误判 | jobs、calls、settings、health、model catalog 五类数据块在未知/加载/失败时误显示为 0 或“无异常”的比例为 0；错误态和过期态展示覆盖率 100% |
| 形成异常处理闭环 | 总览异常、任务、人工门禁和运行提醒均能在不丢失对象上下文的情况下到达详情或主处理动作；抽样链路到达率 100% |
| 保证配置正确性 | 非法类型、非法枚举、非有限数、越界值和依赖冲突的前后端拦截率 100%；配置保存无部分写入；页面展示值与运行时有效值一致率 100% |
| 提升定位效率 | 任一任务、运行提醒和可定位的异常均可用统一深链打开目标 Run；刷新、前进后退后 section、筛选和选中对象恢复率 100% |

| 保持现有能力 | 原有任务搜索、状态筛选、每页数量、上下页、模型连接测试门槛和密钥不回显能力回归通过率 100% |

## 4. 范围与非范围

### 4.1 本期范围

- 监制房子导航 URL 化、筛选/选中对象恢复和统一 Run 深链。
- 总览的数据状态、指标下钻、异常聚合、最近任务定位和配置概况。
- 运行中心列表、步骤、事件、人工门禁、证据、异步切换和待办动作。
- 任务列表详情、处理动作、全量查询、组合筛选和真实总数。
- 模型分配、模型库查找与连接入口的上下文、文案和无障碍增强。
- 调用日志分类、友好名称、异常聚合、详情抽屉、敏感数据遮罩和大内容加载。
- 系统设置 schema、前后端校验、差异预览、事务保存、运行时生效结果和脏状态。
- 全局运行提醒的上下文深链与可见反馈。
- 对应埋点、监控、权限、幂等、组件测试及端到端测试。

### 4.2 非范围

- 重写现有工作流引擎、模型供应商协议或媒体生成算法。
- 改变剧本台、分镜台、评审墙的业务编辑规则；本期仅建立带上下文跳转。
- 清洗或重算历史任务、历史调用的业务结果；历史数据只做可查询、可解释和遮罩。
- 在需求阶段指定数据库表、缓存产品或未确认的具体接口路径。
- 取消既有权限审批、连接测试或审计要求；整改只能增强保护，不能绕过。

## 6. 目标用户流程

### 6.1 异常发现与处理

1. 用户进入监制房；每个数据块独立显示加载状态，已有成功快照则标注最后同步时间。
2. 总览按“正在运行、待我处理、系统异常、近期完成”呈现；任何错误或过期状态均显式展示。
3. 用户点击指标或聚合异常，系统清除冲突筛选并携带来源、对象 ID 和目标筛选进入对应列表。
4. 目标任务/Run/门禁自动选中；页面先给业务影响和建议主操作，再提供折叠的技术详情。
5. 用户执行重试、恢复、批准、打回、取消或去源页面；系统先校验权限与当前状态，必要时展示一次权威影响确认。
6. 提交期间锁定同一动作，完成后刷新受影响对象、总览计数和审计事件；失败则保留上下文和重试入口。

### 6.2 从运行提醒定位 Run

1. 用户点击运行提醒“查看详情”。
2. 系统生成统一深链（语义参考报告中的 `/monitor?section=runs&run_id=...`），切换到运行中心并选中目标 Run。
3. 若用户已在目标页面，目标行滚入视野并短暂高亮/聚焦，避免“点击无反应”。
4. 若 Run 已不在当前列表，按 ID 独立加载详情；不存在或无权限时展示持久错误及返回入口，不静默选择其他 Run。

### 6.3 系统设置变更

1. 页面加载设置值及 schema，字段按类型渲染，显示单位、允许范围、默认值、生效方式与依赖说明。
2. 用户编辑时立即得到字段级校验；规范化后的值若等于服务端基线，自动从改动集中移除。
3. 只有所有字段和跨字段依赖均合法时才能进入差异预览；预览显示旧值、新值、影响范围和是否即时生效。
4. 用户完成既有全局批准后提交；服务端再次校验完整变更集并在事务内写入。
5. 所有声明即时生效的字段成功应用后才返回整体成功；任何失败均不留下部分写入。声明需重启生效的字段以预先约定状态展示，不得伪称即时生效。
6. 页面展示权威结果、配置版本和运行时有效值；失败时保留草稿、定位字段并允许修正后重试。

### 6.4 技术排障

1. 研发/运维从业务异常进入调用日志，默认按业务模型调用过滤，内部指标事件在次级类别。
2. 列表先显示调用目的、模型友好名、耗时、错误阶段、重试关系和下一步动作。
3. 打开详情后才按需加载请求、响应和元信息；敏感字段默认遮罩，技术人员按权限查看/复制/下载已审计内容。

## 8. 状态与交互规则

### 8.1 数据块状态机

| 当前状态 | 展示规则 | 可用动作 | 转移规则 |
|---|---|---|---|
| initial/loading（无快照） | 骨架与“正在加载”，不显示 0、0/0 或“无异常” | 取消导航不受限 | 成功→ready；失败→error |
| refreshing（有快照） | 保留快照，显示轻量刷新和最后成功时间 | 只读与安全跳转可用 | 成功→ready；失败→stale |
| ready-data | 展示数据与更新时间 | 按权限开放动作 | 轮询→refreshing；条件变化可到 ready-empty |
| ready-empty | 明确说明查询口径和“确实无结果”，提供清筛选/下一步 | 清筛选、刷新 | 轮询或筛选变化后重新查询 |
| error（无快照） | 持久错误、错误类别、重试，不展示假数据 | 重试、返回 | 重试成功→ready；失败保持 error |
| stale（有旧快照） | 显著标“数据可能过期”和最后成功时间 | 允许查看；会造成状态变更的控制动作进入保护态或提交前强制重校验 | 成功刷新→ready；继续失败保持 stale |

### 8.2 动作状态与风险等级

- 所有写操作采用 `idle → validating → confirming（需要时）→ submitting → succeeded/failed/conflict`，提交时同一对象同一动作不可重复触发。
- 可撤销且低影响的界面操作可用 Undo；不可恢复、会产生费用或终止长任务的操作只使用一次权威影响确认，不叠加浏览器确认。
- 服务端必须再次校验权限、对象版本和状态；前端禁用不是安全边界。
- 冲突返回最新对象状态，保留用户上下文，不自动重复写操作。
- 成功反馈必须包含“处理了哪个对象、结果是什么”；失败反馈必须持久可见并提供修复/重试入口。

### 8.3 友好文案与技术详情

- 工作流、步骤、状态、模型均优先展示业务名称；原始枚举/ID 置于“技术详情”。
- 未映射枚举使用统一安全回退，不用通用拆词制造似是而非的中文。
- blocker 和错误先展示业务后果、建议动作、错误阶段，再展示 JSON、Hash、Contract、血缘和原始错误。
- 所有“暂无”文案必须来自成功的空查询；加载、错误、无权限和过期不得使用“暂无”。

## 9. 数据、API 与任务要求

本节定义语义契约，不指定未确认的具体接口名。

### 9.1 查询契约

- jobs、runs、calls 的对应现有查询能力需支持服务端 `page/page_size` 或等价游标、搜索、排序及本 PRD列出的组合筛选，并返回真实 `total` 或等价总量信息。
- 每条可定位记录必须提供稳定业务 ID；任务与调用若能关联 Run、项目、集、镜，应返回这些关联标识及可显示名称。
- 汇总卡片和下钻列表使用相同统计口径/状态映射版本，避免卡片数与结果集定义不同。
- 轮询数据包含服务端时间、最后更新时间或可比较版本；客户端用其判断 stale 和缓存失效。
- Run 步骤、事件和门禁证据必须按稳定 ID 请求；客户端需可取消旧请求或忽略不匹配当前选中 ID 的响应。

### 9.2 写操作与任务契约

- 重试、恢复、取消、门禁决策等动作需具备权限校验、状态前置条件、幂等键或等价去重机制、对象版本冲突保护和审计记录。
- 响应至少表达：目标对象、接受/拒绝、最新状态、是否异步、可定位的后续任务标识（若产生）、用户可理解错误和技术关联 ID。
- 对异步动作，页面展示已接受、排队/运行/终态，不把“请求已接收”表述为“任务已成功完成”。
- 任务状态变化后，总览、列表、详情和运行提醒使用同一权威状态映射。

### 9.3 设置契约

- 设置读取需同时提供当前持久值、当前运行时有效值、配置版本和字段 schema；敏感设置只返回是否已配置，不返回明文。
- 设置提交携带基线版本和完整 patch；服务端先校验所有字段与依赖，再进入事务与运行时应用。
- 成功结果逐项返回 requested/effective、生效方式和新版本；失败返回字段级错误并保证无部分写入。
- 禁止读取层静默吞掉非法持久值并回退默认值；检测到历史非法值时需显式健康告警并阻止其被误认为有效配置。

### 9.4 安全与数据最小化

- 调用详情对本机路径、凭证/令牌形态字段、密钥、可能含个人或项目敏感内容的输入采用服务端优先遮罩；前端遮罩不能作为唯一保护。
- 原文查看、复制和下载按角色授权并写审计，导出文件沿用遮罩与留存策略。
- URL 不放置密钥、原始错误全文、prompt 或其他敏感内容，只放稳定标识和非敏感筛选。

## 10. 埋点与可观测性

事件名为逻辑名称，可按项目既有规范映射；不得因命名调整削弱采集字段。

| 观测主题 | 逻辑事件/指标 | 必要维度 | 告警/用途 |
|---|---|---|---|
| 数据可信度 | 数据块加载结果、stale 进入/恢复、最后成功同步间隔 | block 类型、结果、错误类别、重试次数、是否有快照 | 数据块连续失败；任何未知→正常空态的非法转移 |
| 下钻定位 | 总览下钻、深链打开、目标定位成功/失败 | 来源、目标类型、目标 ID 哈希、筛选口径、失败原因 | 定位失败率、旧链接失效率 |
| 异常闭环 | 任务/门禁动作展示、点击、确认、接受、终态 | 动作、对象状态、权限结果、耗时、冲突/失败类别 | 动作接受后长期无终态；重复提交 |
| 设置安全 | 字段校验失败、预览、批准、提交、回滚/冲突 | 字段类别（不含敏感值）、错误类型、版本、生效方式 | 部分写入必须为 0；requested/effective 不一致告警 |
| 查询规模 | jobs/runs/calls 查询耗时、总量、页大小、取消旧请求 | 查询类型、筛选数、页大小、响应大小 | P95/P99 延迟和错误率；深页异常 |
| 调用详情 | 摘要打开、大字段加载、复制/下载、遮罩命中 | 内容级别、大小桶、权限、耗时 | 未授权原文访问；超大载荷阻塞 |
| 可用性 | 键盘操作完成、无障碍错误、前端异常 | 页面区块、版本、视口 | 阻断级 a11y/JS 错误回归 |

日志和追踪必须携带请求关联 ID、对象 ID（按安全规范处理）和配置版本；任何密钥、完整 prompt、响应正文不得进入常规应用日志。

## 12. 实施阶段、风险与回滚

### 12.1 实施阶段

| 阶段 | 交付内容 | 放行门槛 |
|---|---|---|
| 阶段 0：契约与基线 | 状态枚举、统计口径、设置 schema、权限矩阵、埋点基线、固定验收数据；新旧 UI 双读校验但不改写 | 产品/前后端/测试/安全共同确认；不存在未定义 P0 字段 |
| 阶段 1：P0 信任修复 | 显式加载/错误/stale；设置校验、原子保存、脏状态；统一 Run 深链 | 全部 P0 自动化与故障注入通过；配置部分写入为 0 |
| 阶段 2：P1 闭环 | 总览下钻、异常聚合、运行待办、任务动作、门禁决策、调用分类、模型上下文 | P1 端到端通过；动作权限/幂等/审计通过 |
| 阶段 3：P2 规模化 | 服务端全量查询、URL 全状态、异步防串线、证据缓存、日志抽屉、模型查找、无障碍 | 超量数据、性能、键盘/读屏和回归验收通过 |
| 阶段 4：灰度与收口 | 角色灰度、指标对比、告警值校准、旧查询/旧 UI 下线 | 连续观察期内无 P0，定位和动作失败率达标；完成回滚演练 |

### 12.2 主要风险与缓解

| 风险 | 缓解措施 |
|---|---|
| 新旧统计口径导致总览与列表短期不一致 | 口径版本化；灰度期双算对比；只有差异解释清楚后切主 |
| 服务端分页改变现有客户端筛选行为 | 保留兼容适配层；用固定 200+ 数据集做等价回归；分模块开关 |
| 新增任务动作扩大误操作面 | 权限矩阵、状态机前置校验、一次影响确认、幂等和完整审计；默认只读灰度 |
| 设置原子保存与运行时热更新难以一致 | 阶段 0 明确支持原子应用的字段；不能原子热更的字段明确标为需重启，不伪装即时生效 |
| 遮罩误伤排障信息或漏掉新字段 | 服务端结构化遮罩 + 模式兜底；安全回归数据集；受控原文访问审计 |
| URL 参数兼容旧链接 | 对合法旧链接做默认映射；未知参数忽略并提示；不把错误参数写回 |

### 12.3 发布与回滚规则

- 总览状态、任务查询、运行中心、日志详情和设置编辑分别受独立功能开关控制，支持按角色/环境灰度。
- 数据契约先向后兼容发布，前端切换稳定后再移除旧字段；禁止同一发布同时不可逆修改接口与存储。
- 若新查询异常，可回滚到旧查询，但页面必须明确标注“仅最近 N 条”，不得恢复为伪全量文案。
- 若新设置保存链路异常，立即切换为只读并保留旧运行时配置；禁止回退到允许自由文本非法落库的旧写链路。
- 回滚不得删除新审计记录、配置版本或任务动作结果；已接受的异步任务继续按权威状态展示。
