# EP-06 企业部署、运维与安全基线

> 优先级 P1（R1 之后紧接着做）｜ 依赖：无
> 一句话：让客户自己的运维团队敢接手——有交付物、有备份恢复演练、有指标、有审计导出、有授权控制。

---

## 1. 现状事实

- 依赖只有 6 个（fastapi/uvicorn/httpx/pydantic/python-multipart/Pillow），**这是优点**，交付面极小。
- 无 Dockerfile、无 compose；部署靠 `scripts/deploy_to_b.sh` + systemd（`mjagent2-backend`）+ A→B 反向 SSH 隧道（`docs/deploy-two-servers.md`）。
- 数据：SQLite 单文件、62 张表、手写 `MIGRATIONS`（~150 条 ALTER，靠吞 "duplicate column name" 幂等），无 Alembic。
- 备份：`scripts/backup_manju_db.py` 有；**恢复演练脚本没有**。
- 健康：`GET /api/system/health` 有（含模型可用性）；**无 Prometheus 指标端点**。
- 审计：`operation_audit` 365 天保留；**无导出、无外送**。
- 前端发布：`scripts/publish_frontend.py` 有版本偏斜闸门（拦「后端启动时间早于最新 `app/**/*.py`」），这是好机制，企业交付要保留。

## 2. 目标与非目标

**P0（本单元内的最小集）**
1. **一键交付物**：Dockerfile + compose（应用 + nginx），配置全部外置为环境变量/挂载卷；同时保留 systemd 路径不废弃。
2. **备份与恢复演练**：`scripts/restore_drill.py`——从备份恢复到临时目录并跑一组只读断言，输出 RPO/RTO 实测值。
3. **指标端点** `GET /metrics`（Prometheus 文本格式，**手写零依赖**）：请求量/延迟分位、任务队列深度、模型健康、配额水位、DB 写锁等待。
4. **审计导出**：按时间/用户/事件筛选导出 CSV/JSON（管理员）。
5. **安装自检** `scripts/preflight.py`：磁盘、权限、时钟、模型连通性、密钥文件权限、端口占用，一次跑完出报告。

**P1**：SIEM webhook 推送、许可证（席位 + 到期）、灰度升级与回滚脚本、离线安装包（无外网环境）。
**R3**：PostgreSQL。
**非目标**：Kubernetes/Helm、多可用区、自建监控系统（对接客户已有的 Prometheus/Grafana 即可）。

## 3. 交付物形态

```
docker-compose.yml
  app       : uvicorn app.main:app（挂载 data/ projects/ logs/ 与 master.key）
  nginx     : 复用现有 snippet（/media 长缓存 private、SPA、反代）
.env.example  : 全部可配项 + 说明（不含任何真实密钥）
```
- 镜像内**不含数据**；`data/`、`projects/` 一律挂卷。
- 首次启动自动执行 `init_db()` 引导（已有幂等机制）+ `scripts/create_admin.py` 的环境变量分支（`MJ_BOOTSTRAP_ADMIN_USER/_PASSWORD`，仅当 `users` 为空生效）。
- **保留 systemd 部署路径**：现有生产在 B 上跑 systemd，容器化是给新客户的交付形态，不是替换（不得为了容器化改动现有部署脚本的行为）。

## 4. 备份与恢复（判据挂「恢复得回来」，不挂「备份跑过」）

```bash
py scripts/backup_manju_db.py                    # 已有
py scripts/restore_drill.py --from <backup> --to /tmp/drill   # 新增
```
恢复演练必须输出：备份时间 → 恢复完成时间（RTO 实测）、备份点与当前的数据差（RPO 实测）、
以及一组只读断言（项目数、集数、用户数、模型条数、最近一条审计时间）。
**验收判据是演练脚本跑出的实测值，不是「有备份脚本」这件事本身。**

## 5. 指标端点

手写 Prometheus 文本格式（零依赖），最少这几组：
```
manju_http_requests_total{method,path_group,status}
manju_http_request_duration_seconds_bucket{...}
manju_jobs_active{module}         manju_jobs_queued{module}
manju_model_health{model_id,state}  manju_model_failures_total{model_id,reason}
manju_quota_usage_ratio{scope_type,scope_id,resource}
manju_db_write_lock_wait_seconds   # 事件循环冻结事故的直接观测点，必须有
manju_provider_call_latency_seconds_bucket{purpose}
```
- `/metrics` 默认只监听内网/需系统管理员或独立 metrics token，**不裸奔到公网**。
- 采集在内存聚合，**不每次请求写库**。

## 6. 安全基线（企业过检时会被逐条问）

| 项 | 现状 | 本单元要求 |
|---|---|---|
| 传输 | nginx TLS（automanju.com 证书 + IP 证书两条 lego 链路） | 保持；文档化续期链路 |
| 静态数据 | 模型 Key 明文 | 由 EP-05 加密；本单元补「备份文件同样不含明文」的验收 |
| 会话 | 头部 token，滑动过期 | EP-03 补策略；本单元补「登出即失效、并发会话可查可踢」 |
| 媒体 | HMAC 按天分桶票据 + `Cache-Control: private` | 保持，不得改成随机票据（会毁掉长缓存） |
| 审计 | 全字段 + 365 天 | 补导出；补「配置类变更」专门视图（谁改了模型/配额/角色） |
| 密钥文件 | `data/local_session_secret.txt` 等 | 统一权限自检 0600，`preflight.py` 检查 |
| 端口 | 8230 已收口到 127.0.0.1 | `preflight.py` 校验不监听 0.0.0.0 |
| 依赖 | 6 个 | 保持最小；新增依赖需在总纲 §5 记录理由 |

## 7. PostgreSQL 的触发判据（给出可测条件，本轮不做）

不拍脑袋迁移。满足**任意两条**即立项：
1. `manju_db_write_lock_wait_seconds` p95 > 1s 持续一周；
2. 单实例并发用户 > 30 且出现过 `database is locked` 告警；
3. 客户合同明确要求外部托管数据库；
4. 单库文件 > 20 GB 且备份窗口超过 30 分钟。

理由：SQLite 目前扛得住（单租户、单进程、写少读多），而迁移会动 62 张表 + 150 条手写迁移，
代价极高；把判据写死，避免「感觉该换了」这种决策。

## 8. 验收清单

- [ ] 从零开始：空目录 + compose up → 引导管理员 → 登录 → 建项目 → 跑通一集的文本阶段
- [ ] `preflight.py` 在故意制造的错误环境（端口占用、时钟偏移 5 分钟、master.key 权限 0644）下逐条报出问题
- [ ] `restore_drill.py` 输出实测 RTO/RPO，且恢复库的只读断言全绿
- [ ] 备份文件中 `grep` 已知 Key 前缀零命中（与 EP-05 联动验收）
- [ ] `/metrics` 未授权访问 403；授权后指标齐全且数值与业务接口一致
- [ ] 审计导出：按用户 + 时间范围导出，行数与页面筛选一致
- [ ] 容器化**没有改变** systemd 路径的任何行为（`deploy_to_b.sh` 逐字未变或变更点有说明）
