# EP-05 模型管理：落表、凭据加密、用途路由、故障转移、限速与分账

> 优先级 P0 ｜ 依赖：无（可与 EP-01 完全并行）
> 一句话：模型从「settings 里的两个 JSON blob + 4 个全局单选」变成**可运营的资产**——加密的凭据、按用途的优先级链、
> 自动故障转移、限速与健康度、按团队/模型的成本画像。

---

## 1. 现状事实（这是本轮技术债最集中的地方）

| 事实 | 出处 | 问题 |
|---|---|---|
| 模型库 = `settings.custom_models`（JSON 数组）+ `settings.model_credentials`（JSON 对象） | `app/model_registry.py` | 无法查询、无法索引、无并发安全（读-改-写整串覆盖）、无变更历史 |
| API Key **明文**落 `settings` 表 | `app/system_api.py:731-751` | 拿到库文件或备份即拿到全部 Key。GET 时脱敏只挡了接口，挡不住库 |
| `PUT /api/keys` **明文写 `.env`**，provider→ENV 映射是 6 家硬编码 | `app/system_api.py:2205-2237` | 违反「禁止黑白名单与枚举穷举」；新增一家供应商必须改代码 |
| 用途绑定 = 4 个全局单选（`model_text_provider`/`model_vlm_provider`/`model_video_provider`/`model_image_provider`），取值是硬编码白名单，`model_image_provider` 只允许 `hiagent` | `app/monitoring.py:173-177` | 全局单点：一家挂了整站停摆；不能按团队/项目区分；换供应商要改白名单 |
| 换路逻辑是特例：`model_route`（文本审核拒答换路，格式 `provider:model`） | `app/monitoring.py:208` | 只覆盖一种失败原因，超时/限流/5xx 没有换路 |
| 能力探测有、健康度无 | `app/model_capabilities.py`（context/output token 归一化，探不到标 default） | 不知道哪个模型正在坏；坏了也不会自动绕开 |
| 成本数据在 `provider_calls`，但没有按团队/用途的聚合视图 | — | 企业问「这个月哪个部门烧了多少」答不出 |

**保留不动的好东西**：`model_capabilities.py` 的「探不到就标 default、不伪装成实测值」；
`model_registry.py` 的「代码里不再有内嵌模型」这条产品约束——本单元强化它，不推翻它。

## 2. 目标与非目标

**P0**
1. 模型库**落真表**，`settings` 两个 blob 迁移过去，读接口兼容一个版本。
2. **凭据加密**（AES-256-GCM），主密钥文件 0600，UI 只见掩码与指纹，支持轮换；`.env` 里的明文 Key 一并迁入。
3. **用途绑定 → 优先级链**：`(purpose, priority)` 多条候选，主用 + fallback。
4. **故障转移与熔断**：连续失败/超时率/限流触发降级到下一条，健康恢复自动回切，全部换路事件进审计。
5. **限速与并发**：每凭据 RPM/TPM/并发上限。
6. **成本与延迟画像**：按模型/用途/团队/项目聚合（供 EP-04 分账）。
7. **删除硬编码枚举**：provider 白名单、provider→ENV 映射，全部改为从模型库推导。

**P1**：按组织/项目覆盖绑定；灰度（按比例/按团队）；模型下线保护（引用检查）。
**P2**：按质量/成本目标自动选优。

## 3. 数据模型

```sql
models(
  id PK 'mdl_*', org_id,                   -- NULL = 全局
  name, protocol,                          -- openai|openrouter|bailian|deepseek|zhipu|seedance|minimax_h3|seedream...
  provider_label, model_ref,               -- 供应商侧的模型 ID，逐字取用
  kinds_json,                              -- ["text","vlm","video","image"]
  base_url, enabled INT DEFAULT 1,
  capabilities_json,                       -- context/output tokens，来源标记沿用 model_capabilities 的三态
  rate_limit_json,                         -- {"rpm":60,"tpm":200000,"concurrency":4}
  notes, created_at, updated_at, created_by)

model_credentials(
  model_id PK, key_ciphertext BLOB, key_nonce BLOB, key_fingerprint TEXT,  -- sha256(key)[:12]，用于「是不是同一个 Key」比对
  rotated_at, rotated_by, created_at)

model_bindings(
  id PK, org_id,                           -- NULL = 全局默认
  purpose TEXT NOT NULL,                   -- 见 §4：来自能力目录，不是写死枚举
  model_id, priority INT NOT NULL,         -- 0 = 主用，1..n = fallback 顺序
  enabled INT DEFAULT 1, params_json,      -- 如 reasoning_effort=minimal
  created_at, updated_at, created_by,
  UNIQUE(org_id, purpose, priority))

model_health(
  model_id PK, state 'healthy|degraded|circuit_open',
  window_calls INT, window_failures INT, window_timeouts INT, window_rate_limited INT,
  p50_latency_ms INT, p95_latency_ms INT,
  opened_at, half_open_at, last_error_code, last_error_at, updated_at)
```

## 4. purpose：从数据推导，不写枚举

`purpose` 的合法值由**能力目录 + 已有调用点**推导，形如 `<kind>:<stage>`：
`text:screenplay`、`text:mapping`、`vlm:review`、`image:portrait`、`image:scene`、`video:shot`…

- 构建函数扫描现有模型调用点的 kind 与阶段标识（`app/harness/model_gateway` 的调用上下文已带阶段信息），
  产出 purpose 目录；**新增阶段自动出现在绑定页**，不需要改代码加选项。
- 每个 purpose 必须有 `priority=0` 的绑定，否则该阶段判为「未配置」并**在启动自检里报出来**（不是运行到一半才炸）。
- 兼容期：4 个旧 settings 键（`model_*_provider`）迁移成对应 purpose 的 `priority=0` 绑定，读接口保留一个版本后删除。

## 5. 凭据加密

- 算法 AES-256-GCM；主密钥来自 `data/master.key`（首次启动生成，权限 0600），环境变量 `MJ_MASTER_KEY_FILE` 可覆盖路径；
  留 KMS 接缝（一个 `KeyProvider` 协议，默认实现读文件）。
- **写入只写不读**：接口永不回明文，只回 `key_fingerprint` + 掩码（`sk-****abcd`）与 `rotated_at`。
- **轮换**：新 Key 写入 → 用新 Key 做一次真实探活 → 成功才替换旧密文（**破坏性操作要有原子性**）。
- 迁移：启动时若检测到 `settings.model_credentials` 有明文，自动加密迁入新表并把旧键置空，落审计一条。
  `.env` 里的 6 个 `*_API_KEY` 同法迁入（迁入后 `.env` 仍可作为兜底读取源，但 UI 不再写它）。
- 依赖：见总纲 §5 的 `cryptography` 决策。回退方案：`app/payments/crypto_aesgcm.py` **只有解密**，
  需补一个对称的 `aes256_gcm_encrypt`（约 20 行，GCTR + GHASH 已有）——可行但属于自写密码学，验收时必须做 known-answer test（NIST 向量）。

## 6. 路由与故障转移

```
选路：按 (org_id 覆盖 → 全局) × purpose，取 enabled 且 health != circuit_open 的最小 priority
调用：走既有 app/harness/model_gateway（不新建第二条调用路径）
失败分类：timeout | rate_limited | server_error | content_rejected | contract_invalid
换路：timeout/rate_limited/server_error → 下一优先级；content_rejected → 下一优先级（收编现有 model_route 特例）
      contract_invalid（模型输出不合契约）→ **不换路**，走既有修复回路
熔断：滑动窗口内失败率 > 阈值且样本数 ≥ N → circuit_open，冷却后 half_open 放行探针
回切：half_open 探针成功 → healthy
```

**三条硬约束**：
1. **`model` 与 `provider`/凭据必须一起传递**——分开传会让请求打到错误端点且不报错（本仓库踩过）。
   路由的返回值是一个不可分割的 `ResolvedModel(model_id, protocol, base_url, api_key, model_ref, params)`。
2. **换路必须留痕**：每次换路写一条审计（原因、从哪条到哪条、请求 id），否则「为什么这集用了别的模型」永远查不清。
3. **视频类调用有真实费用**：视频 purpose 的换路必须先确认前一次调用**确实失败**（供应商任务状态为终态失败），
   不得因客户端超时就重发——重发前必须算额度（文本免费、视频计费，这条已是既定纪律）。

## 7. 限速与并发

- 每凭据的 RPM/TPM/并发在进程内维护令牌桶 + 信号量，超限时**排队而非报错**（有上限的等待，超时才报）。
- 与 EP-04 的用户/团队并发是两个正交维度：EP-04 管「这个团队能同时跑几个任务」，本单元管「这把 Key 每分钟能打几次」。
- 多进程部署时（B 上目前单进程）令牌桶只在进程内生效——**如实标注这个限制**，不假装是全局限速。

## 8. 管理界面

`模型中心`（系统管理员）：模型列表（状态/健康/近 24h 调用与失败率/p95）、凭据（掩码 + 轮换）、
用途绑定（拖拽排优先级）、限速、测试连通性（已有 `POST /models/{id}/test` 复用）。
新增/改动的前端文件 **≤300 行**，超了拆组件。

## 9. 架构约束

- 新包 `app/models_registry/`（**不要叫 `app/models/`**，与 pydantic 模型语义冲突）：
  `store.py`(L2) / `crypto.py`(L1，纯算法零 db) / `routing.py`(L3) / `health.py`(L2) / `api.py`(L5)。
- `app/model_registry.py`（134 行，现有）保留为**兼容外观**，内部转调新包，一个版本后删除；
  **禁止 `exec()` 外观、禁止 `from .x import *`**。
- 拆包必须同步补 `tests/conftest.py::patch_models_registry_everywhere()` 与 AST 守卫测试
  （`app/hiagent.py:818`、`app/video_providers.py:147`、`app/system_api.py` 三处都在读 `model_credentials`，
  是典型的「拆包后 monkeypatch 静默失效」高危点）。
- 遍历子模块一律用 `sys.modules` 按全限定名解析，**不要 `getattr`**（曾让 `get_conn` 打桩打空连到生产库）。

## 11. 已知陷阱

1. **改共享底层原语必须跑全量**：`model_gateway` 那次子集 586 passed、全量炸出 7 个红。本单元触碰它，主会话验收时必须全量。
2. **健康度写入是高频写**：每次调用都更新 `model_health` 会制造写锁热点（整站冻结的事故根因就是同步写心跳）。
   用进程内窗口聚合 + 定期落盘（≥5s 一次），落盘走独立连接、不等锁。
3. **`model_capabilities` 的三态来源标记不能被覆盖**：迁移时把 `default_128k_32k` 当成实测值写进 `capabilities_json` 会让默认值伪装成事实。
4. **删除模型要做引用检查**：被 `model_bindings` 引用 → 409 并列出引用的 purpose，不许静默删（会让某个阶段突然无主用）。
5. **HiAgent 的思考档位**：`thinking.type=disabled` 会被 400，关思考要用 `reasoning_effort=minimal`——
   这类供应商特异参数进 `model_bindings.params_json`，不要再散落在调用点。
6. **模型库为空的新部署**：健康检查已经处理过「一条都没有」的情况（`app/system_api.py` 的 `options[0] if options else`），
   新的路由层必须同样如实报「未配置」，不得回退到任何内嵌默认模型。
