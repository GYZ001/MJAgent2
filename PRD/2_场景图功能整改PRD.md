## 2. 整改背景与现状结论

场景库当前页面结构、四列卡片密度、详情弹窗、即时搜索、生成参数和证据入口已经具备可用基础，但核心问题是“已采纳”和 QA 分数不可信，可能把错误参考图传播到分镜、图片和视频阶段：

1. **P0，纯环境硬门禁失守。** 实测「萧炎卧室」生成词明确要求画面无人、无水印，实际采用图中出现明显人物及右下角水印，卡片仍显示绿色“已采纳”、QA 0.95。人物可能被固化到下游场景参考。
2. **P0，多视角差异硬门禁失守。** 「萧家测验广场」全景/对向视角肉眼几乎同构，SSIM 0.748937，整包仍为 `ready`；该对向图不能承担反打空间参考作用。
3. **P1，状态、分数与问题互相矛盾。** 样本 8 个场景全部绿色“已采纳”，其中 5 个同时展示水印问题；前端单图通过线仅 0.6，后端整包分项也允许 0.6，且总分可掩盖硬问题。
4. **P1，生成与验收政策不一致。** `multiview.py` 的生成词禁止水印，而 `config.py:208` 默认 `ignore_unless_occluding`，角落水印可能不扣分。
5. **P1，付费与长任务不可控。** “检查并补齐场景图”名称像免费检查，实际可能补图并扣费；“重新生成场景视角包”没有总价确认；单视角重做在 HTTP 请求中同步等待生成与整包 QA。
6. **P2，详情上下文和日常管理有摩擦。** 从场景详情打开候选/参数前会清空 `detailSceneName`，关闭后回列表；状态中混有 `ready`、`approved`、`T3`；长列表筛选、图片放大比较、默认描述恢复、动态视角说明与提示词去重仍不完整。

结论：本期首先重建场景资产的硬门禁和状态语义，并对历史采用资产离线复验；其次统一付费预检和异步任务；最后保留现有高分信息架构并补足上下文、筛选、比较与可访问性。

## 3. 目标与量化成功指标

### 3.1 产品目标

- 让绿色“已采用且通过”只代表所有场景硬门禁均已通过，任何高总分都不能抵消有人物、水印政策违反、空间类型错误或多视角语义错误。
- 让每个采用结论可解释、可追溯；用户能看到通过线、维度、硬失败、警告、候选和采用理由。
- 所有可能扣费的场景操作先扫描/预检再确认，长任务可停止、恢复且不会提前替换旧资产。
- 保留卡片、详情、参数和证据等现有可用结构，降低长篇场景库管理和反复进出详情的成本。

### 3.2 成功指标

| 指标 | 发布门槛/目标 | 统计口径 |
|---|---:|---|
| 纯环境人物硬门禁漏放 | 0 | 纯环境策略下，检测到可识别人物（报告以 `person_count > 0` 表述）的候选不得通过/采用 |
| 水印硬门禁漏放 | 0 | 本 PRD 固定无水印为入库硬门禁；检测到水印或无法确认无水印的候选不得通过，处理后必须复验 |
| 视角角色硬门禁漏放 | 0 | 必需建立/对向/动作区视角未满足分类、相机轴线及标志物方位要求时整包不得通过 |
| 硬问题被总分抵消 | 0 | 任一硬失败优先于总分，状态、证据和下游可用性一致 |
| 历史场景复验覆盖率 | 100% | 以批次起始快照及签收截止前增量快照中的全部当前采用包为固定分母；每包仅计一次，无法评估仍计入分母并形成处置记录 |
| 付费确认覆盖率 | 100% | 生成、补齐、单视角、整包重生等所有扣费入口均先展示服务端真实范围和预算 |
| 取消后的误任务/误扣费 | 0 | 预检/确认取消后不创建生成任务、不扣费、不替换资产 |
| 单视角任务恢复率 | 100% | 刷新或断线后恢复进度、历史尝试和最终结果 |
| 详情上下文恢复率 | 100% | 关闭候选/参数/证据二级面板后回到原场景、原视角和原滚动位置 |
| 核心语义回归通过率 | 100% | 第 11 节 P0/P1 自动化和真实样本回归全部通过 |
| 体验观察值 | 发布后 14 天内可完整观测：硬门禁失败率、重生率、人工复核率、付费确认取消率 | 首版建立真实基线，不虚设历史数据无法支持的降幅 |

## 4. 范围与非范围

### 4.1 本期范围

- 场景圣经/场景图生成、缺口扫描、付费补齐、停止及阶段进度。
- 场景卡、采用状态、QA 分数/问题、详情、锚点、视角说明、多视角参考图、版本与适用集。
- 纯环境、无多余文字、水印政策、空间类型和多视角语义硬门禁；硬/软问题优先级和状态映射。
- 候选预览、QA 证据、人工采用/回滚、单视角和整包重生、持久任务。
- 描述编辑、恢复默认、生成词与 QA 对照、提示词规范化。
- 新场景自动发现待审、长列表筛选分页、图片放大比较、详情二级面板上下文。
- 对现有采用场景包的离线复验、标记、隔离和按失败视角补救。
- 场景页面上的共用导航、查询态、运行提醒、项目名和弹窗基础交互。

### 4.2 非范围

- 不定义人物谱保存、人物多视角脸/服装/发型一致性或人物关键事件线。
- 不承诺替换生成供应商、视觉检测模型或固定 QA 数值阈值；模型、阈值与评估集须由算法/产品通过技术设计和校准确认。
- 不调整真实图片单价和财务结算规则；所有费用由服务端预检提供，不在前端硬编码报告中的样例价格。
- 不自动删除历史不合格图；仅改变其可用状态、隔离下游新引用并提供复验/重生/人工处置。
- 不在本文虚构具体接口路径、数据库表或任务枚举；仅规定产品语义和契约要求。
- 不重构整个分镜/视频下游，仅要求其尊重场景资产可用性和警告状态。

## 6. 目标用户流程

### 6.1 首次生成场景圣经与场景图

1. 用户进入场景库，看到当前项目前期步骤状态和一致的查询态。
2. 用户启动生成后，系统先返回场景提取预览：名称、室内外、首次出现、锚点摘要、预计视角；用户可取消不需要项、合并同义场景、调整名称/锚点。
3. 对确认后的场景清单执行费用预检，展示场景数、视角数、预计图片数、单价口径、预计/最大费用、重试规则、耗时和停止/旧资产策略。
4. 用户确认后创建持久任务；页面显示当前场景、当前视角、尝试次数、QA 阶段、已完成/失败/未开始及已发生费用。
5. 用户可停止，已通过且落盘的资产保留；系统给出待补齐和 QA 失败清单。

### 6.2 检查与补齐

1. 用户点击“扫描场景图缺口”，该步骤只读且不生成、不扣费。
2. 扫描结果按缺图、硬门禁失败、软警告、任务中断、未验证分类，逐场景/视角展示原因、候选和建议动作。
3. 用户勾选要处理的项，点击“付费补齐/重试”；系统进行新的费用预检和确认。
4. 任务只处理选中且仍需处理的视角；并发变化使范围缩小/扩大时必须重新核对，扩大费用需再次确认。

### 6.3 浏览、QA 复核与采用

1. 用户用名称、室内外、QA、候选、缺图、适用集等条件过滤场景，进入目标详情。
2. 详情保留为底层上下文；候选、参数和证据作为二级面板。用户关闭二级面板后回到同一场景、同一视角和同一滚动位置。
3. 用户先看产品化结论：硬门禁、维度分、警告、通过线与“为何采用/为何失败”；需要时再展开技术证据。
4. 候选通过全部硬门禁后可采用；只有软警告时，用户确认风险并填写理由后可采用。普通用户不得绕过硬门禁。
5. 采用切换原子更新当前版本、QA 状态、证据和下游引用；保留旧版本和一键回滚。

### 6.4 单视角/整包重生

1. 用户选择具体视角或当前视角包；统一确认卡展示范围、数量、预计/最大费用和旧资产保留规则。
2. 确认后快速返回持久任务标识；展示生成、单图 QA、整包 QA 阶段，可停止并断线恢复。
3. 新图在包 QA 完成前为候选，旧采用图继续服务下游。
4. 若只因对向/动作区角色错误，默认只重生失败视角，并复跑整包 QA。
5. 新包全部硬门禁通过后才切换；失败保留旧包、候选和证据。

### 6.5 历史资产复验

1. 以影子模式对当前采用场景包执行新版硬门禁，先生成报告，不立即破坏现有引用。
2. 结果按“仍通过/仅警告/硬失败/无法评估”分类；重点标记人物、水印、空间语义及视角同构。
3. 产品/制作负责人审核处置计划。硬失败资产停止被新下游引用，既有引用展示风险；按失败视角补救，禁止静默删除历史图。
4. 补救完成并复验通过后恢复绿色状态；所有迁移批次和决策可审计、可回滚。

## 7. 详细功能需求

> 优先级沿用扫描报告；高分功能以 P2 保留/微调承接。算法阈值、接口路径、模型和数据结构均须在技术设计中确认，本文不把建议写成现有事实。

## 8. 状态与交互规则

### 8.1 场景资产产品状态

| 状态 | 判定规则 | 展示 | 下游规则 |
|---|---|---|---|
| 未出图 | 必需视角尚无图片 | 灰色，显示缺失数和生成入口 | 不可用 |
| 生成/验证中 | 当前候选正在生成或 QA | 蓝色；同时说明旧采用版是否仍可用 | 仅旧的已通过版本可用 |
| 未验证/待复核 | 有图但缺新版 QA、结果不确定或需人工处理 | 灰色/中性，不显示通过 | 默认不可作为新生产参考 |
| 已采用且通过 | 当前采用包所有必需硬门禁通过 | 绿色，展示通过摘要 | 可用 |
| 已采用但有警告 | 硬门禁通过，仅有非阻塞问题 | 黄色，必须可展开警告 | 可用，但向下游传递警告 |
| 硬失败/不可用 | 任一纯净度、空间语义或视角角色硬门禁失败 | 红色，定位失败视角和补救入口 | 不得进入新的生产引用 |

### 8.2 门禁优先级

1. 先判断策略适用性与必需视角完整性。
2. 再判断人物、禁止文字、水印、空间类型、视角角色/相机轴线/标志物方位等硬门禁。
3. 模型有可用结果时，无论硬门禁是否通过，都可计算并展示软质量维度和总分，用于诊断、审计和候选比较；硬失败时必须标“分数不参与通过判定”。
4. 只有硬门禁全通过，总分才可参与可用候选的软质量排序；它永远不得反转硬失败、待复核或必需视角不完整。
5. “已采用”描述事实动作，“通过/警告/失败”描述质量；两者必须组合展示，不能用一个绿色标签掩盖问题。

### 8.3 弹窗与列表上下文

- 场景详情是主上下文；候选、参数、证据均在其上作为二级面板，关闭二级面板只回详情。
- 列表恢复键至少包含项目、搜索/筛选/排序、页码、滚动位置、场景标识和当前视角；具体存储位置与有效期待设计。
- 编辑态任何关闭方式均先处理脏状态；查看态保持关闭按钮、Esc 和遮罩一致。
- 图片浏览支持键盘、放大、1:1、并排；状态不能只依赖颜色。

### 8.4 任务与费用

- 扫描缺口是只读操作；付费补齐是独立确认后的写操作。
- 等待中、运行中、停止中、已停止、成功、部分成功、失败等任务状态的实际枚举待技术设计确认；每个终态必须记录结束时间。
- 新图/新包未通过完整 QA 前只作为候选，不替换当前采用资产。
- 停止不等于退款；统一确认卡必须说明已开始步骤可能产生的费用。

## 9. 数据、API、算法与持久任务要求

### 9.1 场景与视角数据语义

- 场景读模型至少需要表达场景版本、室内外/纯环境策略、结构化锚点、必需及实际视角角色、当前采用视角、候选、适用集、引用摘要和状态；具体字段/表待技术设计确认。
- 每张图必须绑定场景版本、视角角色、生成参数版本、QA 规则/模型版本、候选/采用关系和证据，避免候选切换后证据串联。
- 视角包结果需表达必需视角完整性、各视角分类、相机轴线/标志物方位判断及包级结论；SSIM 等相似度只作为证据之一。

### 9.2 QA 与策略契约

- QA 输出必须区分硬失败、软警告、维度分和总分，并提供机器可判断的阻塞性与面向用户的解释；具体命名待技术设计。
- 纯环境人物门禁应落实报告提出的确定性语义：检测到人物不得由总分抵消。检测器置信度、不确定区间与人工复核策略须经算法校准确认。
- 水印政策必须贯穿生成、检测、自动处理、复验和入库，并保存政策版本；不得继续出现 `ignore_unless_occluding` 与“禁止水印”目标相冲突而 UI 仍绿色的情况。
- 视角门禁至少综合期望视角分类、相机轴线变化和标志物空间关系；任何单一相似度阈值不得成为唯一真值。

### 9.3 费用预检与写入

- 所有付费入口先调用逻辑上的范围/费用预检能力（具体接口名待确认），返回场景/视角清单、图片数、单价口径、预计/最大费用、重试上限、旧资产策略、报价有效期和防重复语义。
- 正式任务提交关联有效预检结果与用户确认；服务端重新验证价格、范围、余额、场景版本。范围扩大或预算提高必须重新确认。
- 幂等在服务端保证；双击、网络重试、刷新恢复不得创建重复任务或账单。

### 9.4 持久任务与原子采用

- 首次生成、付费补齐、单视角重做、整包重生及历史复验均应使用可恢复任务；历史复验可为独立批处理，具体实现待确认。
- 目标异步契约为：请求被服务端接受后 3 秒内返回 `accepted`（HTTP 202 或项目等价异步接受响应）及可跨刷新、断网、服务进程重启保持稳定的任务标识；不得在该请求内等待生成和整包 QA。
- 任务提供阶段、分项计数、尝试次数、已发生/预计费用、更新时间、错误分类、停止能力及结果引用。
- 当前采用切换与场景版本、包 QA、视角 QA、证据、回滚关系必须原子一致；失败时旧采用资产不变。

### 9.5 历史复验数据要求

- 批次开始时冻结基线快照：分母是该时刻全部当前采用场景包的“场景包标识+采用版本”去重集合；同一包在多处引用只计一次，运行中撤销采用也不移出分母。
- 复验期间新采用或切换版本的包进入增量快照；在产品签收截止时刻前持续补跑增量，签收分母为基线与各增量集合去重后的并集，截止后新资产进入下一批次。
- 每个复验批次记录快照标识、截止时间、规则/模型/政策版本、开始/结束时间、分母、已评估、通过、警告、硬失败、无法评估、增量和处置数量；每个资产保存旧结论、新结论、证据和处置状态。
- 影子阶段不改变下游；处置阶段通过显式开关控制“禁止新引用”，不删除旧资产/账单/证据。
- 无法评估的历史图进入“待复核”，不能被当作通过，也不能无证据直接判失败。

## 12. 实施阶段、依赖、风险与回滚

### 12.1 实施阶段

1. **阶段 A（P0 门禁与状态重建）**：明确人物/文字/水印/空间类型及视角角色规则；实现硬/软结论和新状态映射；用报告真实样本建立金标回归，先影子运行。
2. **阶段 B（P0 历史复验）**：全量离线复验当前采用包，出审核清单；按开关阻止硬失败资产的新引用，优先只重生失败视角。
3. **阶段 C（P1 费用与任务）**：生成清单预览、扫描/补齐拆分、统一费用预检/确认、服务端幂等、单视角/整包持久任务与旧包保护。
4. **阶段 D（P2 日常效率）**：详情二级面板、筛选分页恢复、放大/比较、动态视角说明、结构化锚点、中文状态、恢复默认和提示词规范化。
5. **阶段 E（观测与持续校准）**：门禁/不确定率仪表盘、规则漂移告警、人工复核反馈闭环和持续真实样本回归。

### 12.2 依赖

- 产品/算法共同确认纯环境、文字、水印、空间类型、视角角色的硬门禁与不确定处理政策。
- 人物/水印/视角分类、相机轴线和标志物方位等检测能力及经版本化的评估证据；具体模型待技术设计。
- 服务端提供真实范围、价格、最大重试预算、报价有效期和幂等保障。
- 项目现有持久任务设施能承载生成、单图 QA、整包 QA 和批量复验。
- 下游消费方能够识别不可用/警告状态，并阻止新引用硬失败版本。

### 12.3 主要风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 检测器误报人物/水印 | 合格资产被阻断 | 金标校准；不确定区间走复核；展示证据；策略版本化 |
| 对称/无标志物空间难判对向 | 大量进入未知状态 | 多信号组合；生成时强化可验证标志物；人工复核；只重做失败视角 |
| 新门禁使历史库大量变红 | 下游受阻、重生成本高 | 影子报告→审核→分批限制新引用；保留旧引用与风险提示；预算化补救 |
| 自动去水印/裁切破坏构图 | 场景标志物丢失 | 处理后复验；关键区域保护；失败转人工/重生而非直接入库 |
| 持久任务或账单重复 | 资产/费用不一致 | 服务端幂等、任务-账单-资产关联、原子采用和不变量告警 |
| 详情层级复杂导致可访问性退化 | 键盘/读屏不可用 | 焦点栈规范、自动化可访问性测试、单一关闭语义 |

### 12.4 回滚策略

- 新 QA 规则先影子运行；关闭采用开关可停止其改变可用状态，但保留评估结果。**不得回滚“硬失败不能被总分抵消”的服务端安全不变量到已知失守状态**；若模型异常，应切入“待复核”而非旧绿色。
- 新状态 UI、详情二级面板、筛选与比较功能均由独立开关控制；回滚只影响展示，不删除候选、证据或审计。
- 历史复验按批次和规则版本记录；可撤销“禁止新引用”处置标记，但不得删除复验结果。恢复前需明确风险并留审计。
- 新持久任务与旧同步路由在迁移期按创建入口互斥；在途任务继续可查询，禁止同一动作双写。必要时停止新任务创建而非强行删除在途任务。
- 数据迁移/回填可重复执行；任何回滚不删除账单、历史图和人工采用理由。

## 13. Definition of Done（DoD）

- 追踪矩阵已覆盖扫描报告 5 个共用体验项、22 个场景库逐功能项，以及场景相关全部 P0/P1/P2 风险。
- 「萧炎卧室」人物/水印和「萧家测验广场」同构视角已形成脱敏可持续的真实样本或等价金标回归；第 11 节全部 P0 用例通过。
- 人物、禁止文字、水印政策、空间类型和多视角语义等硬门禁不会被总分抵消；状态、QA 证据、当前采用版本及下游可用性一致。
- 基线快照及签收截止前增量快照中的当前采用场景包按包版本去重后完成 100% 离线复验；签收报告分母可对账，无法评估留在分母且不算通过；硬失败资产不再进入新的生产引用，且未静默删除历史资产。
- 所有可能扣费的场景入口先完成服务端范围/费用预检、统一确认和幂等保护；“扫描缺口”经自动化证明不会生成或扣费。
- 首次生成、付费补齐、单视角、整包及历史复验任务均在目标时限内返回稳定任务/批次标识，并可跨刷新、断网和服务进程重启恢复；新候选通过整包 QA 前不会替换旧采用资产。
- 详情、候选、参数和证据层级可连续操作并恢复原上下文；长列表、图片比较、动态视角说明、状态中文化、运行提醒终态计时和恢复默认通过验收。
- 算法规则、阈值、模型/政策版本、接口和状态机已有正式技术设计与评审结论；未确认事项不得以本文建议名直接实现为既成事实。
- 第 11 节 P0/P1 自动化用例 100% 通过，P2 核心路径无阻断缺陷；真实样本语义回归进入持续测试。
- 关键埋点、仪表盘、不变量告警、灰度开关、历史复验批次记录、运维与回滚说明齐备。
