# MJAgent 3.0 接口设计文档

- 文档编号：MJ3-API-001
- 版本：0.1.0
- 状态：立项评审稿
- API 前缀：`/api/v3`

## 1. 通用约定

### 1.1 协议与格式

- HTTPS + JSON UTF-8；文件通过预签名上传/下载。
- 时间使用 RFC 3339 UTC，金额使用 `{amount_minor,currency}`。
- ID 是不透明字符串；客户端不得解析前缀获得权限或类型。
- API Schema 使用 OpenAPI 3.1，服务端和客户端由同一合同生成/校验。
- 异步操作返回 `202 Accepted`和 Run/Stage 位置。

### 1.2 请求头

| 头 | 用途 |
|---|---|
| `Authorization: Bearer` | 用户认证 |
| `X-Request-ID` | 客户端请求关联；缺失时服务端生成 |
| `Idempotency-Key` | 创建/启动/批准/重试等命令幂等 |
| `If-Match` | 资源版本或 ETag 乐观锁 |
| `X-Approval-Token` | 短时高风险/费用批准，不替代权限 |
| `Last-Event-ID` | SSE 断线续传 |

### 1.3 成功响应

```json
{
  "data": {},
  "meta": {
    "request_id": "req_x",
    "server_time": "2026-08-09T08:00:00Z",
    "scope": {"tenant_id": "ten_x", "project_id": "proj_x"}
  }
}
```

异步响应：

```json
{
  "data": {
    "accepted": true,
    "production_run_id": "run_x",
    "stage_run_id": "stage_x",
    "status_url": "/api/v3/projects/proj_x/runs/run_x",
    "events_url": "/api/v3/projects/proj_x/events"
  },
  "meta": {"request_id": "req_x"}
}
```

### 1.4 错误响应

```json
{
  "error": {
    "code": "AUTHORITY_VERSION_CONFLICT",
    "message": "输入权威版本已变化，当前候选未发布",
    "classification": "AUTHORITY_DRIFT",
    "retryable": false,
    "root_error_id": "err_x",
    "details": {"expected_artifact_id": "art_a", "current_artifact_id": "art_b"},
    "recovery_actions": ["refresh", "start_new_run"]
  },
  "meta": {"request_id": "req_x"}
}
```

### 1.5 状态码

| 状态码 | 语义 |
|---:|---|
| 200/201 | 查询/同步创建成功 |
| 202 | 异步命令已持久化受理 |
| 204 | 删除/取消请求已完成且无正文 |
| 400 | 语法或参数组合错误 |
| 401/403 | 未认证/无操作权限 |
| 404 | 对象不存在或不属于请求范围 |
| 409 | 状态、版本、幂等 payload 或活动任务冲突 |
| 412 | `If-Match`不满足 |
| 422 | Schema/业务预检不通过 |
| 429 | 租户/用户请求额度限制 |
| 503 | 必需服务不可用，命令未安全受理 |

## 2. 分页、筛选和作用域

列表使用游标：

```json
{
  "data": {"items": [], "next_cursor": null, "has_more": false},
  "meta": {
    "scope": {"tenant_id": "ten_x", "project_id": "proj_x"},
    "filters": {"status": ["RUNNING"]}
  }
}
```

聚合和 total 必须在租户、项目和全部筛选后计算。项目详情/动作只能位于 `/projects/{project_id}`路径；服务端不可只按对象 ID 查询后交给前端判断。

## 14. 事件流

### 14.1 SSE

`GET /api/v3/projects/{project_id}/events?after={cursor}`

事件：

```json
{
  "id": "evt_x",
  "type": "stage.quality_changed",
  "occurred_at": "2026-08-09T08:00:00Z",
  "project_id": "proj_x",
  "production_run_id": "run_x",
  "stage_run_id": "stage_x",
  "sequence": 123,
  "payload": {"quality_status": "NEEDS_REPAIR", "issue_count": 2}
}
```

SSE 至少一次投递；客户端按事件 ID/sequence 去重，并在断线后用查询接口最终对账。

### 14.2 内部领域事件

- `source.published`
- `screenplay.bundle_published`
- `storyboard.bundle_published`
- `provider.operation_accepted`
- `media.candidate_created`
- `media.selection_changed`
- `artifact.invalidated`
- `delivery.package_published`
- `config.version_activated`

事件 Schema 进入兼容性检查，新增字段向后兼容，破坏性变更创建新 event version。

## 15. H3 内部 Adapter 合同

```python
class VideoGenerationAdapter(Protocol):
    adapter_name: str
    adapter_version: str

    async def validate(self, job: FrozenMediaJob) -> AdapterValidation: ...
    async def submit(self, job: FrozenMediaJob, operation_id: str) -> SubmitReceipt: ...
    async def get_status(self, external_task_id: str) -> ProviderTaskStatus: ...
    async def fetch_result(self, external_task_id: str, sink: ByteSink) -> MediaReceipt: ...
    async def cancel(self, external_task_id: str) -> CancelResult: ...
```

`SubmitReceipt`至少包含 `accepted`、`external_task_id`、`provider_request_id`、`submitted_at`和可安全公开的错误；Adapter 不持久化业务状态。

## 16. 接口安全与兼容

- OpenAPI 中标注 scope、role、idempotency 和 sensitivity。
- URL 不出现本地路径、Prompt、原文、Secret 或签名参数。
- 下载 URL 短时、单对象、按权限签名；禁止任意路径参数。
- 2.0 API 由 compatibility façade 映射到 3.0 Command，不复制业务逻辑。
- 兼容层响应显式包含 `deprecation`和迁移链接；至少跨两个稳定版本。
- API 破坏性升级使用新 major 前缀；Artifact/事件/Prompt 版本独立管理。

## 17. 接口验收门槛

1. OpenAPI lint、breaking-change 检查和生成客户端通过。
2. 所有写接口具有幂等/版本并发测试。
3. 所有项目接口具有跨租户、跨项目和已删除对象测试。
4. 所有详情/下载具有敏感数据和审计测试。
5. 异步接口在服务重启、响应丢失和重复提交下结果一致。
