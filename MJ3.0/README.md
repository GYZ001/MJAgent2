# MJAgent 3.0 项目启动文档集

- 文档基线：`MJ3-BASELINE-0.1`
- 版本：`0.1.0`
- 状态：立项评审稿
- 基线日期：2026-08-09
- 适用范围：MJAgent 3.0 商业化版本、私有化部署版本及其共享生产内核

## 1. 文档目的

本目录定义 MJAgent 3.0 从小说摄入、前期准备、剧本、分镜、视频生成、成片交付，到系统配置和生产观测的完整项目启动基线。文档可以直接用于需求评审、技术方案评审、研发拆解、测试准入、部署准备和变更控制。

3.0 的核心目标不是增加更多 Agent，而是把现有能力收敛为一条证据驱动、可恢复、可审计、可度量的商业生产线：

```text
来源权威 → 叙事权威 → 导演权威 → 实现媒体 → 商业交付
```

其中视频生成服务，包括 H3 私有化服务，统一视为黑盒 `VideoGenerationAdapter`：

```text
冻结输入 → 幂等提交 → 查询状态 → 获取结果 → 技术与内容验收
```

模型服务不拥有业务权威，不得直接发布剧本、分镜、视频采用版或交付包。

## 3. 统一设计原则

1. **三层权威**：剧本定义 Narrative Truth，分镜定义 Directorial Truth，视频记录 Realized Media。下游只能消费、实现或提交变更申请，不能静默重写上游。
2. **正式交接合同**：剧本通过 `ScreenplayStoryboardContract` 向分镜交付；分镜通过 `StoryboardVideoContract` 和 `ShotDependencyGraph` 向视频交付。
3. **候选与发布分离**：模型只生成候选；程序完成验证、证据登记和晋级；人工只处理高风险、低置信度或不可逆决定。
4. **状态三分离**：执行状态、质量状态、发布状态分别持久化，禁止用一个 `succeeded` 表达不同业务含义。
5. **预览与交付分离**：`PREVIEW_READY` 可以有明确标记的缺陷；`DELIVERABLE` 必须满足商业交付合同。预算或截止时间不能把预览自动升级为交付件。
6. **精确失效**：变更通过 Artifact 血缘、状态账本和影响分析计算最小失效范围，不因局部修改清空整条生产链。
7. **可恢复执行**：所有昂贵外部任务持久化操作号、租约代次、输入指纹和供应商状态；响应丢失后先对账，不盲目重新付费提交。
8. **结构化权威优先**：身份、来源、场景、状态和依赖使用稳定 ID 与类型化合同；程序无法判断的真实语义歧义才交给受约束 AI 裁决。
9. **证据可追踪**：任何发布产物都能追溯输入 Artifact、合同、Prompt、模型、参数、评估、成本和批准人。
10. **配置可审计**：平台、租户、项目、运行四级配置有清晰作用域；运行启动时冻结快照，运行中不受后续设置漂移影响。
11. **项目严格隔离**：项目观测、对象详情、下载和写动作都由服务端验证组织与项目归属；系统空间只提供全局配置和聚合健康。
12. **默认安全**：密钥不回显，模型载荷默认脱敏，原文和 Prompt 按权限、用途和保留期访问。

## 4. 两份方案的取舍结论

### 4.1 直接采用

- 统一生产控制面、不可变 Artifact、Evaluation、Promotion、Certificate。
- S2B/B2V 跨阶段合同和三层权威边界。
- `WorldStateLedger`、`AudienceKnowledgeLedger`。
- 场景级 `SceneDirectorPlan` 与类型化 `ShotDependencyGraph`。
- 视频覆盖版、连续性来源版、最终采用版三种语义。
- 低成本预演、高质量生成、场景级全局选优和完整片段 QA。
- Typed Change Request、Impact Analyzer 和最小失效。
- 项目空间、项目观测台、系统设置空间严格分离。

### 4.2 调整后采用

- “一章一集”保留为快速规划模式；商业模式改为可审计的章节/段落到剧集映射，程序保证来源覆盖无遗漏、无重复，人工发布映射。
- VLM 仍可作为评分器，但对真实媒体依赖增加独立的 `DependencyReleaseGate`；商业交付另有不可跳过的完整片段门禁。
- SQLite 仅保留开发或兼容导入用途；商业生产元数据使用 PostgreSQL，媒体使用对象存储。
- 单一供应商配置升级为能力注册、健康度、成本和策略快照，但 H3 的私有接口细节仍严格封装在 Adapter 内。
- 人工风险接受只适用于业务偏好类问题；来源错位、身份错位、文件损坏、缺镜、越权和合规失败不得被普通审批覆盖。

### 4.3 明确不采用

- 为每个问题增加新的自由 Agent 或重复让文本模型理解同一份镜头关系。
- 静默模板兜底、无证据降级、失败后假成功。
- 视频质量不足时继续污染后续尾帧依赖链。
- 用可变业务表代替发布 Artifact，或让旧 Worker 在新版本发布后继续写入。
- 将跨项目原始调用、Prompt、密钥或本地路径直接暴露到观测页面。
- 一次性推倒 2.0；3.0 采用旁路建模、双写、影子比对和阶段迁移。

## 5. 建议实施里程碑

| 里程碑 | 范围 | 建议周期 | 退出条件 |
|---|---|---:|---|
| M0 基线与评测 | 合同冻结、质量样本、成本/失败基线 | 1–2 周 | 文档批准，Golden Set 与核心 SLO 建立 |
| M1 统一控制面 | ProductionRun、StageRun、Attempt、Artifact、Outbox、ProviderOperation | 3–4 周 | 可从任意阶段崩溃恢复且不重复付费提交 |
| M2 前期与双合同 | 商业摄入、来源审阅、Production Profile、S2B/B2V | 3–5 周 | 剧本和分镜发布均能生成可验证下游合同 |
| M3 视频质量闭环 | Dependency Gate、三种选择语义、预演、完整片段 QA、场景选优 | 4–6 周 | 关键镜头不再首个技术有效即采用，依赖换版可重验 |
| M4 成片与商业门禁 | 音频、字幕、终剪、Episode QA、交付证书 | 3–4 周 | 交付包 100% 可追溯且硬门禁不可绕过 |
| M5 商业运行 | 多租户隔离、配额、安全、SLO、灰度与灾备 | 3–5 周 | 完成容量、安全、恢复和试点客户验收 |

并行实施时，4～6 人团队可在约 8～10 周形成商业 Beta，在约 14～18 周形成完整 3.0 首发版本。实际排期应在 M0 依据现有代码复用率、H3 SLA 和评测基线重新估算。

## 6. 文档使用规则

- 所有需求、用例、接口和测试均使用稳定编号；删除条目时保留编号并标记 `RETIRED`。
- 所有数据库、API、Artifact、Prompt 和配置合同必须声明版本。
- 本基线中的目标接口使用 `/api/v3`；兼容 2.0 的接口由迁移层承接，不得污染新的领域合同。
- 文档发生实质变更时必须同步更新需求追踪矩阵、测试用例和架构决策记录。
- 本文档集是项目启动基线，不代表当前 MJAgent2 代码已经实现这些目标。
