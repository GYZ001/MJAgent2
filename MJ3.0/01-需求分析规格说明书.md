# MJAgent 3.0 需求分析规格说明书

- 文档编号：MJ3-SRS-001
- 版本：0.1.0
- 状态：立项评审稿
- 日期：2026-08-09
- 上游基线：MJ3-BASELINE-0.1

## 1. 引言

### 1.1 目的

本文定义 MJAgent 3.0 商业化生产系统的业务范围、用户角色、功能需求、业务规则、非功能需求和验收口径。除非明确标记为后续版本，本文需求均进入 3.0 产品待办和追踪矩阵。

### 1.2 产品定位

MJAgent 3.0 是面向小说改编漫剧生产的工作空间系统。它把小说来源、前期视觉设定、分集剧本、导演分镜、镜头媒体、终剪和交付组织成一条可恢复、可审计、可控制成本的生产线。

系统支持 SaaS 商业部署和客户私有化部署。私有化视频服务以黑盒 Adapter 接入，业务流程不依赖 H3 或任何单一供应商的内部能力。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| Workspace/项目空间 | 一部小说及其全部改编、资产、剧集、运行和交付数据的隔离单元 |
| Production Profile | 项目的平台、画幅、语言、质量等级、预算、时长和生产规则 |
| Artifact | 不可变、有哈希和版本的业务或媒体产物 |
| Promotion | 产物通过证据门禁后被正式采用的决定 |
| Certificate | 证明某个发布产物满足指定合同的不可变凭证 |
| S2B | `ScreenplayStoryboardContract`，剧本到分镜的交接合同 |
| B2V | `StoryboardVideoContract`，分镜到视频的交接合同 |
| Preview | 可供内部观看但不满足商业交付合同的输出 |
| Deliverable | 通过全部不可跳过门禁并签发交付证书的输出 |

## 2. 现状与问题分析

现有 2.0 已具有小说摄入、人物/场景资产、剧本分片、分镜渐进提交、媒体队列、证据记录、项目观测、设置版本控制和交付包等基础。商业化的主要缺口是：

1. 多条业务链各自维护 Supervisor、Checkpoint 和成功语义，统一编排仍未成为唯一状态来源。
2. 剧本、分镜、视频之间缺少正式、版本化、可验证的交接合同。
3. 视频技术可播、连续性来源、最终采用尚未形成独立业务语义。
4. 质量评分、运行成功、媒体覆盖和商业交付存在混用风险。
5. 单章单集无法覆盖商业改编中的拆章、并章、特别篇和跨章钩子。
6. 项目空间隔离已具雏形，但商业部署还需要租户、角色、配额和数据保留策略。
7. 系统设置是全局键值集合，缺少平台、租户、项目、运行快照的完整继承模型。
8. 观测数据需要更严格的敏感载荷控制、跨项目归属一致性和长期指标体系。

## 3. 产品目标与成功指标

### 3.1 业务目标

- 将“能生成”升级为“能稳定交付并解释每次失败”。
- 降低昂贵媒体环节的无效重试和连续性错误传播。
- 提升来源忠实、人物一致、镜头可执行和整集叙事可理解性。
- 支持多个项目、多个生产成员和多个模型供应商的商业运行。
- 形成从客户反馈到定位责任阶段、最小回修和新交付版本的闭环。

### 3.2 建议首发 SLO/质量目标

| 指标 | 3.0 首发目标 |
|---|---:|
| 已发布 Artifact 血缘完整率 | 100% |
| 商业交付包缺镜率 | 0 |
| 商业交付包技术解码通过率 | 100% |
| 不可跳过门禁被自动绕过次数 | 0 |
| 外部已接单任务重复付费提交率 | <0.01% |
| Worker 崩溃后任务恢复 RTO，P95 | ≤2 分钟 |
| API 可用性（月度） | ≥99.9% |
| 项目/租户越权读取成功次数 | 0 |
| P0 关键镜头交付前质量达标率 | 100% |
| 客户问题可定位到责任阶段比例 | ≥95% |
| 运行、模型、成本证据可查询覆盖率 | 100% |

质量模型的具体阈值必须在 Golden Set 上校准，不能把未验证的固定分数直接作为商业门禁。

## 4. 用户和权限

| 角色 | 主要权限 |
|---|---|
| 平台管理员 | 租户、系统模型、平台配置、全局健康和灾备；默认不可浏览租户原文/Prompt |
| 租户管理员 | 成员、租户策略、额度、BYOK、项目创建与归档 |
| 制片人 | Production Profile、预算、阶段启动、人工门禁、交付批准 |
| 编剧/策划 | 来源审阅、人物/世界观、剧本编辑和发布申请 |
| 导演/分镜师 | 分镜规划、镜头编辑、分镜发布和上游变更申请 |
| 媒体制作 | 参考资产、视频候选、重做、连续性来源与候选选择 |
| 质检/审核 | 质量门禁、风险接受、最终交付审核 |
| 观察者 | 项目内只读访问和脱敏观测 |
| 运维人员 | 系统健康、队列、供应商状态和脱敏日志；无业务编辑权限 |

权限采用组织、项目和操作三层校验。知道对象 ID 不构成访问权限；跨范围对象统一返回不可枚举结果。

## 5. 范围

### 5.1 3.0 首发范围

- TXT、EPUB 小说摄入、来源审阅和不可变版本。
- 项目空间、Production Profile、角色/场景 Bible、参考资产和剧集映射。
- 剧本、分镜、视频、成片完整生产链。
- S2B、B2V、状态账本、观众知识账本和镜头依赖图。
- 预览、复核、商业交付三级输出。
- 统一 ProductionRun/StageRun、恢复、预算、成本和人工门禁。
- 项目级观测、系统级健康、模型中心和分层配置。
- 多租户隔离、审计、配额、密钥和数据保留。
- H3 私有化黑盒 Adapter 及其他供应商 Adapter。

### 5.2 非首发范围

- 通用影视剪辑器和无限轨道 NLE。
- 面向公众的素材交易市场。
- 自动进行版权法律判断；系统只保存授权证明和执行配置策略。
- 训练基础视频模型。
- 让模型绕过人工批准直接修改已经发布的上游权威。
- 为历史 2.0 数据伪造缺失证据；只允许明确标记为迁移或未知。

## 6. 核心业务规则

| 编号 | 规则 |
|---|---|
| BR-001 | 小说原文和人工批准的来源修订是内容事实的最高来源权威。 |
| BR-002 | 剧本发布必须同时发布 S2B；分镜发布必须同时发布 B2V 和 ShotDependencyGraph。 |
| BR-003 | 下游发现上游问题必须提交 ChangeRequest；不得原地修改已发布上游 Artifact。 |
| BR-004 | 任何外部模型只能产生 Candidate 或 Evaluation，不能直接产生 Published 状态。 |
| BR-005 | 执行完成、质量通过、正式采用和商业交付是四个独立决定。 |
| BR-006 | `coverage_version`、`continuation_source_version`、`final_selected_version`可指向不同视频候选。 |
| BR-007 | 依赖真实媒体的后续镜头只能消费通过 DependencyReleaseGate 的候选。 |
| BR-008 | 上游版本变化后，由 Impact Analyzer 分类为 VALID、REUSABLE_WITH_REBIND、STALE 或 INVALID。 |
| BR-009 | 预算或截止时间可终止生成并产出 Preview，不得自动产出 Deliverable。 |
| BR-010 | 来源错位、身份错位、文件损坏、缺镜、越权、合规失败属于不可跳过问题。 |
| BR-011 | 人工批准必须记录人、时间、依据、接受风险、对象版本和幂等键。 |
| BR-012 | 配置在 Run 创建时形成不可变快照；运行中不读取后来修改的有效策略。 |
| BR-013 | 供应商创建结果不确定时先对账 operation，不得直接重复创建。 |
| BR-014 | 项目空间切换后必须清理项目对象 ID、请求、详情和筛选状态。 |
| BR-015 | 原始 Prompt、原文和供应商响应按最小权限访问，并受保留期和审计约束。 |

| FR-SYS-004 | P0 | 模型中心维护 Endpoint、CredentialRef、Capability、Assignment、健康状态和灰度策略。 |
| FR-SYS-005 | P0 | 模型或 Prompt 变更在 Golden Set 通过后才能进入生产分配；运行中任务使用旧快照。 |
| FR-SYS-006 | P0 | 密钥保存于 KMS/Secrets Manager 或私有部署密钥库，数据库只保存引用和掩码。 |
| FR-SYS-007 | P0 | 外部 URL 测试防 SSRF、DNS 重绑定和云元数据访问；私有端点由受控网络策略单独授权。 |

## 8. 非功能需求

### 8.1 可靠性

- NFR-REL-001：Run、Stage、Attempt 和 ProviderOperation 必须持久化，API/Worker 均可无状态重启。
- NFR-REL-002：所有写操作使用幂等键或版本前置条件；重复请求结果一致。
- NFR-REL-003：Worker 写入携带 lease generation/fencing token，旧 Worker 不得发布结果。
- NFR-REL-004：数据库状态与队列事件使用事务 Outbox；消息重复消费必须安全。
- NFR-REL-005：对象存储写入先暂存、校验哈希，再提交数据库指针。
- NFR-REL-006：PostgreSQL 每日全备、持续 WAL/PITR；对象存储启用版本和生命周期策略。

### 8.2 性能与容量

- NFR-PERF-001：100 万字 TXT/EPUB 在标准节点上 60 秒内完成本地摄入和报告，不含人工审阅。
- NFR-PERF-002：项目列表 P95 ≤500ms；常用详情 P95 ≤800ms；长任务使用异步 202，不占用 HTTP 连接。
- NFR-PERF-003：事件推送延迟 P95 ≤3 秒；轮询仅作兼容降级。
- NFR-PERF-004：支持按租户、项目、剧集、供应商和资源类型限流与背压。
- NFR-PERF-005：大型项目页面使用分页/游标和按视图 Payload，不加载无关历史候选大字段。

### 8.3 安全与隐私

- NFR-SEC-001：所有非公开接口强认证；服务端执行租户、项目、角色和对象状态校验。
- NFR-SEC-002：传输 TLS，数据库/对象存储加密，密钥独立管理和定期轮换。
- NFR-SEC-003：Prompt、原文、模型响应、文件路径、凭证和个人信息按策略脱敏。
- NFR-SEC-004：审计日志不可由普通项目用户修改，记录配置、审批、原始载荷访问和高风险动作。
- NFR-SEC-005：上传防 Zip Slip、解压炸弹、恶意 MIME、超限和重复文件；媒体下载校验类型与大小。
- NFR-SEC-006：租户删除、导出和保留期满足合同及适用法规要求。

### 8.4 可维护性和兼容性

- NFR-MNT-001：领域合同、数据库、API、Prompt、配置和 Adapter 独立版本化。
- NFR-MNT-002：数据库使用 expand→backfill→switch→contract，无不可回滚的一步式迁移。
- NFR-MNT-003：历史 Artifact 指纹使用原合同序列化器验证，不能用新 Schema 重算。
- NFR-MNT-004：新模型/Prompt/质量阈值必须经过离线评测、影子流量和小比例灰度。
- NFR-MNT-005：关键模块保持领域、应用、基础设施边界，API 层不复制业务动作。

### 8.5 可观测性

- NFR-OBS-001：每个请求和后台任务携带 request_id、trace_id、run_id、stage_run_id、attempt_id 和 operation_id。
- NFR-OBS-002：指标至少包含吞吐、延迟、错误分类、重试、恢复、质量、成本、缓存命中、人工等待和供应商健康。
- NFR-OBS-003：告警必须链接可操作 Run/Stage 和恢复建议，不只给错误码。

## 9. 外部依赖与假设

- 文本、图像、视觉理解、语音和视频模型可能由不同供应商提供。
- H3 私有化服务只保证 Adapter 合同，不假设其内部模式、参数或幂等能力。
- 商业部署使用 PostgreSQL、对象存储、持久工作流/队列、Secrets Manager 和 OpenTelemetry。
- 私有单节点部署可以使用 Docker Compose，但必须保持同一数据与接口语义。
