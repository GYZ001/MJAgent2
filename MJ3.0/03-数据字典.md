# MJAgent 3.0 数据字典

- 文档编号：MJ3-DD-001
- 版本：0.1.0
- 状态：立项评审稿
- 关联文档：MJ3-SRS-001、MJ3-ARCH-001、MJ3-DB-001

## 1. 目的与规则

本文统一业务概念、字段语义、枚举和权威边界。物理列名以 `snake_case` 表示；所有 ID 使用不可猜测的字符串或 UUIDv7，展示编号与业务主键分离。时间统一存 UTC，API 使用 RFC 3339；金额使用最小货币单位整数或 `numeric`，禁止浮点结算。

## 2. 作用域与身份

### 2.1 核心作用域

| 对象 | 定义 | 权威父级 |
|---|---|---|
| Tenant | 商业客户/私有部署逻辑租户 | Platform |
| User | 登录主体 | Platform Identity Provider |
| Membership | 用户在 Tenant 中的角色 | Tenant |
| Project | 一部小说的隔离生产空间 | Tenant |
| Episode | 项目内一个交付剧集 | Project |
| Scene | 剧集内连续时空或导演场景 | Episode/Artifact |
| Shot | 分镜发布后形成的稳定镜头身份 | Storyboard Artifact |

### 2.2 标识字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `tenant_id` | ID | 所有商业数据必须可解析到唯一租户 |
| `project_id` | ID | 所有生产/观测对象必须可解析到唯一项目 |
| `episode_id` | ID | 仅剧集范围对象使用 |
| `artifact_id` | ID | 指向不可变产物，不复用业务表主键 |
| `content_hash` | SHA-256 | 对合同定义的规范序列化内容和文件计算 |
| `input_manifest_hash` | SHA-256 | 冻结全部输入 Artifact、配置和策略版本 |
| `idempotency_key` | 字符串 | 在声明的作用域内唯一，保存请求语义而非随机重试号 |
| `fence_token` | bigint | 每次重新领取写权限递增；旧 token 的提交被拒绝 |

## 8. 标准枚举

### 8.1 ExecutionStatus

`CREATED`、`QUEUED`、`RUNNING`、`WAITING_PROVIDER`、`RECONCILING`、`WAITING_RETRY`、`PAUSED_BUDGET`、`PAUSED_EXTERNAL`、`WAITING_HUMAN`、`COMPLETED`、`FAILED_FINAL`、`CANCELLED`。

### 8.2 QualityStatus

`UNASSESSED`、`EVALUATING`、`PASSED`、`NEEDS_REPAIR`、`WAITING_HUMAN`、`REJECTED`。

### 8.3 ReleaseStatus

`DRAFT`、`CANDIDATE`、`PROMOTED`、`PUBLISHED`、`SUPERSEDED`、`STALE`、`REJECTED`。

### 8.4 EvaluationRole

| 值 | 含义 |
|---|---|
| INVARIANT_GATE | 不满足即不得进入正式下游 |
| BUSINESS_RISK | 可由授权人员说明理由并承担风险 |
| OPTIMIZATION_SCORE | 排序和决定是否值得继续优化 |
| DEPENDENCY_RELEASE_GATE | 决定媒体是否可供后继依赖 |
| DELIVERY_GATE | 决定是否可成为商业交付件 |

### 8.5 IssueCategory

`STRUCTURAL`、`SOURCE_FIDELITY`、`IDENTITY`、`NARRATIVE`、`RENDERABILITY`、`CONTINUITY`、`TECHNICAL_MEDIA`、`AUDIO`、`COMPLIANCE`、`SECURITY`、`OPERATIONAL`、`COST`。

### 8.6 FailureClass

`TRANSPORT`、`RATE_LIMIT`、`PROVIDER_REJECTED`、`PROVIDER_STATE_UNKNOWN`、`TIMEOUT`、`SCHEMA`、`CONTRACT`、`QUALITY`、`AUTHORITY_DRIFT`、`BUDGET`、`AUTHORIZATION`、`CANCELLED`、`INTERNAL`。

### 8.7 DependencyType

`REALIZED_FRAME_REQUIRED`、`STATE_DEPENDENCY`、`SOFT_VISUAL_DEPENDENCY`、`NO_DEPENDENCY`。

### 8.8 ImpactDisposition

| 值 | 含义 |
|---|---|
| VALID | 仍满足新上游合同 |
| REUSABLE_WITH_REBIND | 内容可复用，但需换绑并复验 |
| STALE | 不得正式继续使用，等待复验或修复 |
| INVALID | 必须重新生成 |

### 8.9 ProviderCreateState/ChargeState

- Create：`NOT_STARTED`、`SUBMITTING`、`ACCEPTED`、`REJECTED`、`UNKNOWN`。
- Charge：`NOT_RESERVED`、`RESERVED`、`COMMITTED`、`SETTLED`、`RELEASED`、`REFUNDED`、`UNKNOWN`。

### 8.10 DependencyBindingStatus

`UNBOUND`、`BOUND`、`NEEDS_REBIND_CHECK`、`REBIND_VALIDATED`、`BLOCKED`。

该状态表达某个下游媒体任务与实际上游候选版本的绑定是否仍有效；它不同于 Artifact 的 `ImpactDisposition`。换版时先进入 `NEEDS_REBIND_CHECK`，Impact Analyzer 再给出 VALID、REUSABLE_WITH_REBIND、STALE 或 INVALID，并据此更新绑定或创建修复任务。

## 9. 数据敏感等级

| 等级 | 示例 | 默认控制 |
|---|---|---|
| S0 Public | 产品版本、公开状态定义 | 可公开 |
| S1 Internal | 聚合指标、脱敏错误 | 登录可见，按角色 |
| S2 Project Confidential | 原文、剧本、分镜、Prompt、媒体 | 租户/项目授权、加密、保留期 |
| S3 Secret | API Key、Token、签名密钥 | 仅 SecretRef，永不回显 |
| S4 Restricted | 原始供应商请求/响应、客户授权材料 | 短时提权、用途理由、完整审计 |

## 10. 数据质量规则

1. 所有正式 Artifact 必须有 `content_hash`、`schema_version`、父血缘和至少一项门禁 Evaluation。
2. 所有 Run/Stage/Attempt 必须可解析到唯一 Tenant 和 Project；冲突记录进入隔离队列。
3. SourceSegment 偏移必须连续、合法且对应所属 SourceRevision。
4. Shot 的 identity、scene、Beat、状态和对话引用必须存在于同一发布权威链。
5. 任何媒体选择必须指向技术有效候选；连续性选择还必须有 DependencyReleaseGate 证据。
6. Deliverable 必须引用 PUBLISHED 的上游证书和非 STALE 的媒体选择。
7. 配置和模型变化不修改历史 PolicySnapshot。
8. 历史未知值使用显式 `UNKNOWN`，不使用猜测值填充。
