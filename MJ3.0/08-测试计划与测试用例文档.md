# MJAgent 3.0 测试计划与测试用例文档

- 文档编号：MJ3-TEST-001
- 版本：0.1.0
- 状态：立项评审稿
- 关联文档：MJ3-SRS-001、MJ3-UC-001、MJ3-DET-001

## 1. 目的

本计划用于证明 MJAgent3.0 不只是“能生成内容”，而是能够在长链路、外部供应商不稳定、进程重启、版本变更和多人协作条件下，持续产出可追溯、可恢复、满足约定质量的交付件。

测试同时回答五个问题：

1. 业务语义是否正确，三层权威与跨阶段合同是否被遵守；
2. 失败后是否能恢复，且不会重复付费、串项目或发布旧结果；
3. 自动质量判断是否经过校准，最终交付是否满足硬门禁；
4. 权限、敏感数据、租户边界和供应链是否安全；
5. 版本、容量、成本和灾备是否达到商业运行要求。

## 2. 依据与范围

### 2.1 测试依据

- 《需求分析规格说明书》中的 FR、NFR 和验收条件；
- 《用例文档》中的主成功场景、异常流和后置条件；
- 《数据字典》中的对象、枚举和敏感等级；
- 《架构设计文档》中的组件、信任边界和恢复策略；
- 《详细设计文档》中的状态机、算法和事务边界；
- 《数据库设计文档》中的约束、RLS、迁移与备份要求；
- 《接口设计文档》中的 HTTP、事件和 Adapter 合同。

### 2.2 包含范围

- 工作空间、项目、成员、配额和项目隔离；
- TXT/EPUB 小说摄入、来源审阅和商业拆分规划；
- Production Profile、身份/场景资产和参考图；
- 剧本、S2B 合同、分镜、B2V 合同和依赖图；
- 图像、视频、音频、字幕、终剪和交付包；
- H3 黑盒视频适配与其他模型能力网关；
- Run/Stage/Attempt、Artifact、Evaluation、Promotion 和变更影响；
- 系统设置、模型中心、Prompt/策略版本和运行快照；
- 项目观测、系统健康、审计、计费、恢复和灾备。

### 2.3 不包含范围

- 对 H3 或第三方模型内部算法正确性的验证；
- 未写入已批准合同的主观审美承诺；
- 第三方云平台自身的全量安全认证；
- 尚未纳入 3.0 发布清单的实验能力。

## 3. 质量风险与测试优先级

| 风险 | 后果 | 等级 | 主要验证方式 |
|---|---|---:|---|
| 来源、身份或场景错位 | 内容逻辑错误且后续成本放大 | P0 | 合同测试、Golden Set、端到端追踪 |
| 供应商已接受但本地丢响应 | 重复提交和重复收费 | P0 | 故障注入、对账恢复测试 |
| 旧 Worker 回写新 Run | 数据污染、错误发布 | P0 | 租约代次和并发竞争测试 |
| 技术有效被当作质量合格 | 低质量视频进入连续性链 | P0 | Dependency Gate、全片段 QA |
| 跨项目或跨租户访问 | 商业数据泄露 | P0 | 权限矩阵、RLS、对象存储授权测试 |
| 配置或 Prompt 漂移 | 同一 Run 前后行为不一致 | P0 | 快照、版本兼容和重放测试 |
| 变更导致全链失效或漏失效 | 成本浪费或脏结果复用 | P1 | 血缘图和 Impact Analyzer 属性测试 |
| 长项目加载和任务积压 | 无法商用 | P1 | 容量、背压和页面性能测试 |
| 自动评分漂移 | 错误放行或过度返工 | P1 | 校准集、盲评和分布监控 |
| 观测载荷泄密 | 原文、Prompt 或凭证泄露 | P0 | 脱敏、短期授权和审计测试 |

P0 用例失败时禁止发布；P1 用例必须达到本计划规定阈值；P2 可带经批准的修复计划进入候选版，但不得影响硬门禁。

## 4. 测试策略

### 4.1 测试层级

| 层级 | 目标 | 典型对象 | 发布要求 |
|---|---|---|---|
| 静态检查 | 发现格式、类型、依赖和安全问题 | Schema、SQL、API、前后端 | 每次提交 |
| 单元测试 | 验证纯规则和边界 | 解析、状态机、哈希、失效计算 | 每次提交 |
| 合同测试 | 验证组件可替换而语义不漂移 | S2B、B2V、Adapter、事件 | 每次提交 |
| 集成测试 | 验证数据库、对象存储、队列和服务协作 | Outbox、RLS、事务、下载 | 每次合并 |
| 端到端测试 | 验证从页面触发到交付证书 | 全流程主路径和恢复路径 | 每日及候选版 |
| 质量评测 | 验证模型/Prompt/阈值 | Golden Set、盲评、回归集 | 策略变更及候选版 |
| 非功能测试 | 验证安全、性能、稳定性和灾备 | 压测、混沌、恢复演练 | 候选版及定期 |
| 试点验收 | 验证真实生产目标 | 真实题材、真实供应商、人工签收 | 正式发布前 |

单元测试可使用可控 Fake Adapter；正式候选版必须至少完成一轮真实供应商小规模链路和 H3 私有环境验收，避免只证明替身实现正确。

### 4.2 测试方法

- 示例测试：覆盖已知输入、输出和错误分支；
- 属性测试：验证覆盖无遗漏/无重复、图无环、状态转换闭包和幂等性；
- 差分测试：对 MJAgent2 兼容路径与 3.0 新路径比较来源覆盖、成本和质量；
- 变形测试：改变格式、分段、顺序或无关字段，验证语义不应漂移；
- 故障注入：在提交、持久化、消息、轮询、下载、晋级各边界注入崩溃；
- 回放测试：使用脱敏固定供应商响应复现生产问题；
- 人工盲评：隐藏模型、Prompt 和候选来源，避免评价偏差。

## 5. 测试环境与数据

### 5.1 环境分级

| 环境 | 数据库/存储 | 模型与 H3 | 用途 |
|---|---|---|---|
| DEV | 临时 PostgreSQL、MinIO | Fake/录制响应 | 单元和快速集成 |
| CI | 每任务隔离实例 | 确定性 Adapter | 自动回归、迁移和并发 |
| QA | 长期测试集群 | 沙箱或低成本模型 | E2E、权限、性能基线 |
| STAGING | 生产同构 | 真实模型小配额、H3 验收实例 | 候选版、恢复、灰度验证 |
| PREPROD | 生产同拓扑 | 合同指定模型与网络 | 容量、安全、灾备演练 |
| PROD-CANARY | 生产隔离流量 | 真实模型 | 小流量发布验证，不使用测试密钥 |

所有环境均使用独立租户、凭证、对象存储桶和密钥作用域。测试数据不得复制未脱敏客户原文。

### 5.2 数据集

1. **解析集**：UTF-8/BOM/GB18030/Big5、不同换行、无章名、重复章名、超长章、合法 EPUB、多 spine EPUB、损坏包和解压炸弹样本。
2. **来源集**：短篇、中篇、超长小说，以及拆章、并章、多章节交叉成集的已审核映射。
3. **身份集**：同名异人、别名、称谓、叙述者、非人物实体、身份演化和群像。
4. **质量 Golden Set**：覆盖身份、动作、连续性、画面技术质量、对白容量、字幕和音画同步；每项有双人标注与仲裁结果。
5. **恢复集**：固定外部 operation_id、响应丢失、状态未知、下载截断、过期 URL 和重复事件。
6. **安全集**：跨项目 ID、过期授权、恶意文件名、受限 URL、敏感 Prompt、伪造 MIME 和大对象。

### 5.3 Golden Set 管理

- 样本按题材、人物数量、镜头类型、时长、模型和供应商分层；
- 训练/调参集与最终验收集隔离；
- 标注人不知道候选来自哪个模型或版本；
- 每季度或模型大版本变更后复核分布；
- 自动评分阈值必须记录精确率、召回率、误放率和误拒率，不以单一平均分决定发布；
- 来源、身份、缺镜、文件损坏、越权和合规类硬错误要求验收集误放为 0。

## 6. 自动化与执行频率

| 触发 | 必跑集合 | 时间预算 |
|---|---|---:|
| 本地提交前 | 单元、Schema、文档链接、格式 | 10 分钟内 |
| Pull Request | 单元、合同、数据库迁移、核心集成、安全静态检查 | 30 分钟内 |
| 合并主干 | 完整集成、关键 E2E、兼容回放 | 60 分钟内 |
| 每夜 | 全量 E2E、属性测试、故障注入、Golden Set 快集 | 4 小时内 |
| 每周 | 性能趋势、长稳、依赖安全、备份恢复抽检 | 约 8 小时 |
| 发布候选 | 全 P0/P1、完整 Golden Set、真实供应商、灾备、安全 | 结果驱动 |
| 上线后 | 合成监控、Canary 指标、质量和成本漂移 | 持续 |

不稳定测试必须先归类和修复根因；不得用无限重跑把失败转换为通过。供应商波动用隔离重试策略和趋势报告表达。

## 8. 端到端验收场景

### E2E-A 商业主路径

页面创建工作空间和项目 → 上传小说 → 审阅摄入报告 → 发布商业剧集映射 → 完成前期资产 → 发布剧本/S2B → 发布分镜/B2V → 预演和 H3 生成 → 依赖释放 → 完整片段 QA → 配音字幕终剪 → Episode Gate → 生成 DELIVERABLE 和证书。

验收要求：全链路不直接修改上游权威；每个输出可追溯；最终包无硬门禁问题；成本与供应商 operation 可对账。

### E2E-B 中断恢复

在模型提交、供应商接受、轮询、下载、对象提交、Evaluation、Promotion 和交付打包八个边界分别终止进程并恢复。

验收要求：不重复付费提交、不丢失已确认结果、不越过 Gate、不允许旧 Worker 发布。

### E2E-C 精确变更

发布初版后，依次修改来源片段、人物参考图、场景台词、镜头选择和连续性来源版。

验收要求：Impact Analyzer 的 VALID/REUSABLE_WITH_REBIND/STALE/INVALID 与预期图一致，无关产物保持可用，受影响产物复验后才能再次发布。

### E2E-D 租户与观测隔离

以平台管理员、租户管理员、项目成员、观察者和运维角色访问项目与系统空间。

验收要求：对象级权限、RLS、短期原始载荷访问、下载授权、审计和系统聚合均符合合同；不存在跨项目正文、Prompt 或凭证暴露。

## 9. 缺陷管理

| 严重度 | 定义 | 响应目标 | 发布规则 |
|---|---|---:|---|
| S0 | 数据泄露、不可恢复损坏、错误收费、大范围交付错误 | 立即响应 | 停止发布/必要时回滚 |
| S1 | P0 主路径不可用、硬门禁失效、跨项目错误 | 2 小时 | 必须修复并全量回归 |
| S2 | 有受控替代路径但影响质量或效率 | 1 工作日 | 由发布负责人评估 |
| S3 | 轻微体验、文案或低概率非关键问题 | 3 工作日 | 可进入后续版本 |

缺陷必须包含环境、构建、配置快照、request/trace/run ID、最小复现、期望/实际、脱敏证据和影响范围。外层错误码不作为根因结论。

## 10. 准入、退出与发布门禁

### 10.1 测试准入

- 需求、API、Schema 和迁移版本已冻结；
- 构建可复现，SBOM 和签名可用；
- 测试数据、环境、供应商配额和回滚路径就绪；
- 核心模块单元/合同测试通过，阻断级静态问题为 0。

### 10.2 发布退出条件

- 所有 P0 用例 100% 通过；P1 通过率不低于 98%，剩余项无 S0/S1；
- 需求追踪矩阵中 P0 FR/NFR 均有自动或人工验证证据；
- Golden Set 硬错误误放为 0，其他指标达到批准的 QualityPolicy；
- 真实 H3 与至少一条真实模型全链路通过；
- 性能、72 小时长稳、PITR 和灾备演练达到目标；
- 安全测试无未处置 Critical/High 发布阻断；
- 数据库迁移、应用回滚和配置回滚均演练成功；
- 产品、研发、测试、安全、运维和试点客户签署 Go/No-Go。

通过率不替代关键性判断：任何硬门禁、租户隔离、收费幂等、恢复或证书追踪 P0 失败均为 No-Go。
