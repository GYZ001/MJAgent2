## 0. 一句话结论

**衔接质量在这条链路上被切成了两半，而且两半各自丢掉了对方拥有的东西：**

- **场景内部**：下一镜的唯一视觉输入是上一镜的真实尾帧——几何与构图连续性极强，但**人物/场景真值参考图被显式清空**（`app/media_exec/run_job.py:2887`）。身份锚点整场只在首镜注入一次，之后每一镜都在上一镜的生成结果上继续生成，误差沿链累积且不可逆。
- **场景之间**：身份锚点重新注入，但**几何与构图完全重置**——分镜层看不到上一场产出、计划层清空依赖、编译层不注入上一镜布局，换场镜还拿不到任何额外的观看时间预算（三个预算字段硬编码为 `0.0`）。

再加上兜底闸门全部失效：VLM 质检已 `score_only`、既不阻断也不重抽；视频采用取的是「**第一条技术合格**」而非最佳；`boundary_report` 只比文本且永不阻断。**画面层面的衔接正确性，在整条链路上没有任何一处被强制执行。**

推进合理性另有一处更硬的堵点：`hook` / `cliffhanger` 自分集起恒为空串，全仓没有任何一处写回——**每一集在结构上都被禁止承接上一集、也被禁止铺垫下一集。**

## 1. 两条链路的结构性对比

### 1.1 对照物在做什么

**对照 A（19 镜 × 10s）**：人工先写导演阐述，定下「镜 01–11 暖金夕阳＝人间无力 / 镜 12–19 冷青绿＝仙途暴力」这一条唯一的情绪结构，再用两套「通用尾缀 A / B」把色调分段锁死；跨镜有一条连续的光照推进轴（夕阳压山脊 → 最后一线 → 天光转暗蓝 → 夜空 → 清晨薄光）。执行建议里还有两条本项目正好缺的纪律：**先跑关键镜定基准**、**失败时一次只改一处**。

**对照 B（7 段 × 15s）**：用「电影级预告片质感，多镜头叙事，镜头之间硬切」＋15s 时长诱发模型原生多镜头，每段内含 3–4 个镜头由模型一次生成；**段与段之间全部硬切、不加转场特效**，唯一例外是冷暖分界处留 0.5 秒黑场；动作段快切 4–5 秒、情绪段长镜 8–10 秒；**每段跑 2–3 个候选挑角色最稳的那版**。

### 1.3 最关键的一处架构事实，以及它的代价

`app/video_plan.py:401 apply_scene_boundary_strategy` 用一段确定性代码把每个镜头分成两类：

| | 场景入口镜 | 场景内后续镜 |
|---|---|---|
| 模式 | `REFERENCE_IMAGE_MODE` | `FIRST_FRAME_MODE` |
| 视觉输入 | 人物库图 + 场景库图 + 本镜叙事关键帧 | **只有上一镜真实尾帧一张** |
| 依赖 | `depends_on_shot_id = None`，`state_dependency = "none"` | `first_frame` = `PREVIOUS_ADOPTED_TAIL` |
| 证据 | `app/video_plan.py:415-448` | `app/video_plan.py:450-473`；`app/media_exec/run_job.py:2887` |

`app/continuity.py:319 uses_previous_tail_frame` 对除 `scene_change` 外的**全部** continuity_mode 返回 `True`——同一场景内每一次切镜，画面都是从上一镜真实结束帧长出来的。**这是纯提示词方案在原理上做不到的事。**

**但代价被写在同一段代码里：** `app/media_exec/run_job.py:2887` 执行 `meta["reference_images"] = []`，`app/video_modes.py:4650-4653` 明确禁止 `FIRST_FRAME_MODE` 携带 `reference_image`，`app/video_plan.py:1462-1476` 的 `FIRST_FRAME_ROLE_CONFLICT` 要求 roles 恰好等于 `['first_frame']`。

**于是一整场戏里，人物身份真值只在首镜注入一次。** 第 2 镜起，模型看到的唯一图像是上一镜**生成结果**的尾帧；第 3 镜看到的是「基于第 2 镜生成结果的生成结果」。脸型、发型、服装、体型的微小偏差逐镜叠加，而**系统里没有任何「回注 identity anchor」的机制**。

这就是本项目衔接问题的真正形状——**不是「场内好、场间差」，而是两边各丢了一半：**

- **场内**：几何连续、身份失锚 → 长场景后半段人物慢慢变成另一个人；
- **场间**：身份有锚、几何重置 → 换场处像幻灯片。

## 2. 优点：本项目相对纯 AI 提示词方案的真实优势

**A1 · 场内真实尾帧链。** 见 §1.3。抽帧实现取视频末尾 0.1 秒处一帧（`app/video_modes.py:1926-1943`），并用 `(path, size, mtime_ns)` 冻结上一镜采用版本，检测重抽后的尾帧过期（`:1946-1979`）。对照 A 只能写「他保持着投掷后的姿势不动」，本项目直接把那一帧像素喂进去。

**A2 · 角色身份的三层锚定。** 文本锚（`appearance_canonical`，`app/stages.py:3510`）＋像素锚（定妆照）＋**按集分段的漂移重绘**（`app/portraits.py`，`ep_start/ep_end` 开区间，外观在哪一章变化就在那一集重绘）。对照 A 只能给一张定妆图全片共用。

**A3 · 场景一致性走和角色同一条链。** 场景圣经 → 场景图入库 → 同一 `scene_name` 的所有镜头、所有集共用同一张场景参考图（`app/stages.py:3580`）。

**A4 · 结构化连续性状态，而不是自然语言承接。** `SceneContinuityState`（`scene_revision_id`/`time_of_day`/`lighting_state`/`axis_id`/`landmarks`）、`CharacterContinuityState`（`look/outfit revision`、`screen_side`、`pose`、`facing`、`gaze_target`、左右手占用）、`PropContinuityState`（`revision_id`/`owner`/`location`/`form`/`text_state`），未被本镜改动的字段由代码继承（`app/schemas.py:1294-1320`、`app/continuity.py:456`）。对照包里「葫芦在谁手上」全靠人脑记。

**A5 · 确定性合同约束 LLM 写手。** `app/compiler.py:1202` 输出 20 个固定段落（FORMAT / GENERATION GOAL / VISUAL ANCHOR / REFERENCE ROLES / PREVIOUS SHOT HANDOFF / VISIBLE CAST / START STATE / ONE CURRENT ACTION / ACTION TIMELINE / END STATE / STRUCTURED CONTINUITY / PERSISTENT SCENE GEOMETRY / CAMERA / PERFORMANCE / ENVIRONMENT DYNAMICS / AUDIO TIMELINE / ON-SCREEN TEXT / CONSISTENCY / VISUAL QUALITY / DO NOT），超长时按优先级分级压缩、**永不截断台词/画面文字/首尾状态**（`app/compiler.py:1568-1720`）。对照 A 手写的「0-3 / 3-7 / 7-10 秒」分时段描述，本项目由 `_compile_action_timeline` 按时长自动生成（`app/compiler.py:846`）。

**A6 · 参考图的角色绑定与装箱纪律。** 一次最多 9 张（`app/video_modes.py:162-165`），优先级 `previous_shot_frame > 叙事关键帧 > prop > scene > character > style`（`:4334-4455`），并为每张图生成 `Reference image N: use as character「张三」; identity/appearance only` 的显式映射行，末尾追加「每个具名角色只出现一次」（`:4489-4572`）。对照包只能靠 `@角色名` 这种弱绑定。

**A7 · 口播容量硬门禁。** 口播字数按时长线性预算（`app/config.py:317`，5s ≤18 字…10s ≤36 字），超限强制拆镜（`app/continuity.py:798`）。

> 需如实限定：**动作容量不是同等强度的门禁**。权威路径下由 `AtomicAction` 各阶段 `estimated_min_s` 之和与镜长比较（`app/continuity.py:761-778`）；但 legacy 路径下 `action_capacity_errors` 直接 `return []`（`:779-780`），`count_sequential_action_beats` 已被改成「有文本就返回 1」（`:579-581`）。详见 D22。

**A8 · 来源覆盖与必保留清单。** 剧本层建立 `SRC*` 索引并要求逐段标记交付/合并/上下文保留（禁止静默删戏）；分镜层有 `key_lines` / `key_plot_points` 校验。对照 B 自己在文档结尾承认压缩掉了四段内容，代价只能靠人写进文档提醒。

> 需如实限定：`validate_storyboard_preserves_key_content` 在 `narrative_plan is not None` 时**直接 `return []`**（`app/validators.py:3153-3154`），现代权威剧本改由 narrative graph gate 负责。分工合理，但短路时不打标记，详见 D23。

**A9 · 画面文字不交给视频模型。** `required_text.strategy=deterministic_insert` 时视频 prompt 明确禁字，精确中文由终剪 `render_text_card` 渲染（`app/compiler.py:769`、`app/final_edit.py:146`）。对照 A 也发现了同一问题，但只能靠人工提醒「石匾三字后期合成」。

**A10 · 转场由 NLE 执行，不烧进片段。** 生成模型只被要求「末尾保留约 0.3 秒稳定动作结果，不自行生成渐变、闪光或叠化」（`app/compiler.py:1462-1475`），实际转场由 `app/final_edit.py:58` 映射成 ffmpeg `xfade` ＋ `acrossfade`，并做 `loudnorm=I=-16:TP=-1.5:LRA=11` 响度归一化（`:440-470`）。

**A11 · 关键帧候选 best-of-3 由 VLM 打分选出。** 每个关键帧槽位并发生成 3 个候选（`app/video_modes.py:321-335`），由 VLM 评分选胜。这正是对照 B 建议的「每段跑 2–3 个候选挑最稳的」——**但它只用在关键帧上，没有用在视频上**，详见 D9。

**A12 · 三道人工确认门 + 完整权威指纹链。** S19（确认分镜才解锁付费）、S20（视频补齐授权 + 预算 grant）、S30（交付审批，审核人/意见/风险必填）。串起它们的是 `artifacts.content_hash` + 血缘（`app/db.py:477-499`）、`blueprint_hash` / `identity_registry_hash` / `shard_plan_hash`（`app/stages.py:287`、`:302`）、`production_revisions.input_fingerprint` + completion certificate（`app/production/publish.py:78-120`）、`release_qualification_hash`（`app/video_plan.py:580`）、`manifest_hash`（`app/downstream_authority.py:14`）。缺任一镜真实模型视频直接拒绝出片（`app/media_exec/concat.py:938-955`）。

**A13 · 规模与可恢复性。** 对照包是一次性的 19 条 / 7 条手工提示词；本项目是「一章一集」可无限延伸的流水线，带 Run/Step/Event、artifact 血缘、预算预留与重启续跑。

## 3. 缺陷清单

分级：**P0 = 直接决定衔接自然度与推进合理性**；**P1 = 显著影响观感**；**P2 = 债务与度量**。

### P0

#### D1 · 场内身份锚点只注入一次，误差沿链累积且不可逆

`app/media_exec/run_job.py:2887`：`meta["reference_images"] = []`。
`app/video_modes.py:4650-4653`：`FIRST_FRAME_MODE` 禁止携带 `reference_image`。
`app/video_plan.py:1462-1476`：`FIRST_FRAME_ROLE_CONFLICT` 要求 roles 恰好 `['first_frame']`。

一场戏里除首镜外的**所有**镜头都走 `FIRST_FRAME_MODE`（`apply_scene_boundary_strategy` 的默认分支）。身份真值只在场景首镜注入，之后每一镜的唯一视觉输入是上一镜**生成结果**的尾帧。

**这是镜间观感衔接最大的结构性薄弱点**：脸/发型/服装/体型逐镜微漂，到长场景末尾与首镜脱节，而没有任何回注机制。它和 D2（5 秒默认→一场戏镜头更多）叠加后会显著放大。

#### D2 · 5 秒默认把「生成边界密度」推到不必要的高位

| 证据 | 内容 |
|---|---|
| `app/renderability.py:112` | `PREFERRED_SHOT_DURATION_S = 5` |
| `app/renderability.py:113` | `DURATION_REVIEW_RISK_TAG = "duration_gt5_needs_review"`——**超过 5 秒要进 AI 时长审核** |
| `app/renderability.py:124` | `episode_target_from_spine`：`raw = spine_beat_count * 2 * 5` |
| `app/validators.py:4897-4972` | `prefer_default_shot_durations`：**主动把「能 5s 讲完的镜压回 5s」**。不是被动默认，是主动下压 |
| `app/stages.py:14390` | 逐镜 prompt：「duration_s 默认 5s……**绝大多数镜用 5s**……禁止无内容拉长」 |
| `golden/renderability/doupocangqiong_ep1_baseline.json` | 实测基线：24 镜 / 144 秒 = 均镜长 **6.0 秒** |

对照 A 是 19 镜 / 190 秒 = 均镜长 10 秒。

**必须区分两个概念：**

- **切点密度**：多久切一次。对照 B 每段 15 秒内切 3–4 次，折算约 5 秒一切——和本项目差不多。
- **生成边界密度**：多少次独立的模型生成。对照 B 只有 **7 次**，本项目一集有 **24 次**。

每一次生成边界都是一次身份漂移、光照漂移、音色漂移、底噪跳变的机会。**问题不在「切得密」，而在「每个切点同时是一次独立生成」**，而且在场内还是一次**串联**的生成（D1）。

#### D3 · 场景入口是三重硬断，没有任何视觉承接

1. **分镜层**：`app/stages.py:13385 generate_storyboard_scene_pack` 的签名只接受 `outline` / `scene_context` / `shot_nos`，**不接收任何已完成镜头**；导演规则第 5 条明写「本场第一镜的 `first_frame_desc` 只按人物谱和场景库建立起点」（`:13504`）。写这一镜的模型看不到上一场结束在哪里。
2. **计划层**：`app/video_plan.py:415-448` 在场景入口清空 `depends_on_shot_id` / `state_dependency` / `motion_dependency`。
3. **编译层**：`compile_prompt` 在 `scene_change` 下不注入上一镜构图、光线与布局。

放大器一：场景身份 = `(scene_name, scene_time)`（`app/video_plan.py:392`）。**地点没变、只有时间标签变了，同样触发完整重置。**

放大器二：场景入口镜的 0 秒画面没有对应图像证据。关键帧默认落在镜头 64% 时间点（`app/video_modes.py:822-940`），`duration <= 7s` 时恒为 1 张（`:788-800`），**0 秒起点完全交给文本**。

**并且没有任何校验要求场景入口镜是建场镜**——搜索 `建场 / establishing / 场景首镜` 在 `app/validators.py` 中 **0 命中**。

#### D4 · 换场镜拿不到任何额外的观看时间预算

`app/narrative_outline.py:1598-1608` 里 `ShotCapacityBudget` 三个字段被**硬编码为 0.0**：

```
"attention_switch_s": 0.0,
```

#### D10 · 反打 / 反应镜继承上一镜尾帧，与 PRD 的明确设计相反

`app/continuity.py:319-322`：


`PRD/剧本分镜与Seedance视频连续性整改方案.md` 与 `docs/PROMPT_SPEC.md` §D1 都明确写着「**只有 `action_continuation` 使用上镜尾帧作为 0 秒起点**，其余模式必须重新构图」。代码把这条整体反转了。

**这是「视频衔接不自然」里最可归因、也最容易验证的一条在编码矛盾**——建议按 `continuity_mode` 分档：`action_continuation` / `insert_detail` 用尾帧；`reverse_angle` / `reaction_cut` 改为「尾帧作场景/光线参考，但不作 0 秒构图」，并回注该镜主体的身份图（同时解掉 D1）。

## 4. 根因归纳

**R1 · 一致性是权威，节奏与情绪不是。**
一致性有：结构化状态机、身份合同、场景库、参考图装箱优先级、边界报告、逐镜质检。
节奏与情绪有：一句 `emotional_curve` 自由文本（只校验字数）、一个「默认 5 秒」的常量、三个恒为 `0.0` 的时间预算字段。
一套系统会朝着「它能度量的方向」演化——所以这套系统的成片一致性设计很完备，节奏很平。

**R2 · 衔接被切成两半，两半各丢了一半。**
场内：几何连续（真实尾帧）但身份失锚（`reference_images = []`）→ 长场景后半段人物慢慢变成另一个人。
场间：身份有锚但几何重置，且没有时间预算 → 换场像幻灯片。
更麻烦的是尾帧的**适用范围被反转**（D10）：`reverse_angle` / `reaction_cut` 本不该用上一镜尾帧，现在都在用。

**R3 · 画面层的正确性在整条链路上没有任何一处被强制执行。**
`boundary_report` 比声明状态（且两侧本来就被强制同步，基本恒等）、不阻断；`qa_shot` 只看单镜内部且已 `score_only`；采用取「第一条技术合格」而非最佳；修复路由把 quality 类 Issue 直接 `handoff_human`；确认门只挡 errors。**五道闸门叠加下来，成片是链路里唯一从未被语义审视过的产物。**

**R4 · 跨集推进在数据层就被堵死。**
`hook` / `cliffhanger` 恒空且全仓无写回，`prev_ending` 恒空，`synopsis` 只是前 100 字预览。不是模型不会写钩子，是系统不给它地方放。

**R5 · 多处根因不是没人想到，而是两份 PRD 互相否决、代码只能站一边。**
详见 §6 的设计冲突清单。这类问题不能靠写代码解决，需要产品先裁决一份口径。

## 5. 优化方案

原则遵循 `CLAUDE.md`：优先修改现有代码，不引入新框架，不扩大需求范围。**下列多数条目不是新需求，而是把 PRD 已经写过、但被反转或未落地的机制补回来**——相关处已标注来源。

### P0-1｜按 `continuity_mode` 分档使用尾帧，并回注身份锚点 → D1 / D10

这是**投入最小、收益最直接**的一条，改动集中在两个函数：

1. `app/continuity.py:319 uses_previous_tail_frame` 分档：
   - `action_continuation` / `insert_detail` → 尾帧作 0 秒构图起点（保持现状）；
   - `reverse_angle` / `reaction_cut` → **不再作 0 秒构图**，改为「场景与光线参考」；
   - `same_scene_cut` → 由本镜主体是否与上一镜相同决定（相同则用，换主体则不用）。
2. `app/media_exec/run_job.py:2887` 的 `meta["reference_images"] = []` 改为**保留本镜可见角色的身份图**。这需要同步放宽 `app/video_modes.py:4650-4653` 与 `app/video_plan.py:1462-1476` 的 `FIRST_FRAME_ROLE_CONFLICT`——当前它们要求 roles 恰好等于 `['first_frame']`。
3. 反打镜的资产选择接上已有能力：`app/multiview.py:398-412 select_character_view_roles` 增加 `continuity_mode == "reverse_angle"` 分支优先 `profile`，`select_scene_view_roles`（`:410-413`）在反打时返回 `['reverse_angle']`。**库里已经存了这些视角**（`CHARACTER_REQUIRED_VIEWS` / `SCENE_REQUIRED_VIEWS`，`app/multiview.py:29-32`），只是没人取。

**验收**：长场景（≥6 镜）末镜与首镜的角色身份 VLM 相似度；反打镜的「人物复制/双人重影/上一动作重演」发生率——`PRD/剧本分镜与Seedance视频连续性整改方案.md` §4.2 已定义该指标，当前必然为 100%，目标 0%。

### P0-2｜跨镜像素连续性质检（Cut Readability QA）→ D5

**投入产出比最高——两张帧都已在磁盘上，零额外付费生成。** 且 `PRD/漫剧成片质量、镜头连续性与文字画面整改PRD.md` §11.2 已经把方案写好了（喂入上一镜 80%/95%/末帧 + 下一镜首帧/5% 帧），只是没实现。

1. 新增 `qa_cut(prev_frames, next_frames, boundary_contract)`，评五项：`identity_continuity`、`lighting_continuity`（跨 `lighting_arc` 时按预期方向放行）、`axis_continuity`（配合 P1-3）、`scale_jump`（远景直切特写、同景别同机位跳切）、`ambience_continuity`（若接入 P1-4）。
2. 结果写入 `app/final_edit.py:328 boundary_report`，交付包生成**切点报告**（每行定位到 `from_shot_no → to_shot_no`）。
3. **先做成 warning + 报表，不阻断交付。** 阈值可信后再讨论升级为门禁。

**验收**：每集产出切点报告；「报告标红的切点」与「人工主观觉得不连的切点」重合率 ≥70%。PRD §16.3 的「相邻镜边界目标通过率 ≥75%」第一次有了数据源。

### P0-3｜让质检重新参与采用与重试（有界版本）→ D6 / D7 / D18

当前的 `score_only` 是为了避免 QA 抖动造成无限重抽和成本失控，**这个顾虑是对的**。建议恢复的是**有界参与**，不是回到无界重抽：

1. **让 QA 参与采用。** `app/evidence/media.py:481-485` 的 `best = technical_pool[0]` 改为按已经算好的 `selection_score` 取最高（`ordered[0]`）。**这一行改动零额外成本**——分数本来就算了，只是没用。这直接解掉 PRD §16.2 结构性不可达的「best-of-N 相对首个候选平均 QA 提升 ≥0.10」。
2. **有界重抽。** 只对主项严重不达标（`action_match` 或 `character_match` ≤0.4）触发，**每镜最多一次**，与既有预算预留打通。`compile_prompt` 的 `critique` 入参已支持定向修复（`app/compiler.py:1562-1566`），当前只是没人调用。
3. **一次只改一处。** `app/video_repair_router.py:91-98` 的 `critiques[:6]` 改为**每轮只下发最高优先级的 1 条**，失败后再叠加第 2 条。这正是对照 A 的执行纪律「失败时只改一处，否则无法判断是哪一句起了作用」。
4. **修复级别与失败语义挂钩。** `preferred_level_for_code`（`:44-47`）当前是返回固定 `"L1"` 的 shim，恢复其按失败码选层的语义（PRD §5.1 已定义映射表）。
5. **级联判定放宽。** `app/video_repair_router.py:284-300`：上游镜被替换后，**下游只要 `first_frame` 来自旧尾帧就必须重做**，不看 grade。
6. 保留 `score_only` 作为可回滚的配置开关。

**验收**：重抽率有上限且可观测；采纳镜 QA 主项均分提升；成本增幅可预测（≤每镜一次）。

### P0-4｜场景入口桥接（Scene Entry Bridge）→ D3 / D4 / D16 / D20

1. **让场景包看得见上一场。** 给 `generate_storyboard_scene_pack`（`app/stages.py:13385`）增加 `previous_scene_exit` 入参（上一场末镜的 `last_frame_desc` + `continuity_state_out` 摘要），导演规则第 5 条（`:13504`）从「只按人物谱和场景库建立起点」改为「**必须从 `previous_scene_exit` 里选一个可见承接物带入**」。
2. **新增 `entry_bridge` 字段**：场景入口镜必须声明继承的承接物——人物、道具、方向、声音之一——并写进 `first_frame_desc`。承接物来自上一镜 `continuity_state_out`，可校验。这是把对照 A「他带着某线索来到某处」的手法结构化。
3. **给换场镜真实的时间预算**：`app/narrative_outline.py:1602-1607` 的三个 `0.0` 改为按边界类型取值——`scene_change` 时 `spatial_reorientation_s` 与 `attention_switch_s` 取非零并计入 `minimum_duration`。换场镜自然会比场内镜长，这正是它该有的样子。
4. **场景入口镜强制建场**：`shot_size` ∈ {远景, 全景, 中景}，禁止直接上近景/特写。
5. **给场景入口镜一张 0 秒图像证据**：关键帧默认落在 64%（`app/video_modes.py:822-940`），`duration<=7s` 恒为 1 张（`:788-800`）。建议场景入口镜的单张关键帧改落在 ~10% 处——它的作用是**建立**，不是**决定性瞬间**。
6. **拆开「换地点」与「换时间」**：`app/video_plan.py:392 _scene_identity` 目前把 `(scene_name, scene_time)` 合成一个身份。改为——`scene_name` 变化才完整重置；只有 `scene_time` 变化时走 `time_shift` 子模式，**仍用上一镜尾帧作构图锚**，但允许光照按 P1-1 的 `lighting_arc` 演进。
7. **恢复转场语义**：`app/stages.py:13193-13198` 的二值写死改为按边界语义选择（时间跳跃 → 淡出淡入；回忆进出 → 声音延续+叠化；动作追逐 → 甩镜/遮挡转场；构图呼应 → 匹配剪辑；**其余一律硬切**），并给有前置条件的转场加前置校验。`app/validators.py:114-122 default_scene_transition` 的默认从「淡出淡入」改为「硬切」，`:748-756` 的「换场禁止硬切」改为「换场默认硬切，用特效必须写明理由」。对照 B 就是全片硬切、只在唯一的冷暖分界留 0.5 秒黑场。
8. **给场景密度加上下限**：单场 <2 镜时要求写明「单镜独立成场」的理由；整集 `scene_change` 次数进入度量看板。

**验收**：转场特效使用率 100% → ≤30%；场景入口镜远景/全景占比 ≥60%；换场镜平均时长 / 场内镜平均时长 ≥1.3。

### P0-5｜镜长节奏权威（Tempo Authority）→ D2

1. 大纲阶段引入 `tempo_class` 三档：`sustain`（8~10s，情绪/揭示/收束）、`normal`（6~7s）、`staccato`（5s，动作/话轮/紧张），由场次 `story_function` 与 `emotional_curve` 段位决定。

3. `app/validators.py:4897 prefer_default_shot_durations` 的下压只在 `tempo_class == staccato` 时生效。
4. `DURATION_REVIEW_RISK_TAG`（`app/renderability.py:113`）收窄为「>5s 且口播/动作容量都没用满」才打标——当前这条实质上是在惩罚长镜。

**验收**：均镜长 6.0s → 7.5~8.0s；单集生成边界数下降 ≥25%；金样回归三项指标通过。

3. 解除 `app/stages.py:9822` 的 `no_episode_hook` 恒真，让剧本阶段可以合法铺设集尾钩。
4. `episodes.synopsis` 保持为展示字段（现有约定：禁止作为分镜依据）。

**验收**：连续三集成片里，第 N 集结尾与第 N+1 集开场存在可指认的承接关系；盲审的「能否理解上一集发生了什么」项提升。

### P0-7｜把人声从视频模型里剥离出来 → D8

- **方案 a（推荐）｜引入 TTS**：按 `voice_bible.speaker_id` 绑定固定音色，视频提示词的 `AUDIO TIMELINE` 语义从「说出这句台词」改为「按这句台词做自然口型，**不出声**」，人声在 `app/final_edit.py` 混入。这与 A9（画面文字不交给视频模型）是完全同构的架构决策。

**前置**：方案 a 会改变 `_compile_audio_timeline` 的输出语义（`app/compiler.py:800`），必须先跑金样回归。口型对齐依赖 `audio_timeline` 的 `start_s/end_s`，该结构已存在。

**验收**：同一角色跨镜音色主观一致性评分；方案 a 下口型对齐误差 ≤150ms。

### P1-1｜光照推进轴（Lighting Arc）→ D11

3. `app/compiler.py:923-926`：不跨弧段时仍写「光照保持 X」；跨弧段时改写为「光照由 X 连续过渡到 Y」。
4. 与 P0-4 第 6 点联动：有了 `lighting_arc`，同地点的时间推进不必再断链。

### P1-2｜让情绪曲线进入视听层 → D12

1. `emotional_curve` 从自由文本升级为结构：`[{beat_range, tone, palette_hint, tempo_class}]`，`tempo_class` 直接喂 P0-5。
2. 新增 `visual_style_variant`：在全局 `visual_style_canonical` **之外**按段给出**色调偏移串**——这正是对照 A「通用尾缀 A / B」的工程化。
3. `compile_prompt` 的 `CONSISTENCY` 段注入本镜所属段的 `palette_hint`。
4. **边界写死在校验里**：变体只允许改**色温、饱和度、对比度、光比方向**四类词，**不得改动美术风格串本身**（否则破坏 A2/A3 建立的跨集一致性）。
5. 度量层加一条：整集 `readability_focus` 分布。

**验收**：同项目内可观察到分段色调差异；跨集角色/场景一致性指标**不下降**（硬约束）。

### P1-3｜轴线正向合同 → D14

### P1-4｜场景声床锚点（Ambience Canonical）→ D15

## 7. 本轮明确不做

按 `CLAUDE.md` 要求先冻结不实现的范围：

1. **不引入 15 秒原生多镜头模式（对照 B 路线）进入主链路。**
   理由：多镜头让模型在一个片段内部自行切镜，会同时废掉四项核心资产——真实尾帧链（切点在片段内部，拿不到）、`required_text` 的确定性文字插入（不知道文字该出现在第几个内嵌镜头）、`audio_timeline` 的精确时序、逐镜 `continuity_state` 合同。
   **但它确实是 D2 的另一条解法**（把切点挪进生成边界内部），建议作为**独立实验分支**评估，优先用于动作段与预告片物料。
2. **不做自动配乐。** 只在交付包留出分轨。
3. **不实现 `production_quality_mode`（draft/final 两档质量预算）、道具资产库（`story_props` 等四张表）、PRD §13.3 的七个 API 与 §14 的三处页面。** 这些都是《成片质量》PRD 的未落地项，与本报告主题相关但属于独立工作量，本轮不铺开。
4. **不更换 provider、不引入新框架、不重写 `app/stages.py`。**
5. **不改动叙事蓝图 / 剧本 IR 的来源覆盖合同**（`source_coverage`、SRC ownership）——那是「禁止静默删戏」的保障，与本议题正交。
6. **不因为节奏优化而放宽任何一致性门禁。** 一致性是本项目相对纯 AI 方案的核心壁垒（§2），P1-2 已把这条写成硬约束。

## 8. 验收方法

**回归门禁**（沿用 `docs/PROMPT_SPEC.md` §F）：任何提示词改动先跑 `golden/` 三本小说的 A→B→C 链，结构合法率不降、修复回路次数不升、总耗时不升 20%。结果留档 `golden/runs/<date>.json`。

**新增节奏与衔接指标**（写进 P2-1 度量看板）：

| 指标 | 当前基线 | 目标 |
|---|---|---|
| 均镜长 | 6.0s（`golden/renderability/doupocangqiong_ep1_baseline.json`） | 7.5~8.0s |
| 单集生成边界数 | 24（同上） | 下降 ≥25% |

| 单集 `scene_change` 次数 | 无度量 | 建立基线后设阈值 |

| `BOUNDARY_*_RELATION_INVALID` 命中数 | 恒 0（常量占位符） | >0 且与切点报告相关 |

**双轨基准**：按 `README.md` 既有要求，新旧链路需在三个不同真实项目上通过，指标经 `/api/benchmarks` 录入、`/api/benchmarks/release-gate` 判定，不在仓库里伪造。
