# 单租户账号、空间隔离与权限体系

## Context

MJAgent2 目前是一个**单人本地产品**：功能完整，但没有任何身份概念。这不是疏漏，是当初的设计前提——`PRD/项目空间、观测台与系统设置解耦重构PRD.md` §4.3 明确写着「不引入多租户、成员、权限角色」，"空间"只是本地单人产品里的小说容器。

问题是这个前提已经不成立了：应用现在跑在公网 `https://43.153.78.247/` 上。当前状态下，**任何能访问这个地址的人都是超级管理员**——可读写全部项目、导出模型 API Key、改全局预算、删库。`PRD/2026-07-27_代码审查安全漏洞与垃圾代码Todolist.md` 里 T9（`/media` 鉴权）至今未做，而它的验收条件原文就是「文档禁止 `--host 0.0.0.0` 公网暴露」——现在恰恰违反了。

本期把它做成**完整的单租户多用户系统**：账号、工作空间隔离、五档角色、系统设置门禁，并一并堵掉公网暴露面。同时给未来的多租户与运营端留**加法式**接口，不做现在用不上的抽象。

## 现状事实（已核实，作为设计前提）

**认证**：`app/local_session.py` 是**一个进程级共享密钥**（`data/local_session_secret.txt`），永不过期、不区分人。`GET /api/session` 无鉴权下发它。`require_local_session`（:129）已作为 router 级依赖挂在全部 `/api/*` 上（`app/main.py:196-203`）——**闸门在，身份不在**。未鉴权面：`/api/session`、`/api/system/health`、**`/media/*` 全树**、SPA 外壳。

**已有授权原语（必须复用，不要重造）**：
- `app/capabilities/catalog.py`：62 条命令，60 条带 `rest_routes`。每条 `CommandSpec` 已声明 `scopes`、`risk`(R0–R3)、`confirmation`、`admin_only`。
- **6 个 scope 已存在且 MCP 已在用**：`manju:read`(1) / `project-write`(21) / `generation-text`(12) / `generation-media`(18) / `delivery`(5) / `admin`(8)。
- **`admin_only` 不是死字段（初稿此处措辞有误）**：它在 3 处真实生效，专门把 7 条命令挡在**非人类调用方**之外——`app/mcp/tools.py:62`、`app/agent/orchestrator.py:185`、`registry.py:192` 的 `list_mcp_tools()` 过滤。已核实这 7 条 `mcp_exposed` 全为 False，`admin_only AND mcp_exposed` 为空集。**缺的是对「浏览器会话」这一人类调用方的角色校验**——因为此前根本没有用户身份。
  → 因此本期只能**新增**一层 REST 角色要求，**绝不可改写 `admin_only` 的语义或拿它当 RBAC 角色标记**，否则会把这 7 条从 Agent/MCP 的排除名单里漏出去，等于让 LLM 或外部 MCP 客户端能改模型配置与凭据。
- `CommandBus._run_pipeline`（`app/capabilities/bus.py`）已把 `session_id` 串到 `_gate()`，但**全程无 scope/角色判断**；scope 检查只在 MCP 路径（`app/mcp/auth.py`）。
- `app/capabilities/coverage.py::build_coverage_report()`：**137 条写路由 / 79 走 Bus / 58 显式豁免（每条有书面理由）/ 0 遗漏**，已有 `assert_full_coverage()` 可扩展为回归守卫。
- **`_assert_scope` 已存在**（`app/observability/api.py:1986/2033/2078/2129`），在 `/api/projects/{id}/observability/*` 下已正确使用——现成的隔离范式。

**决定隔离方案的关键约束**：
- 全仓 **361 处直接 `SELECT ... FROM projects/episodes/shots WHERE id=?`，分布 47 个文件**；而 `_project_or_404`/`_episode_or_404`（`app/domain/common.py:124-148`）只有 103 处调用。
  → **在数据访问层加 `AND owner_id=?` 会漏掉约 360 处。隔离必须在 HTTP 边界一次性完成。**
- 路径参数高度规整，可集中解析：`{project_id}`65 / `{episode_id}`51 / `{shot_id}`15 / `{run_id}`12 / `{artifact_id}`10 / `{job_id}`6 / `{version_id}`4 / `{call_id}`4 / `{package_id}`2；`{scene_name}`/`{character_name}` 恒嵌套在 `/projects/{project_id}/` 下。34 条路由无路径参数。
- **媒体路径第一段恒为 project_id**（`_media_url` 一律相对 `PROJECTS_DIR`，`app/domain/common.py:640-646`）→ `/media` 鉴权只需解析首段。
- Starlette 1.6.0 的 `FileResponse` **支持 Range**（实测 `206 Partial Content`）→ 换掉 `StaticFiles` 挂载不会破坏视频拖动。

**本期必须堵的越权面**：
- `PUT /api/keys`、`PUT /api/models/{id}/credentials`：**明文写 provider API Key，完全不走 Bus**，仅靠请求体客户端自填的 `confirm: true`。
- `DELETE /api/episodes/{id}`：不走 Bus、无确认字段。
- `POST /api/system/jobs/{id}/retry`：目录注释写「只限本机管理员」，**无强制**。
- 跨项目泄漏：`GET /api/runs/{run_id}`（**完全无归属校验**）、`/api/runs*`、`/api/system/jobs*`、`/api/system/calls*`（可下载原始请求响应体）、`/api/system/overview`、`/api/gates`。

**数据层**：手写 SQLite，**无 ORM、无 Alembic**。`app/db.py` 巨型 `SCHEMA` 串 `executescript`（:2244）+ `MIGRATIONS` 元组（~150 条 `ALTER TABLE ADD COLUMN`，:1315+），靠吞 "duplicate column name" 幂等（:2245-2250）。67 张表。`new_id(prefix)` 在 `:2495`。`_delete_project_evidence`/`_delete_project_core`（`app/domain/projects.py:920-1132, 1476-1529`）是现成的「一个项目底下有哪些东西」权威遍历。

**迁移规模**：当前库里 **1 个项目 / 1616 集** → 回填是单行操作。

**依赖现状**：`requirements.txt` 只有 fastapi/uvicorn/httpx/pydantic/python-multipart/Pillow。**没有 passlib、argon2、bcrypt、itsdangerous、jose**。stdlib 的 `hashlib.scrypt`/`secrets`/`hmac` 可用。→ **口令哈希用 stdlib `hashlib.scrypt`，会话用自签 HMAC token，零新依赖**，符合 CLAUDE.md。

**测试面**（决定改造风险）：195 个测试文件，**只有 12 个用 TestClient**，13 个直接碰 Bus。`tests/conftest.py` 已有 `session_headers()`（:277）与 `SessionTestClient`（自动附加会话头）、autouse 的 `_reset_capability_runtime`（:237）。→ **改造点集中在 conftest 两处**。

## 设计

### 1. 数据模型

新增 4 张表 + `projects` 加 1 列。追加进 `app/db.py` 的 `SCHEMA` 串（`CREATE TABLE IF NOT EXISTS`，与现有风格一致），列变更进 `MIGRATIONS` 元组。

```sql
users(id PK 'usr_*', username UNIQUE, display_name, password_hash,
      is_system_admin INT DEFAULT 0, status 'active|disabled',
      must_change_password INT DEFAULT 0, created_at, last_login_at,
      auth_provider TEXT DEFAULT 'local', external_subject TEXT)  -- 末两列=OIDC 接缝，本期只写 'local'
workspaces(id PK 'ws_*', tenant_id TEXT NOT NULL DEFAULT 'default',  -- ← 多租户接缝
           name, created_at, created_by)
workspace_members(workspace_id, user_id, role, created_at, PRIMARY KEY(workspace_id,user_id))
user_sessions(id PK, user_id FK, token_hash UNIQUE, created_at,
              expires_at, last_seen_at, revoked_at, user_agent, ip)
-- ALTER TABLE projects ADD COLUMN workspace_id TEXT
```

`password_hash` 格式 `scrypt$n$r$p$<salt_b64>$<hash_b64>`，自带参数便于日后提升成本因子。

**回填与引导**：`init_db()` 末尾加一次性引导——若 `workspaces` 为空则建 `ws_default`（`tenant_id='default'`），把所有 `workspace_id IS NULL` 的项目挂上去。首个管理员由 **`scripts/create_admin.py`** 交互式创建（或读 `MJ_BOOTSTRAP_ADMIN_USER`/`_PASSWORD` 环境变量，仅当 `users` 为空时生效），落地后必须改密。

### 2. 认证

新增 `app/auth/`（`passwords.py` / `sessions.py` / `principal.py` / `api.py`）。

- `POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`、`POST /api/auth/change-password`。
- 会话 token = `secrets.token_urlsafe(32)`，**只存 SHA-256 哈希**（与 `app/mcp/auth.py` 现有做法一致）。默认 12 小时滑动过期，`last_seen_at` 续期。
- **继续用 `X-Manju-Session` 头**，不改协议，前端 `api.ts` 与 `SessionTestClient` 都不用动传输层。SSE 的 `?session=` 沿用（T10 的一次性 ticket 不在本期）。
- **保留现有同源闸门**：`origin_allowed()` 原样保留并前置于身份校验——CSRF 防护与身份认证是两层，都要。
- `require_local_session` 改为 `require_principal`：解析 token → 查 `user_sessions` → 组装 `Principal(user_id, is_system_admin, workspaces={ws_id: role})` 存入 contextvar（复用现有 `bind_verified_session` 的 contextvar 机制）。
- **过渡期双认**：环境变量 `MJ_LEGACY_SHARED_SESSION=1` 时仍接受旧共享密钥并映射为引导管理员。默认关闭，仅供分阶段上线，最后一阶段删除。

### 3. 授权：两层，职责不重叠

**(a) Command Bus 层（权威的"能不能做这个动作"）** — 覆盖 79 条写路由 + 全部 MCP。

在 `CommandBus._run_pipeline` / `_run_pipeline_async` 中，**紧接 `spec = self.registry.get_command(name)` 之后**（`app/capabilities/bus.py:166`）插入 `_authorize(spec, principal)`。

> ⚠️ 位置必须在这里，**不能放到 `_gate()` 旁边**：`_gate` 在幂等缓存查询（`idem_store.lookup`，:177-186）**之后**。若授权晚于幂等查询，一个无权用户发同样参数的请求会**直接命中有权用户的缓存结果**并拿到数据——绕过鉴权。授权必须早于任何返回数据的分支。

判定：
- `spec.admin_only and not principal.is_system_admin` → 拒绝
- `spec.scopes ⊄ principal.scopes_for(target_workspace)` → 拒绝
- 拒绝返回 `CommandResult(REJECTED, reason='forbidden')`，`dispatch.respond_ui` 映射为 **403**。
这一处改动让 `admin_only` 和 `scopes` **第一次真正生效**。

**(b) HTTP 边界层（权威的"这条数据属不属于你"）** — 覆盖 58 条豁免写路由 + 全部读路由。
一个 router 级依赖 `require_access`，从 `request.path_params` 解析归属并校验成员资格。

> 挂载点被架构**强制**在 `app/main.py:197-202` 那 6 处 `include_router(..., dependencies=[...])`：`app/api.py` 用 `exec()` 把 7 个 domain 文件塞进同一命名空间，它们**共用 `domain/common.py:50` 那一个 `APIRouter`**，没有任何 domain 文件自己声明 router。所以「只给项目级路由挂依赖」在物理上做不到——这不是取舍，是既有结构的结果，也正好与「不在 137 条路由上逐个加 Depends」一致。

**失败码用 404 而非 403**：跨空间访问一律返回 404，与既有约定一致（`tests/test_project_observability.py:133/149/169/194/508` 都断言外项目返回 404），也避免用 403 泄露「这个 id 确实存在」。403 只用于「资源你看得见、但角色不够」。

两层不冲突：**边界层只管归属（哪个空间），Bus 只管动作（哪个 scope）**。

豁免路由不进 Bus，其所需 scope **直接扩展现有的豁免登记表**，不另建结构：`registry.rest_exemptions` 现在是 `dict["METHOD /path" → reason]`（`app/capabilities/registry.py:136,172-176`），把 `exempt_rest(route, reason)` 扩为 `exempt_rest(route, reason, *, scopes, admin_only=False)`，值改为带 scope 的记录。58 条豁免逐条补声明——它们本来就每条都写了书面理由，补一个 scope 是同一处的自然延伸。

**读路由（GET）不在 coverage 范围内**，无需逐条登记：边界依赖对 GET 缺省要求 `manju:read` + 空间成员资格即可。

**角色 → scope 映射**：

| 角色 | scopes | 备注 |
|---|---|---|
| 系统管理员 | 全部 + `manju:admin` | 唯一能进模型中心/系统设置/MCP token/全局观测 |
| 空间管理员 | read, project-write, generation-text, generation-media, delivery | **不含 `manju:admin`**；额外可管本空间成员 |
| 制作 | read, project-write, generation-text, generation-media | 不能交付审批 |
| 审校 | read, delivery **+ 人工决策白名单** | 见下方修订 |
| 只读 | read | |

> **修订（初稿此行是错的）**：初稿写「审校 = read + delivery」。**这会让审校干不了审校的活**。实测这 6 个 scope 是**按资源种类切的，不是按角色切的**：
> - `storyboard.confirm`（解锁付费视频的人工门）→ `manju:generation-media`
> - `video.adopt_version`（定稿采纳）→ `manju:project-write`
> - `reference.review`（参考图验收）→ `manju:project-write`
> - `manju:delivery` 实际只覆盖 5 条交付包命令（`delivery.check/concatenate/create_package/review/submit_feedback`）
>
> 只给 `read+delivery`，审校将**无法确认分镜、无法采纳视频版本、无法验收参考图**。
>
> **方案**：在 `_authorize` 里的 scope 判定**之前**加一个短白名单 `_HUMAN_GATE_COMMANDS = {storyboard.confirm, video.adopt_version, reference.review, video.stop_shot, video.stop_episode}`，审校对这几条放行。**不要**改走「给审校补 generation-media」的粗放路子——那会顺带把 `video.generate_shot`（发起新的付费生成）也放开，与「审校只做决策不发起生成」的语义相悖。白名单是精确的，且日后收紧审校基础 scope 时不会误伤。
>
> 拆分 `manju:generation-media` 为「发起」与「决策」两个子 scope 是更干净的解，但那是 P2，本期不做。

### 4. 隔离：边界解析器

`app/auth/resolve.py` 一张 `param → 归属项目` 解析表，按请求缓存：

|---|---|
| `project_id` | 自身 |
| `episode_id` | `episodes.project_id` |

**集合类端点**：

### 5. `/media` 鉴权

> **修订（初稿此节是错的）**：初稿写「`require_principal` → 校验成员资格」。**这在结构上就跑不通**——前端媒体一律是裸 `<img src={...}>` / `<video src={...}>`（`WallPage.tsx:471,1584`、`BiblePage.tsx:1883`、`ScenesPage.tsx:1212`），浏览器**不会给 `<img>`/`<video>` 请求附加自定义头**，`X-Manju-Session` 根本到不了服务端。凡是能保护 `/api` 的头部方案，都保护不了 `/media`。

**改用查询串里的签名票据**（唯一能被浏览器原样带回来的载体）：

1. **先收敛 URL 生成点**。当前有 **7 处**各自拼 `f"/media/{rel}?v=..."`：`app/domain/common.py:646`、`media_exec/concat.py:253,759,815`、`domain/projects.py:718,731`、`domain/storyboard_ops.py:4351`（这处连 `?v=` 都没有）。合并为单一 `app/media_urls.py::build_media_url()`——**不先做这步，签名一定会漏挂**。
2. 该函数取 `rel_path` 首段为 `project_id`，追加 `mt=HMAC(secret, f"{project_id}|{day_bucket}")[:24]`，`day_bucket = int(time.time() // 86400)`。
3. `/media` 侧校验今日与昨日两个 bucket（容忍跨零点），`hmac.compare_digest`，**零 DB 查询**。
4. 票据在已鉴权的 `/api` 响应里签发——彼时该请求的空间成员资格已由边界层校验过，签发只是「授权已发生」的凭证转印。

> ⚠️ **票据必须按天分桶，绝不能每次请求随机**。nginx 的 `immutable` 长缓存是按**含查询串的完整 URL** 命中的；随机票据 = URL 每次都变 = 缓存全废，600KB 参考图会在每轮轮询重下。这个错误能通过功能测试，然后悄悄毁掉本会话刚做完的全部带宽优化。

**服务实现**：不要手写 Range 解析。复用 `app/main.py:210-239` 的 `SpaStaticFiles` 既有范式——持有一个不挂载的 `StaticFiles` 实例，从鉴权路由里调它的 `get_response(path, scope)`，Range/If-Range/ETag/Last-Modified/416 全部由 Starlette 原样保留：

```python
_media_static = StaticFiles(directory=PROJECTS_DIR)   # 顶掉 app/main.py:207 的 mount

@app.get("/media/{path:path}")
async def serve_media(path: str, request: Request, _=Depends(require_media_ticket)):
    return await _media_static.get_response(path, request.scope)
```
仍需**路径穿越防护**（`Path.resolve()` 后必须仍在 `PROJECTS_DIR` 内）。

**性能**：HMAC 校验是纯内存运算，`?v={mtime}` 与长缓存都不受影响——**初稿担心的「54 张图 54 次 DB」在票据方案下不存在**，无需 TTL 缓存。

**备选（不做）**：`Path=/media` 的 httpOnly cookie 也能解，但会给一个零 cookie 的代码库引入第二套认证传输与 SameSite 模型。留作票据方案不够用时的回退。

**nginx**：`/etc/nginx/snippets/mjagent2-app.conf` 里 `location ^~ /media/` 的 `Cache-Control: public, max-age=31536000, immutable` 改为 **`private`**：`?v={mtime}` 版本号机制不变，长缓存继续有效，只是不再允许共享缓存。（2026-08-25 加域名证书时，应用 location 从 `sites-available/mjagent2` 抽成了这个共用 snippet，域名与 IP 两个 server 块都 include 它。）

**8230 收口**：在腾讯云安全组删除 8230 入站规则（无需重启，推荐），或设 `MJ_BACKEND_HOST=127.0.0.1`（`scripts/dev.sh:137` 默认 `0.0.0.0`）后重启后端——后者受 backend 无托管的约束。

## 已知陷阱（会比看起来难的地方）

1. **不要试图在数据层做隔离**。361 处直接 `WHERE id=?` 意味着补 `AND workspace_id=?` 是个无底洞，且漏一处就是越权。边界一次性拦截才是可审计的。
2. **授权必须早于幂等缓存**（见上）。`command_idempotency` 的 PK 是裸 `idem_key`、无空间命名空间；虽然 `lookup` 会校验 `request_fingerprint`（参数不同不会命中），但参数相同的跨用户重放仍要靠授权前置来挡。
3. **`/media` 用不了头部鉴权**（本计划最难的一点，见 §5）。`<img>`/`<video>` 不带自定义头，凭证只能进查询串。且票据**必须按天分桶**——随机票据会让 `immutable` 长缓存全部失效，26 MB 的场景库图片每轮轮询重下，悄悄抹掉本会话刚做完的优化。
4. **"工作空间"这个词已经被占用了**。`PRD/项目空间、观测台与系统设置解耦重构PRD.md:124-125` 明确定义「项目空间 ≡ 工作空间 ≡ 一部小说」，前端 `/workspaces` 路由指向的就是项目列表（`Studio.tsx`）。新的租户边界实体如果在 UI 上也叫"工作空间"，会和既有产品词汇正面冲突。**建议 UI 文案用「团队」，代码与 API 保留 `workspace`**；角色名「空间管理员」保持不变（用户已定），但在界面上下文里配「团队」这个名词出现。
5. **`app/api.py` 的 `exec()` 门面**决定了依赖只能挂在 router 级（见 §3b），不是可选项。
6. **六个 scope 是按资源种类切的，不是按角色切的**——直接拿它们拼角色会让审校干不了审校的活（见 §3 修订）。
7. **`admin_only` 现在是死字段**。给它加强制会**立刻改变 MCP 与 Agent 的行为**（那 7 条命令目前对持有 token 的 MCP 客户端是可调的），需要同步复核现有 MCP token 的 scope 分配。
8. **`provider_calls.project_id` 是启发式回填的**，历史行可能为 NULL；`agent_conversations.project_id` 本就可空。这两类对象的归属判定必须有明确的兜底（NULL → 仅系统管理员 / 仅创建者），不能默认放行。
9. **`verify.py` 当前就是红的**——`ruff` 未安装，Python lint 段直接 exit 1。开工前先装，否则每阶段都无法用它验收。

## 验收方法：绕过产品的操作即功能缺口的指纹

这轮改造里有 4 个缺陷不是靠代码审查发现的，而是靠三层验证手段，检出成本依次降低：

1. **跑一遍验证步骤**（抓「预期与实际不符」）——发现 `must_change_password` 从未被强制、
   `workspaces.status` 是摆设、停用团队后仍显示在登录载荷里。这三处读代码都看不出来：
   读的时候会觉得"过滤已经加了"，因为确实加了，只是加在另一个函数里。
2. **回看验证记录**（抓「验证手段本身不合法」）——发现停用团队只能改库。当时只顾着验
   收权逻辑对不对，没意识到「我必须绕开产品才能验证这个功能」本身就是结论。
3. **机械扫描验证脚本**（把第 2 步自动化）——列出所有没走 HTTP API 的操作，逐个问
   "用户怎么做这件事"。不需要语义判断，成本最低。

**第 3 步的产出必须逐条裁决，不能默认合理。** 本项目的扫描结果：4 处绕过中 1 处是真缺口
（已补停用团队接口），3 处是有意为之（引导首个管理员、不提供删除只提供停用、服务账号
凭证签发暂缺），裁决与理由记在 `app/auth/admin_api.py` 模块文档里。

配套的测试规矩写在 `tests/test_rbac_enforcement_evidence.py` 文件头：**断言一律是「做一次
真实操作看它是否真的被挡住」，不许写成「检查某字段等于某值」**——后者正是让上述三处缺陷
在代码审查里全部通过的原因。

变异测试还暴露一个推理推不出的事实：把重复真源收敛掉之后，一致性断言对单点回归就失效了
（两边一起错，无分叉可测）。所以行为断言与一致性断言互补不可替代——前者抓「规则没被
强制」，后者抓「两处实现分叉」。

## 最终收口的执行步骤（三个开关）

**为什么写进 `.env` 而不是 export**：后端由多方按各自规程重启，进程环境不可控（实测当前
进程里根本没有任何 `MJ_` 变量）。`app/config.py:_load_env()` 在 import 时把 `.env` 逐行
`os.environ.setdefault` 进环境，而两个开关都是**调用时**读 `os.environ`，所以写进 `.env`
的值对任何人发起的重启都生效。已实测验证：`.env` 里的值确实进了 `os.environ`；
`MJ_LEGACY_SHARED_SESSION=0` 确实让 `legacy_shared_session_enabled()` 返回 False。

**前置条件（缺一不可）**：回归驱动脚本已切到 `data/regression_session_token.txt` 并实跑
验证过（至少一次 `status` 读 + 一次带两段式审批的写）。**不满足就不要翻**——旧共享密钥
是那些脚本当前唯一的凭证。

```bash
# 1. 两个开关写进 .env（对任何人的重启都生效）
printf 'MJ_LEGACY_SHARED_SESSION=0\nMJ_MEDIA_REQUIRE_TICKET=1\n' >> .env

# 2. 重启后端加载（与他方协调窗口；本机无托管，须手工重启）

# 3. 关闭 8230 公网入口 —— 二选一
#    a) 腾讯云安全组删掉 8230 入站规则（推荐：不动进程，nginx 走 127.0.0.1 不受影响）
#    b) MJ_BACKEND_HOST=127.0.0.1 + 重启（scripts/dev.sh:137 默认 0.0.0.0）
```

**验收**：无凭证 401、管理员登录 200、旧共享密钥**应当变成 401**（这条是翻成功的标志）、
服务账号 token 200、跨团队媒体 URL 403、同团队媒体 200 且 Range 请求仍 206。

**回滚**：把 `.env` 里 `MJ_LEGACY_SHARED_SESSION` 改回 `1` 并重启，约两分钟。不改代码、
不动数据。回滚成本低是刻意设计的——正因为退得回来，才不必为了保险无限推迟。
