验证日期：2026-09-09。调试、数据库检查、前后端发布均在本机完成。

本次修复覆盖原文归属、分镜合同、视频输入、单段修订和历史证据展示。用户反馈的另一台电脑上的《我欲封天》第五集成片尚未取得，因此下述结论是代码和本地回归验证结果，不代表已对那份成片逐镜验收。

## 方案预设与代码事实

| 核对事项 | 已确认的代码事实 | 最终落地方式 |
| --- | --- | --- |
| 说话人与旁白为什么会错位 | 旧逻辑允许必保台词使用旁白绕过人物归属；还会把未带引号的角色画外音改成旁白，提示词只尝试替换一种标签形态 | 归属冲突明确报错；显式 OS/VO 和原文说话人优先；台词与提示词共同修订 |
| 听者为什么会被当作说话人 | 原先的归属启发式包含点头、皱眉等反应；连续引句、长台词拆分及片段裁剪会丢失后面的听者上下文 | 缩小发声证据范围；裁剪前保留整个对话块的听者排除证据，并随原文引用传入分镜生成 |
| 同一称谓为什么会借到别人的身份 | 称谓映射曾按整集字典取值，缺少原文段号约束；重复别名按先后顺序占用 | 按原文范围解析称谓；多人候选明确提示歧义；注册群演身份独立保留 |
| 是否只要修改展示的人名即可 | 台词、人物资源、实际图片选择和视频幂等复用由不同消费者读取 | 同一身份规范化结果驱动各消费者；提交前校验；片段身份指纹进入复用键与执行阶段校验 |
| 群演是否必然没有角色卡 | 原选图逻辑按名字查卡，不区分独立群演、声音主体和可见角色；模型自报正式角色也需要核验 | 显式区分角色、独立群演、人群及可见性；正式角色资格来自当前素材身份清单；群演和仅声音主体不选角色图 |
| 是否可以直接复用自动成片质检 | `run_auto_qa` 明确说明 VLM 视觉质检已经下线 | 增加按视频版本保存的人工视听复核记录、实际提示词及参考图展示；本次没有恢复自动 ASR/VLM 判定或自动重抽 |
| 留存素材顺序是否等于提交顺序 | 本地真实版本中，候选素材列表是“孟浩、山顶”，实际提交标签是“山顶、孟浩” | 按提交时的图片编号展示；不能唯一定位或缺少提交顺序的历史记录明确说明，不猜测 |

## 使用方式与数据范围

1. 进入分镜台，选中问题片段，点击“复核说话人和群演”。
2. 旧片段先点击“仅重新编写本段（调用文本模型）”。模型只生成该段候选，复用既有规划和相邻片段；候选生成不会覆盖已保存分镜。
3. 核对每句说话人、发声方式和出镜人物。需要时补充独立群演，并修订镜头稿；台词位置标记保留在实际发生的镜头中。
4. 点击“校验并预览修订”，检查系统展开后的实际声道标签、台词与口型说明，再保存本段修订。继续编辑会撤销此前预览状态。
5. 保存仅更新该段，旧视频保留为历史版本，其他段保持不变。当前片段若有未结束的视频任务，需要先在生成台处理该任务。之后可在生成台生成该段的新视频。
6. “成片与实际提交记录”可切换历史视频、查看当时的提示词和实际参考图编号，按视频版本保存视听观察。保存观察不会自动重抽。

修订使用写事务及片段指纹比较，防止覆盖别人的较新修订。证据写入失败会回滚；旧视频文件保留。修订后的旧采用结果失效，整集交付权威同步失效。已提交供应商的任务仍可走原有查询回收路径，不能因片段变动再次付费提交旧合同。

新合同使用 `segment_identity/1.0`，未全局提升既有分镜包版本。旧数据不会仅因缺少新字段就全部失效；确定性冲突会指向当前片段修订入口。未执行批量数据迁移，也未重生成用户的历史视频。
