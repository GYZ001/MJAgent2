## 0. 结论先行

对话的核心判断是：**模型决定天花板，方法论决定离天花板多近**。今年模型能同时吃多张参考图，「把一致性当资产管理来做」这套老方法才真正兑现。它点名的具体做法里，最关键的一条是：

> 「反打视角是防穿帮的关键。在生成反打镜头之前，一定要先有这个视角的场景参考图」
> ——腾讯云开发者社区《AI真人短剧是"管"出来的》，2026-06-24（对话引用的方法论来源，逐字核对）

对照本仓，这一条正是我们最实在的缺口，而且缺得比想象的深：

1. **反打场景图白生成了。** B 上 152 个场景都生成了「反打视角」图，但 9 月以来 421 个成功生成的视频版本里，一张都没用上。每段只带角色正面全身图和场景主视角图。
2. **反打图本身就是假的。** 抽查 8 个项目各一组，没有一张真正朝向相反方向：它们都是主视角图的轻微位移或拉远。颁奖现场那组本该从舞台看向观众席，实际仍然看向舞台。

所以现在一场对话戏正反打时，视频模型只拿到一个方向的场景图，另一个方向的背景只能现编。对话里说的「一整集仍会在空间关系上穿帮」，在我们这里有明确的结构性成因。

按优先级排，建议做五件事：

| 优先级 | 做法 | 花不花视频额度 | 状态 |
|---|---|---|---|
| **P0** | 反打场景图做实并接进视频请求 | 修图只花图片调用；验证随正常生产 | 新发现，建议立即做 |
| **P0（需拍板）** | 查证并评估 Seedance 2.5 | 查证零额度；试用一集随正常生产 | 需你查 HiAgent 控制台 |
| P1 | 台词语气具象化（语速、停顿、音量） | 零额度，随正常生产观察 | 新增 |
| P1 | 生成台「带意见重拍」（09-23 方案 P0-4，至今未做） | 功能本身零额度 | 对话里「可用率高了精修才划算」的论证提高了它的优先级 |
| P2 | 短剧档补节奏检查点，并配确定性核验 | 零额度 | 加强已上线的短剧档 |

角色多视角参考（四视图、面部特写）行业在做，但本仓有「同一人多张不同尺度的图易出分身」的实测记录，**不建议在 Seedance 2.0 上直接加**，放到 2.5 评估里一起试（见 §3）。

## 2. P0：反打场景图做实并接进视频请求

### 2.1 现状取证（B 生产库只读，2026-09-26）

**视频请求实际带了哪些图**（`shot_versions.image_inputs.reference_images`，2026-09-01 起成功的 421 个版本）：

| 素材 | 次数 |
|---|---|
| 角色 · 正面全身（front_full） | 710 |
| 场景 · 主视角（establishing） | 414 |
| 道具 | 298 |
| 上一段画面 | 21 |
| 角色侧面 / 四分之三侧面 / 场景反打 | **0** |

每个版本带 1–9 张图，多数是 2–5 张；Seedance 2.0 上限是 9 张（`app/video_modes/mode_selection.py:151`），名额是有富余的。

**库里已生成的视角**：场景主视角 152、场景反打 152；角色正面、侧面、四分之三侧面各 103，状态全是 ready。

**代码里为什么没用**：
- `app/multiview.py` 的 `select_scene_view_roles` 恒返回 `["establishing"]`。
- `app/video_modes/asset_lookup.py` 取场景图时优先主视角，取角色图时优先正面全身，每个实体只取一张。
- 按反打关键词选图的逻辑，2026-07-26 在 `ec3c550a` 里加入，2026-08-09 被一次自动提交 `360270f3` 删掉，没有留下理由。
- 2026-08-23 的《视频衔接与叙事推进优化报告》第 300、453 行已经指出「库里明明存了 reverse_angle 场景视角，反打镜却拿不到」，但没有落地。

**反打图本身不合格**：抽查修表铺、宠物医院诊室、炸串摊、地铁车厢、山路、消防通道、小区楼道、颁奖现场 8 组，没有一组是真正的反向视角：
- 修表铺的「反打」只是在同一画面外加了一圈门框。门外的街道仍出现在画面深处，几何上不可能。
- 诊室、山路、颁奖现场几乎与主视角一样。

原因在生成方式：`app/multiview.py:1494` 起，反打图是以主视角图作种子图做图生图，文字要求「与建立视角相对的反打方向……禁止简单复制原构图」。图生图天然保留原构图，而原画面背后的那面墙长什么样，任何输入里都没有写。第 1533 行注释写明「技术产物存在即 ready……不再等待 VLM 评审」，所以从来没人发现它不合格。这正是 CLAUDE.md 里「模型答不出来时，先查它有没有收到标准答案」的情形。

### 2.2 改法

分三步走，每一步单独可验证：

1. **把反打图做实**（映射台，只花图片调用，不花视频额度）。
   - 先用文本模型根据场景设定与主视角图的描述，写出「原机位背后那一侧」有什么：墙面、门窗、陈设、光源方位。文本调用不计费。
   - 再生成反打图。主视角图降级为「材质与画风参考」，不再作构图种子；具体用法取决于图像接口是否支持多图参考。
   - 验收挂在「这张图是不是真的朝向反方向」这件事本身上：给一个只答是/否的视觉判定（对应 09-23 前沿方案 P1-4「已标定的二值视觉检查」），先在已有的 152 组上人工标定判定准确率，再决定是否作为闸门。
   - 不合格的不标 ready。
2. **让分镜模型按镜头指定用哪张场景图**（分镜台）。
   - 在段资源里同时给出主视角与反打视角两张场景图，由分镜模型在每个「镜头N」里写明用哪一张。
   - 代码只核验它引用的图确实存在于本段资源中，即模型提名、代码核验，不回到按「反打/对视/对话」关键词选图的老路。
   - `seedance_reference_notes` 给两张图分别写清用途，例如「@图片4：修表铺反打方向，从门口朝柜台里侧看」。
   - 规则要写进 `storyboard_dialects.py` 的 Seedance 与 H3 两块方言：进视频模型的规则在方言里，不在 `compiler.py`。
3. **验证**：随正常生产的对话戏集数顺带观察，对照组用同项目已采纳的旧版本。看两件事：
   - 正反打两个方向的背景在一场戏内是否前后一致，门窗、陈设方位对不对得上；
   - 有没有因为多一张场景图而出现构图混乱。

### 2.3 风险

- 图像模型可能画不出真正的反向视角。所以第 1 步先在 5 个场景上试做、人工看图，过关再改流水线。
- 多一张场景图可能让视频模型在镜头间来回切场景。所以第 2 步只在分镜确实写了正反打的段里带反打图。
- 已有的 152 张假反打图要重做或作废。重做只花图片调用；如果图片调用有费用，需要先估算。

## 3. P0（需拍板）：查证并评估 Seedance 2.5

### 3.1 事实

| 说法 | 来源 | 核实 |
|---|---|---|
| 2026-07-31 发布；单次最长 30 秒；最多 30 张图、10 段视频、10 段音频参考 | 字节 Seed 官方博客 seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5 | 逐字：「Up to 30 seconds per generation」「input up to 30 images, 10 video clips, and 10 audio clips」 |
| 降低不受控的字幕与背景音乐 | 同上 | 逐字：「minimizes uncontrolled occurrences in subtitles and background music」 |
| 时间戳级局部编辑 | 同上 | 逐字：「timestamp-level control for targeted editing of audio and video content」；发布时写「API access coming soon via BytePlus ModelArk」 |
| 2026-08-07 火山引擎上线 2.5 API | 21 世纪经济报道 m.21jingji.com/article/20260807/herald/2f9b5d6485209070f1d1b56e444d0d61.html | 逐字：「火山引擎宣布正式上线Seedance 2.5 API服务」「最高50个全模态素材参考」「具备更精准、稳定的编辑能力」 |
| API 是否支持 15 秒以下、局部编辑是否对 API 开放 | 火山方舟文档页需要 JS 渲染，取不到 | **未查实** |
| HiAgent 是否已代理 2.5 | 无公开来源 | **未查实**，需要看 HiAgent 控制台 |

### 3.2 为什么值得评估

它直接对着我们已知的三个痛点：
- **画面文字**：09-23 差距分析 G2 说这是「最容易被一眼识破的 AI 感」，字幕闸门拦下的每一次重拍都在花额度。
- **同一集配乐忽变**：B 库实测，龙猫出爪第 6 集有成片的 15 段里，配乐描述有 12 种不同写法，从「acoustic 吉他」到「民谣小调」「钢琴短旋律」「急躁感电子 BGM」。
- **重拍成本**：现在改一处瑕疵要整段 15 秒重拍。

另外，参考图上限从 9 张提到 30 张，§2 的反打图和角色多视角才有足够的名额。

### 3.3 做法

1. **零额度查证**：你在 HiAgent 控制台看有没有 doubao-seedance-2-5，以及单价。我这边不调用供应商接口。
2. **若可用**：按「升级模型版本」的既有流程接入：
   - 探针核对 duration、ratio、resolution 三个字段（曾有不传 resolution 就静默降到 720p 的教训）；
   - 保持段固定 15 秒，明确排除 30 秒单次；
   - 角色固定音色的参考音频要单独确认 2.5 是否兼容。
3. **验证**：不做额外的 ×2 对照（09-23 拍板），拿下一个正常要生产的新集直接用 2.5，与同项目前几集对比。看三项：
   - 画面文字被字幕闸门拦下的次数；
   - 配乐听感是否连贯；
   - 可用率，即首次生成即采纳的比例。
4. **局部编辑**等 2.5 主体验证通过后再单独评估，接到生成台的重拍入口上。

## 4. 其余建议

### 4.1 P1：台词语气具象化

- **现状**：`storyboard_dialects.py:110` 已要求「情绪一律写成面部肌肉动作和肢体动作……不写抽象情绪词」，但只管脸，不管嘴。B 上第 8 段实际提示词只有「开口说画内对白（林姐）：“小姑娘，你运气好……”」，语速、停顿、音量一概没有。
- **行业依据**：通义万相官方提示词文档把人声拆成「角色说话的内容＋情绪＋语调＋语速＋音色＋口音」（help.aliyun.com/zh/model-studio/text-to-video-prompt，发布日期不明，作背景）；抖音 2026-05 的 AI 短剧审片标准把「机械配音」列为红线（tvoao.com/a/224167.aspx，媒体转述）。
- **改法**：在 Seedance 对白规则里加一条正面陈述：关键台词在动作链里写可执行的说法，例如「压低声音、放慢语速、一字一顿地说」，而不是「愤怒地说」。H3 方言同步加。措辞避开已知的合规拒收触发词。
- **风险**：语气描写对带参考音频的固定音色是否起作用，没有验证过。随正常生产观察，不能改完文本就当生效。

### 4.2 P1：生成台「带意见重拍」（09-23 方案 P0-4）

- 这一项在 09-23 已列为 P0，git 记录里至今没有落地。
- 对话的论证给了它新的理由：模型可用率上来以后，「精修一个镜头」从不划算变成划算，人工精修的主要工作量就在挑片和局部重拍（差距分析 G3）。
- 功能本身不花额度，花额度的是用户每次点重拍。

### 4.3 P2：短剧档补节奏检查点

- **现状**：`storyboard_short_drama.py::short_drama_beat_sheet_rules` 只量化了总时长、段数与节拍保留，没有「开篇冲突点、结尾钩子」这类位置检查。
- **行业依据**：腾讯云文章（2026-03，早于窗口，作背景）写「开篇3秒情绪炸点，10秒内立住角色立场，结尾5秒悬念」；虎嗅 2026-07-03 写「3集内就进入主线」。调研中流传的「每 15–20 秒一次反转」**两处来源都没有这个数字**，不采用。
- **改法**：加正面陈述，同时配一条确定性事后核验，机械统计钩子与反转标记落在第几段。不能只信模型自报：本仓刚在我欲封天 EP3 吃过「模型改标签绕过复核」的亏。

## 6. 看起来很美但不建议做 / 暂缓

| 做法 | 不做的理由 |
|---|---|
| 多候选生成 + VLM 打分择优（best-of-N） | 2026-08-26/29 已下线 VLM 质检，理由是「评分可靠性为 0」（`2704713a`、`a91e43ec`）；每个候选都要花视频额度 |
| 九宫格预览图先行 | 在确定性参考图模式外再加一道关键帧预生成，与 08-26 摘掉 AI 视频模式规划（`05cceae6`）的方向相悖 |
| 单次 30 秒多镜头 | 与「段固定 15 秒」拍板冲突 |
| 首尾帧 / 上一段尾帧衔接 | 已退场；「相邻段重演情节」的放弃理由没有被新证据推翻 |
| 角色多视角直接加进 Seedance 2.0 请求 | `mode_selection.py:213` 记录「多张不同尺度含人物图易触发分身/前景巨人」，默认每人 1 张；放到 2.5 评估里验证 |
| MiniMax H3 因「声画同生」提前 | 它解决的是单次调用内的音画对齐，不是跨段配乐漂移；且不支持参考音频，会让角色固定音色失效 |
| Runway / Gemini / 万相的编辑与动作迁移 | 要新接供应商；局部编辑优先看 Seedance 2.5 自带的 |
| 学术框架（跨镜头记忆库、物理裁判、时空超分、拟音生成等） | 需要自建 GPU 推理，与机器配置冲突；多数没有托管接口 |
| 抖音「AI 标识三处」 | 属于合规，不是画质；另记合规待办，补进 `docs/ai_labeling_compliance.md` |

## 7. 未查实

- 可用率「<20% → 90%+」：出自知乎，本环境访问被拒。
- Seedance 2.5 的时间戳编辑是否对 API 开放。二手报道说的是「局部编辑」，与官方博客的「timestamp-level」是否同一功能不明。
- 2.5 API 支持的最短时长。
