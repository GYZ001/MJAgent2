# 连播失败复盘：失败三元分类 + 修补优先 + 无人值守自愈（2026-09-05）

## 依据
七天数据（B 库）：分镜结构化校验打回 29、映射台运行时错误 33（其中文本模型审核拒答 11；
三个台合计拒答 17）、生成台等待人工 19（S3 上传 500 被判内容拒绝 13、缺参考图反复重试 8、
大模型调用失败判外部终态 5）、连播任务级失败 21；两次整站无响应（事件循环上的同步 sqlite 写等锁）、
两次重启后队列不恢复。归因四类：契约比模型严且拒绝即整集作废；失败分类靠猜、出路靠人；
单写者数据库上跑多写者并发；状态机没有「自愈」态。

## 原则（冻结）
1. 校验错误必须能回答「程序能不能自己修」；能修的不许打回模型，只重问出错的那一段。
2. 失败只有三种去向：可重试（换新任务/延后）、换路（换模型或换措辞模板）、需人。
   无人值守流程里「需人」只能作用于单个镜头/单个集，不能停整条队列。
3. 无结构化信号时默认可重试；「重复出现」只证明任务已终结，不证明内容被拒。
4. 事件循环线程上不做等锁的同步写；写事务不得跨 await。先立静态闸门，再收敛到单写者。
5. 每个后台循环：异常不致死、卡住有超时、状态可从库重建、自愈留痕。

## P0（本轮落地）
- WS1 失败三元分类（app/hiagent.py、app/media_exec/run_job.py、app/harness/model_gateway.py）
  - 1a 无结构化 failure 载荷 → technical + retryable（AUTOMATIC_RETRY），首次失败即换新任务重试，
    重试次数由修复路由分级封顶；只有供应商结构化 category=model_rejection 才是外部终态。
  - 1b 文本模型审核拒答（LLM-REJECTED「不符合安全合规」「公序良俗」）→ 换路：
    settings `text_moderation_fallback_route`（provider:model）非空时按该路由重试一次，
    并在 system 提示前加固定的「文学作品改编分析」框架语；仍拒答才抛出。
- WS2 修补-校验推广到映射台/分镜（app/production/prep_pack/*、app/portraits/*、app/production/storyboard_*）
  - 2a 称谓解析响应条目缺 raw_label → 按候选顺序补齐或丢弃该条并留痕；
  - 2b 身份决议 source_label 重复 → 确定性合并（保留首条，冲突留痕）；
  - 2c 来源证明缺 anchor_phrase → 在本集原文里定位该名称所在句作为锚点；
  - 2d 分镜段落台词与后段必保台词冲突 → 从前段删除该句（预留给后段）。
  每处修补写 `[<STAGE>_REPAIR]` 日志；修不了的仍打回。
- WS3 无人值守自愈（app/media_exec/reference_pool_gate.py、app/refs.py、app/scenes.py）
  - 3a 参考图候选池「本该有却没有」→ 自动补生成一次（定妆照/场景图），再重试装配；仍缺才转人工。
- WS4 数据库写模型闸门（scripts/check_write_across_await.py + tests）
  - 静态检查：async 函数内 INSERT/UPDATE/DELETE 之后、commit 之前出现 await 即报；存量播种基线，
    新增即拒；接入 `scripts/verify.py --full`。线程局部连接同样记「最后一条写语句」供争用日志点名。

## P1（下一轮）
- 连播成片允许「带空洞」：需人的镜头先跳过，成片标空洞，人处理完只补该镜。
- 观测指标：按项目统计「无人工介入出片率」与每集失败根因类别。
- 内容审核换路的措辞模板由数据驱动（记录换路后成功/失败）。

## P2 / 不做
- 数据库收敛到单写者（写队列 + 批提交）：单独排期。
- 非剧情章节在分集规划识别跳过：失败样本来自已删除的集，暂不做。

## 验收
- 每条改动有定向测试；子代理只跑 `-k` 定向测试，全量由主会话在干净 worktree 跑；
- B 上以我欲封天在跑的连播任务为观察对象：等待人工数、整集失败数、争用日志。
