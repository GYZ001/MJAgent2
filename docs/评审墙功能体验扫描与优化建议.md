# 评审墙功能体验扫描与优化建议

> 扫描日期：2026-07-26  
> 扫描视角：首次接触产品、但需要实际完成逐镜评审与视频采用的制作用户  
> 体验评分：1 分=不可用或高风险，2 分=明显难用，3 分=可完成但有阻力，4 分=顺畅，5 分=优秀

## 一、结论摘要

评审墙的基础信息链路是完整的：用户可以切换分集和镜头，查看文字、参考图、视频版本、QA、费用与状态，也具备生成、停止、采用、导出、清空、陈旧资产修复和 Supervisor 补齐等生产能力。

但它目前更像“把后台能力集中展示出来的控制台”，还不是一个足够稳健的“连续评审工作台”。综合体验评分为 **2.8 / 5**。

最需要优先处理的不是增加新功能，而是以下四件事：

1. **评审对象必须稳定**：当前用数组下标保存选中镜头；后台刷新导致镜头增删时，用户会被自动切到另一镜，存在误评、误采用、误清空风险。
2. **流程断点必须有下一步**：未确认分镜、零镜头、无参考图、无视频时，页面经常只展示空白或给出无法执行的提示。
3. **高风险操作必须统一交互**：预算授权、清空、取消 Supervisor、重生成等操作混用了浏览器 `prompt`、`confirm` 和服务端批准弹窗，重复确认、输入校验和取消语义都不一致。
4. **连续评审必须减少重复动作**：切换镜头会强制回到“文字内容”，没有“只看问题镜头 / 待采纳镜头”的筛选，视频对比也不是并排 A/B 对比。

## 二、扫描范围与验证方式

本次扫描包含：

- 从项目中心进入评审墙；
- 分集上一集/下一集、1646 集搜索与远端集跳转；
- 镜头状态轨、上一镜/下一镜、快速定位；
- 文字内容、参考图、视频对比三个标签；
- 生成、重生、停止、采用、导出、删除、清空；
- 陈旧资产预览与批量修复；
- 全片快速生成、Supervisor 补齐与运行控制；
- 加载、空态、错误态、自动刷新、可访问性与窄屏布局；
- 相关前后端实现及自动化测试覆盖。

实际项目数据状态：第 1 集处于编剧运行态，最初显示 5 镜，扫描过程中刷新为 4 镜；第 1646 集为 `planned` 且 0 镜；当前数据库没有视频版本。因此，真实媒体播放、真实版本采用和 Supervisor 终态主要依据实现代码与专项测试评估，没有触发付费生成或破坏性操作。

验证结果：

- 前端相关测试：12 个通过；
- 后端视频、参考图、停止任务、Supervisor 专项测试：45 个通过；
- TypeScript 类型检查：通过；
- 浏览器控制台：未发现 warning/error；
- 现有 `WallPage` 测试只覆盖参考图分组等纯函数，没有覆盖完整组件交互、刷新竞争、空态和破坏性操作。

## 四、最可能被用户认为“不好用”的功能

### 1. 跨镜逐项评审

用户通常会按同一维度连续检查，例如先看全片文字，再看全片参考图，再看全片视频。当前每切一镜就回到“文字内容”，用户必须重复点击标签。镜头多时，这会成为最明显的重复劳动。

优化建议：保持当前标签；提供“上一问题镜 / 下一问题镜”；支持“只看待采纳、失败、B 级、衔接降级”。

### 2. 补齐到全片可用的授权流程

预算、时间、分镜编辑授权都很重要，但连续浏览器弹窗会让用户不确定“取消”是终止流程，还是选择“不授权”。错误输入还需要从头重来。

优化建议：改为单个结构化影响弹窗，包含数字输入、单位、上下限、默认值、预计费用、镜头数、复选框和最终一次确认。

### 3. 视频版本比较

版本信息齐全，但只能在同一个播放器里来回切换。用户很难记住人物脸、动作连贯性、口型或镜头抖动等细节。

优化建议：提供双播放器 A/B、同步播放、同帧暂停、循环区间、QA 差异和一键采用。

### 4. 空态与前置条件不满足时的页面

零镜头、未确认、无参考图、无视频时，页面缺少行动路径。最典型的是“请使用下方按钮”，但状态不允许显示该按钮。

优化建议：空态必须由“原因 + 当前状态 + 下一步 + 跳转按钮”组成，不能只显示空框或技术状态。

### 5. 清空、取消、废弃等高风险动作

清空使用双重确认，Supervisor 取消却没有二次确认，参考图废弃又是一键提交，交互安全等级不一致。

优化建议：建立统一的风险交互规范：可撤销操作用 Undo；不可恢复操作用一次服务端影响确认；涉及费用或长任务终止时展示明确影响。

## 五、最容易出现 Bug 的环节

### P1：镜头列表刷新导致评审对象漂移

实测：用户选中第 5 镜后，后台编剧任务把镜头数从 5 更新为 4，页面自动显示第 4 镜。实现中使用 `idx` 保存选择，并通过 `shots[idx]` 取当前镜头；列表变化时只把越界下标收缩到最后一项。

风险：用户以为仍在评审原镜头，随后可能对另一镜执行采用、重生、废弃参考图或清空。

修复：用稳定 `shot.id` 保存选择；刷新时按 ID 重定位；若原镜被删除，冻结操作区并显示变更说明，让用户主动选择下一镜。

### P1：预算和时间授权允许非法值

前端通过 `Number(value) || default` 解析：`0` 会被替换为默认值，负数会保留。后端签发授权时直接 `float()`，没有正数、合理上限或有限数校验。

风险：负时间墙会得到过去的截止时间；负预算会让 Supervisor 异常暂停或提前收口；超大值可能造成过度授权。

修复：前后端共同校验 `min/max/finite`；前端用数字字段和单位；服务端把约束写入请求模型，而不是接收任意 `dict`。

### P1：编剧运行中清空媒体，可能与后台写入竞争

评审墙在 `scripting` 状态仍显示“清空本镜/本集”。清空媒体只会停止视频 Supervisor，不会停止正在生成或改写分镜的编剧/分镜任务。

风险：清空后内容被后台重新写回、镜头引用失效、用户看到结果反复变化。

修复：活动编剧/分镜任务期间禁用清空；或先提供“停止上游任务并清空”的统一预演，服务端用状态机和锁保证原子性。

### P1：详情加载失败被伪装成素材为空

切镜时详情对象被清空，但 UI 立即回退到列表摘要；详情请求失败只显示短 Toast。

风险：用户可能把请求失败当作“无参考图/无视频版本”，进而重复生成或做出错误判断。

修复：摘要和详情分别标记；详情区使用明确加载骨架；失败后保留持久错误卡和“重试”，禁止会依赖详情的操作。

### P2：Supervisor 面板可能展示过期快照

轮询失败会被静默忽略并保留旧快照，没有“最后成功同步时间”。

风险：用户以为任务仍在某阶段或预算仍未耗尽，基于过期信息执行控制操作。

修复：显示最后同步时间；连续失败后标记“数据已过期”；控制按钮在重新同步前进入保护态。

### P2：动态列表刷新与 `refreshAll()` 存在下标竞争

刷新完成后仍用旧 `idx` 在新列表中找镜头详情；同时另一个 effect 可能才刚把下标收缩。

风险：详情请求和列表选中项短暂不一致，出现闪烁、错版或操作对象变化。

修复：所有刷新链路只传 `shotId`，不要跨异步边界保存数组下标。

### P2：参考图原因被过度折叠

一致性漂移、质量门禁、重复角色等多种原因统一显示为“分数不足”。

风险：用户无法针对真实问题修复，甚至会错误恢复本应阻断的视频输入。

修复：保留用户可理解的一级原因，技术码放在展开详情中；恢复时按风险级别要求不同确认。

### P2：版本管理不完整

删除入口只针对当前未采用版，旧失败版本和历史候选缺少逐版本删除/归档入口。

风险：版本越来越多，用户误把“当前播放器版本”当成“被删除的版本”。

修复：每张版本卡拥有独立操作菜单，清楚区分预览、采用、导出、删除和归档。

## 六、优化实施优先级

### P0：先消除误操作和流程死路

1. 把镜头选择从 `idx` 改为 `selectedShotId`，刷新时保持对象稳定。
2. 为零镜头、未确认、无参考图、无视频、详情失败提供状态化空态和下一步 CTA。
3. 用一个结构化影响弹窗替代多段 `prompt/confirm`，并做前后端预算/时间上下限校验。
4. 在上游编剧/分镜运行时禁用清空和依赖稳定分镜的媒体操作。
5. Supervisor 取消、追加预算必须显示最终影响并确认；轮询失败显示数据过期状态。

### P1：把页面变成高效率评审工作台

1. 跨镜保持当前标签，增加问题镜头筛选和上一/下一问题镜。
2. 增加真正的 A/B 视频对比、同步播放和 QA 差异。
3. 增加评审批注、问题类型、负责人、处理状态和“本镜评审完成”。
4. 分集选择器展示制作/评审状态，并支持按状态筛选。
5. 参考图废弃增加 Undo，恢复弹窗显示完整原因、分数和影响。
6. 把技术枚举和英文诊断字段翻译为中文，原始值放到“技术详情”。

### P2：完善可访问性、移动端与测试覆盖

1. Lightbox 使用标准对话框语义、焦点锁、明确关闭图标和键盘打开。
2. 移动端降低空视频区域高度，避免多个 sticky 元素互相遮挡。
3. 增加组件级和端到端测试，至少覆盖：
   - 镜头列表增删后选中对象不漂移；
   - 切镜保持标签；
   - 未确认/零镜头/详情失败空态；
   - 预算负数、0、超大值、非数字；
   - 清空与上游任务并发；
   - Supervisor 轮询失败和取消确认；
   - 版本预览、采用、删除的对象一致性；
   - 参考图废弃、恢复和 Undo。

## 七、建议的验收指标

- 连续评审 20 镜时，每镜平均额外点击次数降低 40% 以上；
- 后台刷新后，当前镜头 ID 保持率 100%，不允许静默切换对象；
- 所有空态均包含原因和至少一个可执行下一步；
- 所有费用授权值均通过前后端上下限验证；
- 不可恢复操作只出现一次权威确认，不再叠加浏览器确认和批准弹窗；
- 详情请求失败时，不得显示为“无素材”；
- Supervisor 连续两次轮询失败后，页面必须明确标记数据已过期；
- 键盘可完成镜头切换、标签切换、图片预览、版本预览、采用和关闭弹窗；
- 新增端到端测试覆盖本报告列出的全部 P1 风险。

## 八、最终判断

评审墙的功能广度已经足够，视频生产和审计能力也比普通“素材列表页”更完整。当前主要短板是：**对象稳定性不足、状态与下一步不清楚、连续评审效率低、高风险操作交互不统一**。

建议先用一轮 P0 整改把“不会看错镜头、不会走进死路、不会错误授权或误清空”做扎实，再投入 A/B 对比、批注和问题队列等效率功能。这样能以较小改动显著提升用户信任，而不需要重做现有后端能力。
