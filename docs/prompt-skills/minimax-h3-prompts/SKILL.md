# MiniMax H3 视频提示词

MiniMax H3（Hailuo 3.0 / Hailuo 03）是 MiniMax 于 2026 年 7 月 31 日发布的开源权重全模态生成模型：文本、图像、视频、音频进同一个上下文，单次输出 5-15 秒、最高 2K、24fps、原生立体声的音视频。

**先记住三条与 Seedance 相反的规则**，这是迁移时最容易踩的坑：

| | Seedance 2.0 | MiniMax H3 |
|---|---|---|
| 时间戳 | 不可靠，只能用镜头序号软提示 | **官方语法**，`[Shot 2] At 00:03.500` 严格递增 |
| 画面文字 | 汉字必乱码，写"无字"后期合成 | 文字与品牌呈现是官方主打能力，屏上文字用双引号原文写进提示词 |
| 提示词形态 | 中文自由散文 | **结构化三字段**，描述部分按官方规范用英文写；台词和屏上文字保留原文 |

写任何 H3 提示词之前，先读 `references/official-format.md`——那是官方规范的完整整理，字段名、固定指令行、对话标签都必须逐字符合，写错字段名模型不会报错，只会静默降级成自由文本理解。

## 官方提示词骨架（速查）

一条 H3 基础提示词 = **（可选的图像对齐指令行）+ 三个核心字段**：

```
<模式对应的固定对齐指令行，T2VA 没有，空一行后接字段>

integrated_multimodal_description: [Shot 1] <风格>, <首镜头构图与主体>...
[Shot 2] At 00:05.000, the camera cuts to <下一镜头>...

overall_soundscape: <1-4 句英文，全片环境音/物理音效/非语言人声>

non_diegetic_music: <1-3 句英文，只有观众听得到的配乐；没有就写 N/A>
```

三个字段各管一摊，不要互相越界：

- **integrated_multimodal_description** 是主体：沿时间线写视觉、动作、运镜、说话人、对话、歌唱、剧情内音效。首镜头 `[Shot 1]` 不带时间戳并要先声明整体风格（`Live-action, cinematic` / `2D-animated` / `3D CG` 等）；后续镜头带严格递增的切点时间。
- **overall_soundscape** 只写环境与物理声音（风、雨、脚步、布料、呼吸），不重复对话。**这个字段留空的代价很大**：H3 是音画联合生成，声音不给方向就会自己生成，可能是不想要的杂音——沉默从来不是默认值。
- **non_diegetic_music** 写乐器、速度、节奏、力度变化，**不写抽象情绪词**（"悲伤的音乐"无效，"缓慢的钢琴单音加渐强的低音提琴"有效）。

四种模式（T2VA / I2VA / FL2VA / L2VA）的固定指令行、关键帧融入写法、对话与歌唱语法（`(S1)` 说话人 ID、`<d>[Chinese] 原话</d>` 台词块、画外音、`<scenetrans>` 跨镜延续）全部在 `references/official-format.md`。

## 工作流

### 单条视频

1. **选模式**：只有文字 → T2VA；要锁开场画面 → I2VA；要同时锁开场和结尾 → FL2VA（注意官方偏好单镜头，让模型在两帧之间连续插值）；只锁结尾 → L2VA。图片、视频、音频要共同参与 → Ref2VA（另一套六段式格式，见 official-format.md 末节）。
2. **给每个参考素材派一个明确的职责**。这是所有社区实践文章重复次数最多的一条：图片锁身份/商品外形，视频锁动作/镜头路径/剪辑节奏，音频锁人声/节奏。职责不写，模型自己猜，猜错了你不知道该改哪。素材上限以官方平台当前显示为准（社区普遍报为图片 9 / 视频 3 / 音频 3，合计约 12 个文件——这个数字未经我们实测，用前核对）。
3. **写三字段**。时长预算意识：5-15 秒里每条指令都在争时间，四个运镜加三句台词加一次变身塞不进 10 秒。先删到"一个主动作 + 一次运镜 + 最多两句台词"，跑通了再加。
4. **失败时一次只改一个字段**，种子固定。三个字段对应模型的不同子系统，隔离修改才能定位。

### 小说 / 剧本 → 分镜（接 novel-to-storyboard 的八步工作流）

novel-to-storyboard skill 的节拍表、角色锚、色调分段、质检、定点重跑逻辑全部适用，只有两处因 H3 的能力而改变：

**段内结构改用官方 Shot 语法。** 不再用"镜头1/镜头2 + 括号软时间"，直接写 `[Shot 1]`（无时间戳）、`[Shot 2] At 00:05.000`、`[Shot 3] At 00:10.000`——H3 的切点时间是可靠的，节奏可以精确设计。每段仍建议 15 秒 3-4 镜。

**跨段一致性改用首尾帧链。** 这是 H3 对这个工作流的最大价值：段 N 生成后抽出末帧，段 N+1 用 I2VA 以这一帧为首帧继续。首帧锚定意味着人物长相、服装、场景在段边界被上一段的真实画面锁住，而不是靠参考图和文字描述赌运气——跨段换脸的根因（每段独立采样）被直接消除。链式生成的代价是段与段必须串行、不能并行跑，时间换一致性。角色参考图仍然要给（应对镜头切换后人物再入画的情形），身份锚写法用 `the <特征> from Shot 1`。

### 成片修复：先想改，再想重跑

H3 有两个 Seedance 没有的修复通道，能省掉大量重生成：

- **In-context 编辑 / 再生成**：用自然语言指定改某个时间区间或画面区域，其余保持不变。局部瑕疵（某两秒的手部崩坏、某个区域的道具错误）优先走这条路。
- **768P → 2K 再生成**：官方支持先用 768P 低价迭代内容，满意后原样提交全部内容外加源视频，升级输出 2K。批量项目先低清跑创意、终版再升清，成本差数倍。

质检本身（切点、色温、响度、面部一致性）与模型无关，装了 novel-to-storyboard 的话直接用它的 `scripts/qc_video.py`。

## 写作规则（按重要性排序）

1. **运镜写成句子，不写标签堆**。官方定义运镜 = 类型 + 幅度 + 速度三维，写成自然的英文动作句："The camera pushes in with small amplitude at slow speed toward her hands"，而不是句尾堆 "push in, slow, cinematic"。中等幅度、常速可省略。一镜一个主运镜。完整运镜词表见 official-format.md。
2. **台词逐字进 `<d>` 块，身份描述放块外**。`<d>` 里只有语言标签和原话，不改写不翻译；说话人的年龄、音色、语速写在 `<d>` 外面。中文台词直接 `<d>[Chinese] ...</d>`，模型按原文生成口型。
3. **切镜要有信息增量**。官方明确：一次切换应带来主体、空间、状态、视角或时间上的新信息；只想改景别就用运镜，不要切。
4. **屏上文字用双引号原文**。招牌、字幕、横幅写 `reading "..."`，保留原文与标点不翻译。H3 的文字呈现是强项，但复杂字形（书法、密集小字）仍建议先跑一条测试镜验证再进正片。
5. **给长镜头一个重复性事件当时间锚**（旋转的灯、闪烁的霓虹、驶过的列车）——社区实测能显著减少长镜头的漂移。
6. **soundscape 从画面倒推**。写完画面描述后逐项自问"这个东西是什么声音"：碎石上的脚步、布料摩擦、金属刮擦。多写两句物理声，成片质感差别明显。
7. **提示词不追求长**。官方 45 条示例的中位长度约 130 个中文字符量级——结构完整、描述精准比堆字数重要。
