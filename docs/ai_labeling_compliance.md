## A.《人工智能生成合成内容标识办法》与 GB 45438-2025

### A.1 基本信息（官方原文，来源可核）

- 发布主体：国家互联网信息办公室、工业和信息化部、公安部、国家广播电视总局四部门联合发布。
- 发布日期：2025年3月14日；施行日期：**2025年9月1日**。
- 官方通知全文页面：https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm （通知+《办法》正文一体发布，共14条）
- 官方新闻通稿：https://www.cac.gov.cn/2025-03/14/c_1743654685899683.htm
- 官方答记者问：https://www.cac.gov.cn/2025-03/14/c_1743654685896173.htm
- 配套强制性国家标准：**GB 45438-2025《网络安全技术 人工智能生成合成内容标识方法》**，发布日期 2025-02-28，同日 2025-09-01 施行，发布单位为国家市场监督管理总局、国家标准化管理委员会。标准页面：https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F32EA2A561F1886CD8D606513512D547 （**该页面为在线预览系统，WebFetch 工具未能渲染出全文正文，本报告中 GB 45438 的具体条文细节来自第三方转述，非直接抓取的官方原文，见 A.4 标注**）。

### A.2 逐条原文摘录（从 cac.gov.cn 官方通知页面提取，工具逐字引用，非我方转述）

> **第一条**：立法目的——促进人工智能健康发展，规范生成合成内容标识，保护公民、法人和其他组织合法权益，维护社会公共利益。
>
> **第二条**（适用范围）："符合《互联网信息服务算法推荐管理规定》、《互联网信息服务深度合成管理规定》、《生成式人工智能服务管理暂行办法》规定情形的网络信息服务提供者（以下简称'服务提供者'）开展人工智能生成合成内容标识活动，适用本办法。"
>
> **第三条**（术语定义）：
> - 人工智能生成合成内容："利用人工智能技术生成、合成的文本、图片、音频、视频、虚拟场景等信息。"
> - 显式标识："在生成合成内容或者交互场景界面中添加的，以文字、声音、图形等方式呈现并可以被用户明显感知到的标识。"
> - 隐式标识："采取技术措施在生成合成内容文件数据中添加的，不易被用户明显感知到的标识。"
> - **注意**：办法本身**未**对"生成合成服务提供者""网络信息内容传播平台""互联网应用程序分发平台""使用者"这几个主体分别下定义条款，这些主体的义务分散在第四、六、七、九、十条中直接规定，主体范围要结合第二条援引的三部上位规定（算法推荐规定/深度合成规定/生成式AI暂行办法）来判断。
>
> **第四条**（显式标识的具体方式，按内容类型分类）：
> - 文本："在起始、末尾或中间适当位置添加文字提示或通用符号提示等标识，或在交互场景界面、文字周边添加显著的提示标识。"
> - 音频："在起始、末尾或中间适当位置添加语音提示或音频节奏提示等标识，或在交互场景界面中添加显著的提示标识。"
> - 图片："在适当位置添加显著的提示标识。"
> - **视频："在起始画面和播放周边适当位置添加显著提示标识，可在末尾和中间适当位置添加。"**（漫剧属于视频，这条是最直接适用的条款）
> - 虚拟场景："在起始画面适当位置添加显著提示标识，可在持续服务过程中适当位置添加。"
> - 下载、复制等：需"确保文件中含有满足要求的显式标识"。
>
> **第五条**（隐式标识）："在文件元数据中添加隐式标识，包含生成合成内容属性信息、服务提供者名称或编码、内容编号等制作要素信息"，并"鼓励"采用数字水印等技术形式加强。
>
> **第六条**（网络内容传播服务提供者义务）：核验元数据中的隐式标识；处理用户声明情况；识别疑似生成合成痕迹；提供标识功能并提醒用户声明。
>
> **第七条**（应用分发平台义务）：应用程序上架/上线审核时，"应当要求互联网应用程序服务提供者说明是否提供生成合成服务"，并核验相关标识材料。
>
> **第八条**（服务提供者义务）：应在用户协议中"明确说明生成合成内容标识的方法、样式等规范内容"。
>
> **第九条**（关闭显式标识的唯一合法路径）：用户申请不含显式标识内容的，提供者可在用户协议中"明确用户的标识义务和使用责任"后提供，"并依法留存相关日志不少于六个月"。
>
> **第十条**（使用者/发布者义务）：用户发布生成合成内容应"主动声明并使用服务提供者提供的标识功能"；禁止"恶意删除、篡改、伪造、隐匿"标识，也不得"为他人实施上述恶意行为提供工具或者服务"。
>
> **第十一条**："服务提供者开展标识活动的，还应当符合相关法律、行政法规、部门规章和强制性国家标准的要求。"（即必须同时满足 GB 45438 等强制性国家标准）
>
> **第十二条**："服务提供者在履行算法备案、安全评估等手续时，应当按照本办法提供生成合成内容标识相关材料，并加强标识信息共享，为防范打击相关违法犯罪活动提供支持和帮助。"
>
> **第十三条**：违反本办法，"由主管部门按照有关法律、行政法规、部门规章的规定予以处理"（未在本办法内规定具体罚则，需援引其他法规，如《网络安全法》《生成式人工智能服务管理暂行办法》等）。
>
> **第十四条**："本办法自2025年9月1日起施行。"

### A.3 义务主体归属——对"调用第三方API生成、自己剪辑成片、投放平台"这类角色的分析

这一点**办法条文本身没有直接写明**，以下是基于第二条适用范围条款做的结构性推理（不是官方逐字定论，请法务复核）：

- 第二条把"服务提供者"限定为落入《算法推荐管理规定》《深度合成管理规定》《生成式人工智能服务管理暂行办法》适用范围的**网络信息服务提供者**——即那些**向公众/其他用户提供** AI 生成能力的主体（如火山引擎/即梦本身）。
- 一家仅仅**调用**第三方 API 生成素材、自己剪辑成片、再对外发布的公司，通常不构成向他人提供生成合成服务，因此**大概率不落入"服务提供者"范畴**，不直接承担第四、五条（生成显式/隐式标识）的技术实现义务——这个义务落在火山引擎/即梦身上。
- 该公司在**发布**成片到抖音/快手等平台时，扮演的是第十条所称的"用户"角色，义务是"**主动声明并使用服务提供者（此处指平台）提供的标识功能**"进行标识，即在各平台的发布界面主动勾选/声明"AI生成"。
- 如果该公司未来自己搭建了向公众开放的 AI 生成工具（即不再是单纯"使用"而是"提供"），则会转变为"服务提供者"，需自行承担第四、五、八、九条的全部义务。

## B. 供应商 logo 与法定标识是不是一回事

### B.1 结论先说：不是一回事，法律上不能划等号

从 A.2 第五条原文看，**隐式标识（文件元数据）是"服务提供者"的强制义务，条文没有给"用户可以要求不加隐式标识"的选项**——第九条只允许提供商在满足用户协议+留存日志的前提下，应用户要求提供**不含显式标识**的内容，条文中没有类似条款允许免除隐式标识。也就是说：
- **法律上**，即便供应商关闭了可见水印（无论是品牌 logo 还是"AI生成"提示字样），供应商仍然被要求在文件元数据里写入隐式标识——这是供应商自己的法定义务，不是可选项。
- 但这只是"法律要求供应商做什么"，**不等于"供应商实际做了"**。2026年4月28日国家网信办公开通报（见 B.3），恰好点名了即梦AI（本报告调研对象所属同一产品线）未有效落实标识规定，说明"法律要求"和"实际执行"之间存在真实的落差，不能想当然认为供应商已经合规实现。

### B.2 火山引擎/即梦 API 层面的证据（部分来自第三方 API 文档镜像，非火山引擎官方文档原文，需用户自行用官方账号实测核实）

- 本次调研尝试直接抓取 volcengine.com/docs 与 docs.volcengine.com 官方 API 文档页面，**多次因页面为 JS 渲染的 SPA 而抓取失败（WebFetch 返回空内容或反爬检测页）**，未能拿到官方原文。以下信息来自检索引擎对第三方 API 文档聚合站（如 api-doc.vncps.com 等代理转发文档站）的摘要，**权威性有限，务必用户自己登录火山引擎控制台核实官方文档原文**：
  - 即梦图片/视频生成 API 存在一个 `logo_info` 参数对象，字段包括：`add_logo`（布尔值，是否加水印，检索到的信息显示默认值为"不添加"）、`position`（0=右下/1=左下/2=左上/3=右上）、`language`（0=中文"AI生成"/1=英文"Generated by AI"）、`opacity`（0-1透明度）、`logo_text_content`（自定义水印文字）。
  - 这组参数控制的看起来是**可见水印/显式标识**（因为默认文案就是"AI生成"/"Generated by AI"字样，而非"即梦"品牌名），而不是元数据里的隐式标识。
  - **本次调研没有找到任何官方文档段落明确写"关闭 add_logo 不影响隐式标识/元数据"这句话**——这是用户在报告里特别想确认的点，目前**查不到官方原文佐证，只能标注"未查到"**，不能替用户下结论。建议用户直接生成一张 `add_logo=false` 的图片，用 exiftool/exiv2 等工具读取文件元数据，实测是否含有 GB 45438 要求的隐式标识字段——这是比查文档更可靠的验证方式。

- 消费端网页（jimeng.jianying.com，非 API）的水印行为，来自多篇自媒体/技术博客（CSDN、cnblogs 等，**权威性低，仅作线索**）描述为：左上角"AI"字样标识 + 右下角"即梦AI"品牌水印两层；据称左上角"AI"字样即便开通会员导出后依然保留（描述为不可去除的合规标识），右下角品牌水印可通过会员去除。**这组信息全部来自自媒体转述，本次未能在即梦官方帮助中心/用户协议页面找到逐字对应说明来源核实**，如果用户的系统走的是网页端而非 API（大概率不是，用户描述是"当前 AI 供应商...烧了自己的 logo 水印"更像是 API 场景），需要单独核实。

### B.3 关键背景事实：供应商本身已因标识违规被官方查处（官方原文，权威性高）

- 官方通报：https://www.cac.gov.cn/2026-04/28/c_1779119736411711.htm ，发布日期 2026年4月28日。
- 原文核心表述："（国家互联网信息办公室）发现'剪映''猫箱'App及'即梦AI'网站存在**未有效落实人工智能生成合成内容标识规定要求**等问题，违反网络安全法、生成式人工智能服务管理暂行办法、人工智能生成合成内容标识办法等规定"。
- 处置措施原文："约谈、责令改正、警告、从严处理责任人等处置处罚措施"。
- 通报**没有**具体点明是显式标识缺失还是隐式标识缺失（"未有效落实"是笼统表述），但**运营主体是深圳市脸萌科技有限公司（字节跳动旗下，剪映+即梦同一运营方）**——这意味着用户目前使用的供应商产品线（即梦/火山引擎）曾在官方通报中被点名标识履行不到位。这是一个**强信号**：不能默认"供应商已经把法定标识做对了，我只要关掉品牌 logo 就行"，需要用户自己核实一次生成结果的元数据，或直接书面询问供应商的合规团队。

### B.4 实操建议（不是法律意见，是技术验证路径）

1. 用当前使用的 API 生成一批测试图片/视频，同时保留"开水印"和"关水印"两个版本。
2. 用 exiftool（`exiftool -a -G1 file.jpg`）或类似工具比对两个版本的文件元数据差异，确认关闭 `add_logo`/`watermark` 后，元数据里是否仍然存在 GB 45438 要求的隐式标识字段（服务提供者名称/编码、内容编号等）。
3. 如果关闭水印后元数据里的隐式标识字段也消失了，说明供应商把"法定义务"和"品牌开关"耦合在了一起，实质上违反了办法第五条（隐式标识不应该是可选项）——这种情况下用户应该书面联系供应商合规/法务团队问清楚，而不是自行下结论继续使用。
4. 如果元数据里的隐式标识依然存在，那么用户"关闭品牌 logo"这个动作本身在法律层面没有问题——法定义务由供应商在后台履行，用户不需要额外操心隐式标识这一层。

## D. 实操结论（基于 A-C 的综合判断，不构成法律意见）

### D.1 "关掉供应商 logo + 分发环节按平台规则声明 AI 生成"这条路，从查到的条文看，方向是对的，但有两处不能想当然

1. **"关掉供应商 logo"这个动作本身没有法律问题**——前提是关掉的是"品牌 logo/可见水印"这一层，而不是连带关掉了法定的**隐式标识（文件元数据）**。这一点法规上（《标识办法》第五条）明确是供应商的强制义务，不因用户关闭可见水印而豁免。但**本次调研拿不到官方文档确证火山引擎/即梦的 `add_logo=false` 参数不影响元数据**，加上供应商本身在 2026年4月刚被网信办点名"未有效落实标识规定"，这两点叠加起来意味着：**不能默认供应商已经把隐式标识做对了，必须自己抽样实测元数据**（见 B.4 的具体验证步骤），或者直接书面问供应商合规团队要一份书面说明。这是本报告能给出的最重要的一条行动项。

2. **分发环节的声明义务落在用户公司身上，不是可选项**。《标识办法》第十条要求"用户"（即漫剧生产公司，扮演发布者角色）在发布 AI 生成内容时"主动声明并使用服务提供者提供的标识功能"——这里的"服务提供者"在发布场景下指的是**抖音/快手/B站等分发平台**，不是火山引擎。也就是说，即便供应商那边的隐式标识做得很干净，用户公司自己在往抖音/快手/B站发布成片时，**仍然需要在这些平台的发布界面主动勾选"AI生成"声明**——这一步骤不能省，省了就是直接违反第十条，平台侧也大概率会有检测+限流的后果（各平台公告转述中均提到类似机制，虽然没有拿到平台官方原文逐字确认处罚力度）。

### D.2 需要额外做的动作（建议清单，供产品负责人排期）

- **必须做**：
  - 实测火山引擎/即梦 API 关闭水印后的文件元数据（用 exiftool 等工具），确认法定隐式标识字段是否仍然存在；如果消失，联系供应商解决或考虑要求供应商出具书面合规声明。
  - 成片发布到各平台时，在平台后台主动勾选"内容由AI生成"声明（抖音"发文助手自主声明"、B站"创作声明"等，各平台入口不同，需要产品/运营团队逐一核对当前生效的入口位置——平台改版频繁，本报告查到的入口路径可能已经过时）。
  - 如果计划以"微短剧"备案渠道发行（涉及广电总局发行许可证/备案公示），需要在**每一集**画面明显位置加显式标识（广电《微短剧发展管理办法》第三十四条，2026年9月1日起施行）——这条独立于抖音/快手等平台自己的标识规则，是否适用取决于用户的具体发行渠道是否走"微短剧"备案路径，需要用户确认。
- **建议但本报告无法替用户判断是否必须**：
  - 是否需要在成片文件里自己额外写入/保留一层标识元数据（比如在剪辑合成环节，用 ffmpeg 写入自定义 metadata 字段），作为供应商隐式标识之外的兜底证据——这取决于第一条的实测结果：如果供应商元数据确实保留了，就不必重复做；如果供应商元数据丢失了，这一步就从"建议"变成"必须"。
  - 与法务确认：公司自身是否可能因为"批量、规模化地使用 AI 生成技术制作对外发行的视听内容"这一商业模式，在某些从严认定口径下被认定为事实上的"生成合成服务提供者"（尤其是如果未来对外提供生成能力、或者被监管从严解释）——本报告倾向于认为按现有条文文本，单纯内部使用+自行发布不落入"服务提供者"，但这是本报告的结构性推理，不是条文直接写明的结论，建议正式立项前让法务书面确认一次。

### D.3 本报告的局限性（如实说明，不夸大调研完整度）

- GB 45438-2025 标准正文（技术细节，如元数据具体字段编码、附录E/F 范例）**始终未能获取到官方原文**，本报告涉及的技术细节均为第三方转述，不能作为开发依据，正式做元数据实测/开发前需要单独获取标准正式文本。
- 火山引擎/即梦官方 API 文档因页面是 JS 渲染 SPA，本次工具多次抓取失败，B、B.2 节涉及的参数细节来自第三方文档镜像站，不是官方文档原文抓取，需要用户登录官方控制台核实。
- 各平台（抖音/快手/B站/小红书等）的公告，本次只有转述、没有一处成功抓到官方公告原文全文（B站官方公告页被验证码拦截）。这些规则本身也是各平台自己制定、可随时调整的私域规则，不具有法规那样的稳定性，建议产品上线前指派专人定期复核。
- 未查到"标识办法"本身规定的具体罚则数额（第十三条援引其他法规处理，未在办法内列明罚款金额等），如果需要评估违规成本，需要进一步查《网络安全法》《生成式人工智能服务管理暂行办法》等上位法的对应罚则条款，本次未展开。
