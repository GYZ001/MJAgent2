# 角色固定音色：声音生成接口调研与实施方案

> 2026-09-23 · 基于 main@8f6822d2 · 本轮只做调研与方案：没有改代码，没有调用任何付费接口，没有提交视频任务。
> 外部事实都标了来源。标「未查实」的，不作为设计前提。
> 本文取代《AI 批量成片对标小云雀人工》方案中「P1-1 角色音色锚」一节的第 2 步：音色样本的主来源从「截取已采纳片段」改为「模型接口按文字描述生成」。

## 0. 结论先行

**可以做，而且改动面可控。**做法是：每个角色用声音生成接口「凭文字描述」生成一个专属音色，保存成一段 ≤5 秒的参考音频，绑定到人物卡。生成视频时，本段有台词的角色，把他们的声音和定妆照一起传给 Seedance 2.0，每段最多 3 个角色。

**有两件事官方没有承诺，必须先实测再投入开发：**

1. **公司 HiAgent 网关会不会原样转发音频参考。**现在代码只发过文本、图片、视频三类内容。利用网关「非法参数只在轮询时失败、不计费」的既有实测，可以零额度证实。
2. **带了参考音频，Seedance 的效果是否真的变好。**要看三件事：音色是否跟随参考；会不会把参考音频里的原话念出来；两三个角色同段时会不会串音。官方文档只写了参数格式，这三点都没有表态。需要约 4 段、共 60 秒的视频额度做对照。

**声音生成接口推荐阿里百炼「千问声音设计」**（qwen3-tts-vd）：

- 官方文档把端点、参数、返回物、价格（0.2 元/个）、保留规则（1 年未使用才删除）都写明了；
- 仓库已有百炼密钥位（`BAILIAN_API_KEY`）。

备选 MiniMax Voice Design。火山的「豆包音频生成模型 1.0」（Seed-Audio）和 Seedance 同一体系，长期看最合适，但 API 仍在邀测，文档也取不到，本期不依赖它。

**需要你做的只有两件**（见第 9 节）：

- 提供一个百炼 API Key；
- 批准约 60 秒视频额度的对照探针。

## 1. 需求拆解与范围

**明确不做**

| 方向 | 理由 |
|---|---|
| 用 TTS 整段替换视频原生对白 | 口型对不上，与 09-23 方案「明确不做」一致 |
| 本地部署开源 TTS 模型 | 生产机 8 核、无确认可用的 GPU；要引入 torch 等大依赖；CPU 推理速度没有可信实测 |

**合规**：音色设计生成的是虚构声音，不涉及真人声音权。复刻真人录音须取得书面授权，所以「上传录音」放到 P1，并加授权声明。

**参考音频的内容怎么选**：没有找到 Seedance 官方说明。第三方经验一致的几条：

- 要干净人声，不带混响和底噪；设计出来的试听音频天然满足。
- 语言与目标对白一致。
- 情绪平稳。

## 3. 调研：视频模型能否接收参考音频

**Seedance 2.0**（火山方舟官方「创建视频生成任务」页，本轮亲自核对）：

- 写法：`{"type":"audio_url","audio_url":{"url":…},"role":"reference_audio"}`。url 可以是公网地址、`data:audio/<格式>;base64,…` 或素材 ID。
- 限制：
  - 格式 wav、mp3；单段 2–15 秒；
  - **最多 3 段，总时长不超过 15 秒**；
  - 单段 ≤15 MB，请求体 ≤64 MB。
- 原文「**不可单独输入音频，应至少包含 1 个参考视频或图片**」。
- 原文「图生视频-首帧、图生视频-首尾帧、全模态参考生视频（包括参考图、视频、音频）为 3 种互斥场景」。我们分镜台 2.x 走的正是全模态参考，首尾帧 08-26 已退场，不冲突。
- `generate_audio` 默认 true。
- **官方没写的**：
  - 提示词里怎么指代音频：示例代码只出现过 `@图像1`、`@视频1`；
  - 多角色会不会串音、会不会复读参考内容；
  - 带音频是否额外计费。
- 该页已并列 Seedance 2.5 的参数：单段 2–30 秒、最多 10 段、总长 ≤30 秒，且可以只传音频。公司若升级到 2.5，上限随能力配置放宽即可。

**MiniMax H3**（官方视频生成 v2 接口）：

- 同样支持 `audio_url` + `reference_audio`，上限也是 3 段、总长 15 秒；
- 官方提示词指南的写法是「`<Audio 1>` 是 `<Subject 1>` 的音色参考」，并说明参考模式下不带入原台词；
- 社区反馈音色跟随成功率约五成。

**其他模型**只作可切换设计的参照：

- Veo 3.1 不支持参考音频；
- Vidu 的音色参数只属于数字人产品；
- 万相 S2V 是用音频驱动口型，不是固定音色；
- 可灵有独立的音色管理接口，但与视频生成怎么绑定没查到。

**结论**：主流做法都是**每次请求带上音频文件本身**，没有可复用的音色 ID。所以我们在本地保存参考音频，每次请求重新附带，这是必然的形态。

## 4. 代码现状（与方案相关的事实）

- **人物卡没有独立 id**：
  - 卡是 `projects.bible_json` 里 `Bible.characters[]` 的一项，以 `name` 为键（`app/schemas/character.py:102`）；
  - 定妆照存在 `character_portraits` 表，按 (项目, 角色名, ep_start) 分行，另有年龄段 `anchor_key`（如 `age:8`）；
  - 改名、合并走 `portraits/card_merge.py`、`card_rebind.py`。
- **没有性别、年龄的结构化字段**：只写在 `appearance_canonical` 自由文本里，另有 `personality`、`speech_style`（界面显示为「语风」）。
- **段落里的说话人**：`SegmentDialogue.speaker_identity_id`，形如 `bible:{名}`、`entity:{哈希}` 或「旁白」。`SegmentCharacter.visibility` 有 `voice_only`（`app/schemas/segment_identity.py`）。
  - 参考图清单会**跳过** `voice_only` 与旁白（`app/multiview.py:476`）。声音的依赖要另从台词说话人推导。
- **请求组装链路**：
  - 素材清单 `multiview._storyboard_pack_asset_dependencies`；
  - 冻结到版本 `media_exec/input_reference.py`；
  - 提交时把本地图转 data URL（`video_modes/seedance_pack.py` → `hiagent.data_url_from_file`，mime 写死为 png/jpeg）；
  - 最后 `hiagent.create_video_task` → `seedance.py`。
- **网关层的本地校验只放行三种图片角色和 `reference_video`**（`hiagent.py:2917-2922`），要新增 `reference_audio`。
- **日志压缩**：`compact_provider_payload` 对任何 `;base64,` 串都换成「长度 + 哈希」，音频 data URL 不会撑大 `provider_calls` 表。
- **幂等**：
  - 领域幂等键包含素材清单指纹（`enqueue_prompt.py:246`）；
  - 供应商侧会比对「同一版本的请求是否变化」，变了就拦（`seedance.py:99-109`）。
- **过期判据**：只比对清单里 `character:`、`scene:` 两类 revision（`domain/storyboard_ops/staleness.py`）。
- **模型库**：职责集合写死为 `{"text","vlm","video","image"}`（`system_api.py:212`）。职责选路、绑定由数据驱动，加一种职责不用改选路。
- **前端全站没有一个 `<audio>`**。`/media` 路由支持 Range，音频放在项目目录下即可播放。
  - 段落素材面板已有「仅声音」占位（`SegmentResourcePanel.tsx:111`），也已有「定妆照已更新」角标可照抄。
- **语音识别可复用**：`subtitles.engine.transcribe_media` + `subtitles.align.align_shot`（拼音同音匹配，阈值 0.60）可以校验试听音频有没有念对。
- **行数零余量的文件**：`hiagent.py`、`system_api.py`、`input_reference.py`、`seedance_pack.py` 都正好卡在基线上。改动要先把相关逻辑外移，腾出空间再接线。新代码全部进新包 `app/voice/`（`app/` 根目录不再加散文件）。

## 5. 方案设计

### 5.1 数据模型

新表 `character_voices`，由 `app/voice/store.py` 懒建，照 `app/props/store.py` 的写法，不进 `db.py`：

| 字段 | 说明 |
|---|---|
| `id` | 声音版本 id |
| `project_id`、`character_name`、`anchor_key` | 绑定到人物卡；`anchor_key` 默认空串，表示该角色的默认年龄段 |
| `status` | `generating` / `candidate` / `current` / `failed` / `retired`；每个 (项目, 角色, 年龄段) 最多一条 `current` |
| `source` | `design`（P0）/ `upload`（P1） |
| `model_id`、`provider_voice_id` | 模型库条目、供应商音色 ID（只用于日后重新合成，视频不依赖它） |
| `voice_prompt`、`preview_text` | 实际使用的音色描述与试听文本 |
| `audio_path`、`clip_path`、`clip_duration_s`、`clip_sha256` | 完整试听音频；给视频用的 ≤5 秒片段及其时长、哈希 |
| `check_status`、`check_reason`、`asr_text`、`asr_match` | 自动校验结果 |
| 时间与操作人 | `created_*`、`adopted_*` |

- 文件放 `projects/<pid>/voices/`。每个角色最多保留 5 条非当前候选，超出删最旧的（机器配置一般，保留类数据要有上限）。
- **不写进 `bible_json`**：声音不是人物设定，写进去会无谓地提升 `bible_version`。
- 卡改名、合并时，在 `card_merge` / `card_rebind` 的同一事务里迁移声音行，并配测试守住。

### 5.2 声音生成流程

1. **写描述（文本模型，免费）**：由人物卡的外观、性格、语风、角色定位、年代，写出两样东西：
   - 音色描述：性别、年龄段、音高、音色质感、语速、情绪基调、口音，约 100 字；
   - 试听文本：一两句符合人物说话风格的中性台词，18–30 字，不含剧情事实和人名。
   - 同项目已有角色的音色描述作为上下文一并给出，让音色互相区分。
   - 提示词按「写完整的正面陈述」规范写。
2. **生成（付费，约 0.2 元）**：调用 `voice:default` 绑定的模型，拿到音色 ID 和试听音频。
3. **校验（本地，免费）**：
   - 时长必须在 2–15 秒之间，响度不能近乎静音；
   - 语音识别转写后与试听文本比对，匹配率 ≥0.60 算通过。
   - 识别引擎不可用时记「未校验」并在界面显示，不拦。
4. **裁片**：在 5 秒内最后一个停顿处截断，截出给视频用的参考片段，并做响度归一。用 ffmpeg，确定性处理。
5. **采用**：
   - 自动流程里，第一个通过校验的候选自动采用；
   - 手动「重新生成」只产生候选，你试听后点「采用」。人工采用优先级最高。
6. **自动触发**：定妆照生成完成后，若已绑定声音模型，为同批有卡的具名角色补生成声音。群演、无卡角色不生成。未绑定模型时，人物谱显示横幅「未配置声音生成模型」，并给出去模型中心的入口。
7. **批量补齐**：人物谱工具栏提供「为未配置声音的角色生成（N 个，约 N×0.2 元）」。

生成与采用都走命令总线：

- 生成带幂等键；
- 失败原因写在候选行上并显示在界面，不静默。

### 5.3 视频请求接入

- **选谁**：取本段台词的说话人（`speaker_identity_id`，含画外音、内心独白，不含旁白），解析到人物卡。
  - 超过 3 人时，按本段台词句数取前 3，同数取先出场者；其余记「超出每段 3 个上限」。
  - 每个片段 ≤5 秒，3 段合计必然 ≤15 秒。
- **不传的情形**：每一种都写明原因，显示在生成台。
  - 角色未配置声音；
  - 本段用的是非默认年龄段的定妆照，而该年龄段没有声音——宁可不传，也不拿成年人的声音给童年戏；
  - 本段一张参考图都没有（Seedance 不允许只传音频）；
  - 当前视频模型未接入参考音频（H3 在 P1 前属于这种）；
  - 全局开关已关。
- **冻结**：入队时把音频清单写进版本记录的新键 `reference_audios`（角色、年龄段、声音版本 id、片段哈希、时长），不写进 `reference_images`，否则整组参考图会被判废。
  - 提交与重试一律按冻结清单读文件；哈希对不上就明确失败，不偷换成别的声音。
  - 上线前已创建的版本没有这个键，不带音频，不会触发「同一版本请求内容变化」拦截。
- **幂等键**：只在清单非空时追加 `|reference_audios:<指纹>`。没有声音的项目行为完全不变。
- **提示词说明**：在现有「@图片N 用途说明」之后追加声音说明，写法是完整的正面陈述，例如：
  - 「张三的每一句台词都用 @音频1 的音色和语气说出，台词内容只来自本段剧本。」
  - 编号写法（`@音频N`）沿用图片的既有约定。官方没有规定，由探针验证。
- **能力开关**：视频能力快照新增「是否支持参考音频」及段数、时长上限，适配器各自声明，上限不写死在业务代码里。

### 5.4 界面（声音预览）

新增一个播放组件：全站共用一个播放器，同一时刻只响一处；不预加载，显示时长。它会是前端第一个 `<audio>`。挂载点如下：

| 位置 | 展示 | 操作 |
|---|---|---|
| **人物谱·人物卡** | 卡片上一个声音标记：播放 / 未配置 / 生成中 / 失败及原因 | 「角色设定与生成参数」弹窗新增「声音」一栏：可编辑音色描述与试听文本；生成 / 重新生成；候选列表（播放、时长、校验结果、采用） |
| **映射台·人物谱** | 每个角色一个播放按钮；未配置的显示「未配置声音」 | 只读，点标记跳到人物谱 |
| **分镜台 / 生成台·段落素材** | 说话角色旁边加播放；「仅声音」占位变成可播放；一行「本段将传入声音：张三、李四；未传：王五（未配置声音）」 | 只读 |
| **生成台·本次实际传入素材** | 列出这个版本**实际发送**的音频（「音频1 · 张三」+ 播放）及未传原因 | 只读，数据来自冻结记录，保证界面说的就是真实发出去的 |

### 5.6 我替你拍板的几处（可推翻）

1. **换声音不自动把已采纳视频判为过期。**
   - 与换定妆照不同。换定妆照会判过期，连播重跑时会重烧；声音也照做的话，一次换音色就可能连带重烧整集额度。
   - 改为在段落素材上显示「声音已更新」角标，与定妆照「已更新」同款。
   - 换声音的确认框写明「已采纳的 N 段仍是旧声音，不会自动重拍」。
2. **参考片段固定 ≤5 秒**：保证 3 个角色一定装得下，行为可预期。单人段不放长。
3. **自动生成只覆盖有卡的具名角色**：群演交给视频模型自由发挥。
4. **旁白音色、分年龄段声音放 P1**：P0 先保证「不会用错」，即年龄段不匹配时不传，再做「分开配」。
5. **先实现千问一家**：MiniMax 等试听对照后，确有必要再加。

## 6. 可行性验证（先证伪，再开发）

**探针 0：零视频额度，约半天**

1. **声音接口**：选一部现有项目的 3 个角色，例如我欲封天的孟浩、王有材、许清，按 5.2 走一遍。
   - 产出试听音频，人工试听，并过语音识别校验；
   - 花费约 0.6 元，北京地域有免费次数。
   - 若同时有 MiniMax 密钥，同一批描述各生成一份做盲听对照。
2. **网关是否转发音频**：沿用 `docs/HIAGENT_INTEGRATION.md` 记录的「非法参数创建返回 200、轮询时才失败、不计费」。
   - 提交一个故意不合法的任务：1 秒音频（下限是 2 秒），同时时长也填非法值。
   - 轮询报错**点名音频参数**，就证明网关原样转发了。
   - 若只报时长错，再做一次「只有音频非法、时长取最短 5 秒」的探测。最坏情况是网关丢掉了音频字段，任务作为合法请求照常生成，消耗一个 5 秒额度。

**探针 1：约 4 段 × 15 秒 = 60 秒视频额度，需你批准**

- 从已出片的集里挑一段 2 人对话、一段 3 人对话，旧版本就是免费的无声音对照组；
- 每段带参考音频各生成 2 次，看稳定性。
- 判定：

| 检查项 | 方法 | 通过线 |
|---|---|---|
| 不复读参考原话 | 语音识别转写成片，比对试听文本 | 4/4 无泄漏 |
| 不串音 | 人工逐句听辨说话人；有条件时加声纹比对 | ≥3/4 段全部分配正确 |
| 音色跟随 | 与参考音频、无参考旧版对比盲听 | 明显更接近参考 |
| 无新增拒收 | 看任务结果 | 无合规或版权拒收 |

- **结论分三档**：
  - 全部通过：按第 8 节开发。
  - 只有多人段不稳：P0 改为「每段只传台词最多的 1 个角色」。
  - 复读或拒收：功能停在开关关闭状态，改为跟进 Seed-Audio 的「音频先行」路线，并向你汇报。

**上线验收**

- 功能层面：
  - 人物谱能生成、试听、采用声音；
  - `provider_calls` 里的视频请求出现 `reference_audio` 条目；
  - 生成台列出的音频与实际请求一致；
  - 关掉开关后请求里不再带音频。
- **已有成片的集重新入队，不得触发重烧。**这条单独写测试。
- 效果层面：挑一集 5 段以上有同一主角台词的，与无声音的旧集做盲听对比。

## 7. 风险

| 风险 | 应对 |
|---|---|
| 网关剥掉音频字段 | 探针 0 就能发现，届时只能请公司 HiAgent 管理员开通，没有绕过网关的办法 |
| 模型把参考原话念进成片 | 试听文本用中性句；说明里写明台词来源；语音识别泄漏检测（P1 做成闸门）；全局开关兜底 |

  - 映射台人物谱、分镜台/生成台段落素材可直接试听。
- **不做金额展示**：沿用 09-01「金额退场」的决定，确认框只说明「将调用付费的声音生成接口」与数量。

**视频请求带上声音（U3）与生成台显示（U4b）已完成，默认关闭**：

- **开关**：两个系统设置，归在「参考图与视觉生成」组。
  - 「生成视频时传入角色声音参考」：默认关，开关关闭时请求、幂等键、版本记录都和改动前逐字相同。
  - 「每段最多传入几个角色的声音」：1–3，默认 3；实际生效值取它与视频模型能力上限中较小的一个。
- **选谁**：取本段具名说话人（含画外音、内心独白，不含旁白与未具名角色），按台词句数排序。以下几种情况跳过，并逐个写明原因：
  - 超出人数或总时长上限；
  - 角色没配声音；
  - 年龄段对不上；
  - 本段没有参考图；
  - 视频模型不支持参考音频。
- **冻结**：版本第一次冻结参考图时，一并把声音清单（含片段哈希）和提示词里的声音说明写进版本记录。重试时只读这份记录；已冻结的老版本不会被补上声音，避免重试时请求形状改变。提交前核对片段哈希，不一致就明确失败并标为「未发出」，不偷换成别的声音。
- **提示词说明**：「声音参考：@音频1 是周晚的声音，周晚的每一句台词都用 @音频1 的音色和说话方式说出；……。参考音频只提供音色，台词内容以本段剧本为准。」
- **不会重烧已采纳的段**：整集生成、续跑、全片补齐在进入幂等计算之前，就已经按「未完成」把已采纳或已有成功产物的镜头过滤掉，这由测试钉住。只有显式的「全量重新生成」会重拍，那属于用户的明确意图。
- **供应商**：
  - Seedance：请求体末尾追加 `audio_url` 项；能力快照声明最多 3 段、总长 15 秒。
  - MiniMax H3：声明不支持，解析阶段就会跳过，适配器收到音频时明确拒绝并标为「未发出」。
- **生成台**：「本次实际传入素材」列出这一版实际发出的「音频N · 角色名」，可以试听；同时列出没传声音的角色及原因。

**上线后怎么做效果对照（代替原探针 1，不需要登录生产机）**：

1. 在系统设置打开「生成视频时传入角色声音参考」；
2. 给龙猫出爪的周晚、阿凯、小李生成并采用声音；
3. 在生成台对第 1 集第 5 段、第 3 集第 12 段各重拍 1–2 次，约 30–60 秒额度；
4. 听音色是否跟随参考、有没有把试听台词念进成片、多人段是否串音。

多人串音就把「每段最多传入几个角色的声音」改成 1；出现念原话或被拒收就关掉开关。

**已知限制**：

- 入队时算的幂等指纹与提交时冻结的清单分两次读库，中间若改绑声音可能有细微出入。只影响去重，不影响实际发送内容。
- 每个角色超过 5 个候选时会删最旧候选的文件。若某个待重试的视频恰好冻结了被删的那段片段，重试会明确失败，需要重新生成。
- 旁白音色、按年龄段分别配声音、上传自有录音仍是 P1。

**尚未做**：P1 各项；存量视频不会自动补声音。
