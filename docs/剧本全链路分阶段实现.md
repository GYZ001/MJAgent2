# 剧本全链路分阶段实现

## 决策依据

以 `PRD/QA只评分与偶然错误拦截改造PRD.md` 的 2026-07-31
生产决策为准。它覆盖早期“QA 不通过持续 Patch 到完成凭证”的设计：

- QA 只评分和提示，不阻止结构可用的剧本发布。
- QA 不触发语义 Patch、整版重生或自动续跑。
- 只有 JSON/Schema、必需人物身份、来源/版本上下文、权限、并发、
  供应商和显式取消等确定性问题可以暂停或失败。

## 生产阶段

剧本任务固定为以下六个可展示阶段：

1. `CHARACTER_DISCOVERY`：解析本集实际出场人物，持久化文字卡和身份决议。
2. `GENERATING_BASELINE`：只生成一次完整 Baseline，并保存不可变 working Artifact。
3. `STRUCTURE_VALIDATION`：执行 Pydantic、Artifact、人物身份和上下文绑定检查。
4. `QUALITY_SCORING`：记录 `score_only` Evaluation，不修改控制流。
5. `PUBLISHING`：绑定当前原文/Bible/人物决议指纹，签发证书并原子切换发布指针。
6. `SUCCEEDED`：页面和下游只读取 published Artifact。

每次阶段迁移写入 `production_revisions.checkpoint_json.phase`。服务重启或用户停止后：

- Baseline 尚未产生：重新进入首次生成，但仍受 revision Baseline 计数保护。
- Baseline 已产生：直接从 `STRUCTURE_VALIDATION` 继续，不再调用完整生成或语义 Patch 模型。

## 状态与失败边界

| 问题 | 状态 | 自动动作 |
|---|---|---|
| JSON/Schema 无法解析 | `failed` | 有限格式重试，不注入质量 critique |
| 必需人物身份/上下文缺失 | `failed` | 保留 working Artifact，等待重新识别或人工修正 |
| QA 低分、节奏或叙事风险 | 正常发布 | 记录 score-only Evaluation 和 `gate_retry_exhausted` |
| 429/网络/5xx/超时 | `WAITING_RETRY` | 仅 Harness 统一预算重试 |
| 用户停止 | `CANCELLED` | 保留 working Artifact，不在重启后自动恢复 |
| 并发版本变化 | `409` | 保留草稿和当前发布版 |

## 前端展示

剧本台展示阶段轨：

`人物识别 → 生成首版 → 结构校验 → 质量评分 → 原子发布 → 已完成`

每一阶段显示 `已完成 / 进行中 / 已暂停 / 待开始`。

- 暂停主操作统一为“继续剧本流程”。
- 自动任务运行时禁止手工发布旧版本。
- QA 质量问题不显示“进入独立 Repair”按钮。
- 结构/人物上下文问题保留草稿并展示具体错误。

## 发布与下游

- working 与 published 指针分离。
- 证书绑定 Artifact hash、revision、输入指纹、合同版本和当前 score-only Evaluation。
- 数据库事务先切换新剧本并清空下游权威指针。
- 旧镜头与文件在发布成功后物理清理；清理失败不会回滚或破坏新发布权威。
- 人工候选创建时不提前替换 `screenplay_production_revision_id`，发布成功后才切换。

## 不再允许的行为

- QA issue 自动进入 `screenplay_narrative_patch`。
- 因低分或叙事质量问题反复调用文本模型。
- “继续局部修复”作为默认用户流程。
- 发布失败前删除旧分镜/视频。
- 自动任务与人工发布并发覆盖 revision。
- adapter 与 Harness 叠加重试同一文本请求。
