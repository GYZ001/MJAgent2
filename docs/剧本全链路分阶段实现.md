# 剧本全链路分阶段实现

## 决策依据

以 `docs/剧本全链路性能与健壮性整改方案.md` 和当前 typed contract 为准。它覆盖早期
“QA 全放行”或依赖错误码/错误文案选择修复器的设计：

- `Issue.category` 由 validator 显式填写为 structural / quality / operational；不得从 code/message 反推。
- `must_fix/runtime_blocking` 是发布门禁；非 runtime 的 score-only 质量项只记录评分。
- 完整 Document 建立后禁止整版重生，只允许现有 CAS Document Patch；分片只存在于 Baseline 之前。

## 生产阶段

剧本任务固定为以下十个可展示阶段：

1. `CHARACTER_DISCOVERY`：解析本集实际出场人物，持久化文字卡和身份决议。
2. `BLUEPRINT_GENERATION`：生成/复用 Blueprint SRC 分片并执行全局门禁和风险审稿。
3. `IDENTITY_FREEZE`：用 Blueprint typed evidence 收口缺口并冻结 identity registry。
4. `ENVELOPE_GENERATION`：生成不含完整原文的全局 metadata/experience。
5. `SCENE_SHARD_GENERATION`：并行最多 2 个 Blueprint-owned 场次写作分片。
6. `IR_MERGE`：确定性命名空间、合并并执行全局来源/身份/边界门禁。
7. `STRUCTURE_VALIDATION`：完整 ScreenplayDocument 建立后执行结构与上下文检查。
8. `QUALITY_SCORING`：执行 runtime gate 与 score-only Evaluation。
9. `PUBLISHING`：绑定当前原文/Bible/人物决议指纹，签发证书并原子切换发布指针。
10. `SUCCEEDED`：页面和下游只读取 published Artifact。

每次阶段迁移写入 `production_revisions.checkpoint_json.phase`。服务重启或用户停止后：

- Baseline 尚未产生但已有 validated Envelope/Scene Shard：从缺失小单元继续，合同或输入 hash 变化时拒绝复用。
- Baseline 尚未产生且无安全检查点：重新进入 Blueprint/首版生成。
- Baseline 已产生：直接从 `STRUCTURE_VALIDATION` 继续，不再调用完整生成或语义 Patch 模型。

## 状态与失败边界

| 问题 | 状态 | 自动动作 |
|---|---|---|
| JSON/Schema 无法解析 | `failed` | 有限格式重试，不注入质量 critique |
| 必需人物身份/上下文缺失 | `failed` | 保留 working Artifact，等待重新识别或人工修正 |
| 非 runtime 的 QA 低分/偏好风险 | 正常发布 | 记录 score-only Evaluation |
| `must_fix/runtime_blocking` | `repairing/WAITING_HUMAN` | 在完整 Document 上执行有限 CAS Patch，耗尽后停止发布 |
| 429/网络/5xx/超时 | `WAITING_RETRY` | 仅 Harness 统一预算重试 |
| 用户停止（仅有 shards） | `CANCELLED` | 保留 validated shards，页面提供“继续首版场次生成” |
| 用户停止（已有 Document） | `CANCELLED` | 保留 working Document，页面提供“继续完整剧本校验” |
| 并发版本变化 | `409` | 保留草稿和当前发布版 |

## 前端展示

剧本台展示阶段轨：

`人物识别 → 叙事蓝图 → 身份冻结 → 全局包络 → 场次写作 → 全局编译 → 结构校验 → 质量评分 → 原子发布 → 已完成`

每一阶段显示 `已完成 / 进行中 / 已暂停 / 待开始`。

- 暂停主操作区分“继续首版场次生成”和“继续完整剧本校验”。
- 场次阶段显示 `已完成 N/M 组`；技术错误进入 RunCenter，页面只给可操作摘要。
- 自动任务运行时禁止手工发布旧版本。
- QA 质量问题不显示“进入独立 Repair”按钮。
- 结构/人物上下文问题保留草稿并展示具体错误。

## 发布与下游

- working 与 published 指针分离。
- 证书绑定 Artifact hash、revision、输入指纹、合同版本和当前 score-only Evaluation。
- 数据库事务先切换新剧本并清空下游权威指针。
- 旧镜头与文件在发布成功后物理清理；清理失败不会回滚或破坏新发布权威。
- 人工候选创建时不提前替换 `screenplay_production_revision_id`，发布成功后才切换。

## 不再允许的行为

- score-only QA issue 自动进入 `screenplay_narrative_patch`。
- 因低分或叙事质量问题反复调用文本模型。
- “继续局部修复”作为默认用户流程。
- 发布失败前删除旧分镜/视频。
- 自动任务与人工发布并发覆盖 revision。
- adapter 与 Harness 叠加重试同一文本请求。
